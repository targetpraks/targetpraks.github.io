Why COR is the right tier

  • The Company Snapshot describes a quick-service restaurant brand: “QSR pasta, bespoke pasta, Papa Pops”, target market “middle-income families looking for easy weeknight dinner solutions”. That is end-user marketing, which is what COR means in this space.
  • ZOR/FND is franchise-network development — the franchisor selling and supporting franchisees. The doc has no franchisee recruitment, territory or fee content; its one franchisor-flavoured artefact (“Franchise Overview Sheet”) sits in a generic 40-row collateral template.
  • The space already holds MKT ZOR/FND - PPP (1501000000001200) and MKT COR - PPP (1501000000001216). Both are complete, so a misfiled doc would load without a single error — the tier has to be decided on content, not on whether a list exists.
  • The space conventions record the same rule: “a doc titled ZOR: for end-user marketing should read COR:”, with two docs already retitled for this reason.

What changes: the document title only. The doc URI superhuman://docs/5No69dElsQ and the web URL stay the same, so links, embeds and the Quick Links table keep working. Nothing in ClickUp changes as a result of the retitle — the target lane is already COR.

What “creates nothing” means, precisely

  • 0 folders, 0 lists, 0 custom fields. The lane's 19 lists and the space's 12 custom fields already cover every section above; the only field values the load needs (Brand, Engagement Tier, Function, Objective, Work Format) exist.
  • No moves. The single existing item — Brand Manual revisit - Target Audience — stays where it is. Its content overlaps phase 1, so the phase-1 payload links to it rather than copying it.
  • No deletions in ClickUp. The 25 KPD keyword rows are retired inside the document, not deleted from a ClickUp list, because they were never in one.
  • One writer at a time. ClickUp cannot move a task between lists (a PUT /task/{id} with a new list id returns 200 and moves nothing), so a mis-filed item can only be re-created. That is the reason every phase names its list id before it starts.
  • No due dates on create. A space automation rewrites due_date to the following Monday within seconds; dates are written in a second pass, and undated items are left undated.
