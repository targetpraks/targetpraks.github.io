Why COR is right

  • The Company Snapshot describes a quick-service restaurant brand — “QSR pasta, bespoke pasta, Papa Pops” for “middle-income families looking for easy weeknight dinner solutions”. That is end-user marketing.

The tier follows the audience the marketing serves.
  • Both MKT ZOR/FND - PPP and MKT COR - PPP exist and are complete, so a misfiled doc loads without one error. The tier is decided on content.
  • The space conventions say the same: a doc titled ZOR: for end-user marketing should read COR:.

Only the title changes. The URI and URL stay, so every link, embed and the Quick Links table keep working.

10.3 The loop that makes it stick

Measure Monthly report pulls the numbers from each platform console, not from memory.
Audit Every quarter the same five audits run against the same checklists, so two quarters can be compared.
Decide Each finding becomes one item in Optimization, Link Building, Social or Creative Projects — never a note in a report nobody opens.
Fix The item is worked, closed with evidence (a URL, a screenshot, a rank), and dated.
Re-measure The next month's report proves whether the fix worked; if not, the item reopens.

Where the numbers are kept. Each monthly report is one item in Recurring whose description holds the figures and whose attachment is the report; the twelve month rows in the doc's Marketing Reporting table stay the brand's annual record, and the doc is updated from the ClickUp item, not the other way round. That keeps one direction of truth.

Two limits to plan around. ClickUp's public API exposes no recurrence parameter on create or update, so the 13 items are created once through the API and their repeat is configured in the UI. That is not one toggle: each item needs a due date, a schedule (monthly or quarterly interval), the trigger, the “create new task vs reuse” choice and the history-retention choice, then save — and the due date is what drives it.

Where the reports are filed is a decision. The lane has a Recurring list (1501000000002318) and a filing rule that says Function decides the pillar list. Both readings are defensible: all standing work in Recurring (what the list is for), or each report in its own function list with Work Format = Reporting. This plan defaults to Recurring and lists the function destinations beside it so the choice is one line for Ricardo, not a silent assumption.

The reporting table is 2026, this calendar is 2027. The doc's twelve month rows are dated 1 January to 1 December 2026 and hold no figures. Decide whether the first reporting year is the remainder of 2026 (backfill) or January 2027 onward, because the recurring items' due dates follow from that answer.
