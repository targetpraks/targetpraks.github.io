Creality Hi · Klipper, macros and slicer

Set for quality. The speed was never in the printer.

Three layers decide how a part looks: the printer's own firmware config, the start macro it runs, and the profile in the slicer. All three were pointing the same way — faster. Two of the three are now changed, and the third is a profile you pick.

The printer itself

These are the machine's own settings, applied by firmware restart and verified by reading them back live.

Round features: arc resolution1.0 mm steps0.1 mm stepsThe Klipper [gcode_arcs] setting. At 1 mm, every curve is chopped into 1 mm straight pieces. At 0.1 mm the arc is 10× finer. The new G-code for this cradle contains 62,817 arc moves, so this one lands on every round part in the pack.

The start macro

The printer runs a Creality start sequence before every job, and that sequence was quietly resetting the machine to its old fast defaults — 12,000 mm/s² acceleration and a 10 mm/s corner speed. Fixing the config alone would have been overwritten on the next print. Both files are patched.

The slicer profile

This is where most of the damage was. The file named "quality" was running 160 mm/s inner walls, 180 mm/s infill, two perimeters and 6000 mm/s² acceleration. It is now a genuine quality profile — process-hi-quality-v2.json — riding on a machine profile that makes the fast numbers impossible: machine-hi-quality.json caps acceleration at 3000 and corner speed at 5, whatever the job asks for.

What I did not touch, and why

Pressure advance is still 0.04

Not calibrated for this filament. It is a 20-minute tower and a judgement call on the print, so it is the next thing to run — not something to guess at.

Klipper reference

Input shaping uses the factory numbers

MZV at 44.6 Hz on X and 24.8 Hz on Y. Those look like a real measurement, not a guess, but they were not taken today. A fresh resonance test is 5 minutes with the machine empty.

Klipper reference

The bed probe takes one sample per point

samples: 1. More samples would steady the first layer, but this is Creality's own pressure probe and changing it needs a measured before/after, not a hunch.

Machine values read back from the printer after the change: gcode_arcs resolution 0.1, square_corner_velocity 5.0, bed_mesh fade 2 → 10, state ready. Slices made on the laptop, real slicer output, not estimates — the estimates in this house have been wrong by 9–13 % before.
