Crucible — the X post, checked on this Mac

github.com/codepawl/crucible · npm @codepawlhq/crucible 0.20.0 · MIT · installed into scratch only

It is real, it runs here, and it is fast. I installed it, drove its MCP server, and rendered a still, a video and a GPU path trace on the Mac mini. Nothing in the post was exaggerated beyond taste: it is not "as capable as Blender" — it is a headless render engine an agent drives with JSON, and on that job it is genuinely good. The one real risk is that it is a six-week-old, one-author, pre-1.0 project that changes API every few days.

What it actually is

A JavaScript 3D engine (WebGL2 via a browser page, plus an optional GPU path tracer called Cook) with an MCP server bolted on as the front door. You don't click anything: an agent sends a scene recipe as JSON, gets back a session id, previews a PNG, edits nodes atomically with revision checks, then submits still or MP4 render jobs. 25 MCP tools, no UI, no timeline editor.

Note the naming: 67js is not dead in the marketplace sense — the GitHub repo was renamed, so old links 404. The npm package @codepawlhq/67js still pulls 3,972 downloads/week; Crucible pulls 1,425. The post is a rename announcement dressed as an obituary.

Honest read on the quality

  • Materials are solid, not film-grade. Metal picks up colour bounce, glass/transmission is supported but I did not push it. There is no micro-surface detail, no procedural texture library, no HDRI set shipped — you bring those.
  • Lighting is a single key plus point lights and fog. It looks like studio product viz, and it looks that way instantly. It will not look like a commercial.
  • Denoising carries it. 64 spp at 960×540 came back clean because the wavelet denoiser ran. Fine for motion, where noise is hidden anyway.
  • No text, no captions, no 2D. Our ffmpeg 9.0.2 still has no drawtext, so titles keep coming from HyperFrames or PNG cards regardless.

Risk, stated plainly

single author pre-1.0 API churn

  • 4,154 commits in six weeks, 4,264 of them from one person (anxuanng), 1,943 merged PRs, 73 open issues. That is machine-velocity output from one developer — impressive, and fragile.
  • Five releases in nine days (0.16 → 0.20). Pin an exact version in any project that depends on it; do not float.
  • 722 stars, 57 forks, zero watchers-of-substance — buzz is real but shallow. No third-party production usage I could find.
  • It shells out to a browser (Chrome or a Playwright chromium) for every render and needs ffmpeg for MP4. Both already present here.

Where it fits our stack

Nowhere yet, and that is the point: we have no 3D renderer in the media lane at all — the code-video lane is HTML→MP4 (HyperFrames), React→MP4 (Remotion) and Three.js for hand-written 3D. Crucible's value is that an agent can produce a lit 3D clip from a JSON recipe with no human in a 3D app, which is exactly the gap for product/motion work.

  • Good fit: product turntables and abstract 3D idents for marketing media, driven from a brief by an agent, delivered as MP4 and muxed with audio by ffmpeg.
  • Bad fit: anything with typography, UI, charts or explainer pacing — HyperFrames and Remotion stay the answer there.
  • Integration: it is a plain stdio MCP server (npx crucible-mcp --backend gpu --jobs <private dir>), so it drops into Hermes's MCP config as one entry. Nothing is installed here permanently; my test lives in scratch.
