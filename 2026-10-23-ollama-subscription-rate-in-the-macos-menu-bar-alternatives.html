Ollama subscription rate in the macOS menu bar

Alternatives to Quotio Beta for the Hermes Agent workflow on rmmacbook and the MacBook — evaluated against the real account, not the marketing pages.

Verdict — solved, deployed

The number was never missing, only unread. Ollama exposes the subscription meter at GET https://ollama.com/api/balance; the API key is enough, no browser sign-in. Quotio Beta never had Ollama at all, and the menu-bar app that did have it was stuck on a web-login path that was never signed in. Both are fixed: the readout now shows 92% left (session) from the API, live on rmmacbook.

Recommended: Ollama Bar v2 — native NSStatusItem, now API-backed. Runner-up if you want zero custom code: SwiftBar + a 12-line plugin.

What the brief assumed, checked against the machines

1
Quotio Beta cannot display Ollama. Installed on the MacBook is Quotio Beta 1.0.0-beta.10; its binary contains zero occurrences of “ollama”, quotio-cli providers lists no Ollama entry, and its menu bar pins at most three quota providers. So the rate you were seeing there was never Ollama’s — it is a different provider’s quota, or the app’s own account row.
2
The app that could show it was not signed in. ~/AI Hub/ollamabar (“Ollama Bar”) was installed and running on the MacBook, but its cloud path held a hidden WKWebView on ollama.com/settings. The log repeated cloud: sign-in required every ten minutes since 15:42 — the badge therefore fell back to the local model count, never a percentage.
3
Ollama does publish the meter — undocumented. Probed today with the account key: GET /api/balance → 200 with session and weekly remaining percentages and reset times. The older note “no quota API” was wrong: api/limits, api/credits, api/plan, api/billing/usage still 404, but the balance endpoint answers.

The data source, verbatim

GET https://ollama.com/api/balance      Authorization: Bearer $OLLAMA_API_KEY

{"included":{"session":{"remaining_percent":92.08,"resets_at":"2026-10-23T19:00:00Z"},
             "weekly":{"remaining_percent":54.97,"resets_at":"2026-10-26T00:00:00Z"}},
 "purchased":{"balance_usd":0}}

Credit-wallet plans send included.allowance_usd, included.balance_usd and included.period.until instead; the same parser maps that onto the session meter. POST /api/me still supplies the plan name (max), and /api/usage still gives request counts.

Alternatives, scored against the constraints

1 · Ollama Bar v2 recommended

Native AppKit status item on /api/balance — the fleet’s own app, upgraded today.

Pros
  • Reads Ollama’s own meter; no browser, no sign-in, no cookie
  • Key stays in ~/.hermes/.env, read at call time, never logged
  • Also shows the mini’s loaded models over the tailnet; click to unload
  • Logs one verifiable line per refresh — no guessing from a screenshot
  • One status item, no Electron, ~260 KB
Cons
  • Our code to maintain (single Swift file)
  • /api/balance is undocumented, so the payload can change
  • Ollama only — no Claude/Codex quotas in the same item
Setup

cd ~/AI Hub/ollamabar && ./build.sh — compiles on the MacBook, installs /Applications/Ollama Bar.app, loads LaunchAgent com.maio.ollamabar. ./build.sh --check reports state.

2 · CodexBar 0.80.0 viable, blocked today

steipete’s 63-provider menu-bar app; ships an Ollama provider.

Pros
  • Mature: 29,514 installs in the last 365 days; Homebrew cask
  • Could retire Quotio entirely — Claude, Codex, Copilot, Cursor, Grok in one place
  • CLI with JSON: codexbar usage --provider ollama --format json
  • Reset countdowns, per-provider icons, no Dock icon
Cons
  • Verified failure on this account: API mode answers “Ollama returned an unrecognized credit balance response.” — its Ollama API parser expects the credit-wallet shape, while the Max plan returns session/weekly percentages
  • Cookie mode needs a Chrome (or Safari) login; your default browser is Dia
  • Wants the key in ~/.codexbar/config.json — a second copy of the secret
Setup

brew install --cask codexbar → Settings → Providers → Ollama → API key (printf '%s' "$OLLAMA_API_KEY" | codexbar config set-api-key --provider ollama --stdin).

3 · SwiftBar + plugin best zero-code

A menu-bar host that runs a script; the script is the whole integration.

Pros
  • No app to compile; the plugin is a file I can rewrite remotely in seconds
  • Dropdown menus, colours and refresh cadence come free
  • Same plugin file works on the MacBook and the mini
Cons
  • One more app in the stack
  • You own the script’s upkeep; no model unloading or daemon view
Setup

brew install --cask swiftbar, then a plugin named ollama.10m.sh:

#!/bin/bash
KEY=$(grep '^OLLAMA_API_KEY=' ~/.hermes/.env | cut -d= -f2-)
J=$(curl -s -H "Authorization: Bearer $KEY" https://ollama.com/api/balance)
J="$J" python3 - <<'PY'
import json,os
d=json.loads(os.environ["J"])["included"]
print(f"☁️ {d['session']['remaining_percent']:.0f}%")
print("---")
print(f"Session {d['session']['remaining_percent']:.0f}% left")
print(f"Weekly {d['weekly']['remaining_percent']:.0f}% left")
PY

Recommendation

Keep one purpose-built status item: Ollama Bar, now API-backed. It is the only option that reads the exact meter with no browser session, keeps the secret in one canonical file, and still gives you the mini’s loaded models and the unload action. CodexBar would be the better long-term home if you also want Claude and Codex quotas in one place — but until its Ollama parser learns the percentage shape, it cannot show this number at all. SwiftBar is the fallback if you would rather not own a compiled app.

Hermes Agent workflow

ollama-rate is the bridge: ollama-rate --check 15 exits non-zero when the session drops under 15% left, so a Courage cron can warn you before a run dies mid-task instead of after. It reads the same key from ~/.hermes/.env and prints nothing secret.

Caveats

  • “Title bar” in macOS means the menu bar for this kind of readout — apps cannot draw into another app’s title bar; the status item plus its tooltip is the equivalent surface.
  • /api/balance is undocumented. If Ollama changes its shape, the app logs a fallback and keeps the last reading; the web-login path remains as a backstop.
  • Quotio Beta stays useful for Claude/Codex/Copilot quota — it simply never covered Ollama.
  • Nothing was bought, no account terms accepted, no key copied out of ~/.hermes/.env.
