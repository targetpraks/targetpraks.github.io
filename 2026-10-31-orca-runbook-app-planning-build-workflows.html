Orca Runbook — App Planning & Build Workflows

All orca orchestration verbs must run from the coordinator's live Orca terminal (the Claude pane), or pass --from <handle>. Without a bound terminal they fail no_active_sender_terminal.

0. One-time discovery (any shell)

orca status --json
orca skills get orca-cli
orca skills get orchestration
orca account list
orca repo list --json          # note the repo id for --repo id:<id>
orca worktree ps

1. Planning (idea → PRD)

Create the planning worktree with Claude as the coordinator seat:

orca worktree create \
  --name plan-<app> \
  --repo id:<repoId> \
  --base-branch main \
  --no-parent \
  --agent claude \
  --surface chat \
  --prompt "Load the app-planning-workflow skill and run it for: <app idea>. You are the coordinator. Cap clarification at 2 rounds / 7 questions. Use orca orchestration gate-create for every bounded decision; council for deliberative ones. Produce a full PRD (features, structure, UX/UI, NFRs) and publish it." \
  --activate --json

Bounded decisions from the coordinator terminal:

orca orchestration gate-create --task <task_id> --question "UI direction?" --options '["editorial","brutalist","minimal"]' --json
orca orchestration gate-resolve --id <gate_id> --resolution "minimal" --json

2. Build (PRD → shipped)

2.1 Preflight

gh auth status                                  # GitHub 403 blocker check
orca account list
orca repo list --json                           # <repoId>

2.2 Create the run (binds to this terminal)

orca orchestration run-create --objective "Build <app> from PRD: <abs path>" --json
# → run.id
orca orchestration run-current --json

2.3 One task per ticket (from to-tickets; deps = blocker task ids)

orca orchestration task-create --run <run_id> --task-title "T01 upload API" --spec "<abs brief>" --deps '[]' --json
orca orchestration task-create --run <run_id> --task-title "T02 upload UI" --spec "<abs brief>" --deps '["<T01_id>"]' --json
orca orchestration task-list --run <run_id> --ready --json

2.4 One supervised worker per ready task (own worktree)

orca orchestration worker-start \
  --run <run_id> --task <T01_id> \
  --worktree new-top-level \
  --repo id:<repoId> --name t01-upload-api --base-branch main \
  --agent claude --model <model> --effort high \
  --json
# → dispatch.id

Per-lane agent by strength: claude (UI/TS), codex (Go/infra), omp/opencode (bulk), hermes only with a pinned --in + --yolo.

2.5 Watch (liveness authority)

orca orchestration worker-list --run <run_id> --include-remote --json
orca orchestration worker-read --dispatch <dispatch_id> --limit 80
orca orchestration worker-show --dispatch <dispatch_id> --json

2.6 Decisions + messaging

# bounded decision: blocks the task until resolved
orca orchestration gate-create --task <T01_id> --question "Postgres or SQLite for v1?" --options '["postgres","sqlite"]' --json
orca orchestration gate-resolve --id <gate_id> --resolution "postgres" --json

# steer a worker / answer a worker's ask
orca orchestration send --to dispatch:<dispatch_id> --subject "steer" --body "use the pnpm workspace" --json
orca orchestration reply --id <msg_id> --body "yes, ship the migration" --json

2.7 Settle tasks

orca orchestration task-update --id <T01_id> --status completed --result "gate green, <sha>" --json
# statuses: pending | ready | dispatched | completed | failed | blocked

2.8 Integration (coordinator's own worktree)

orca worktree create --name <app>-integration --repo id:<repoId> --base-branch main --no-parent --activate --json
# merge in dependency order; run the independent acceptance suite; report; never push/merge to main without Ricardo

Kickoff prompts (what to paste into Claude)

Planning

Load the app-planning-workflow skill and run it for: <app idea>.
You are the coordinator in Orca. Run orca orchestration from this terminal.
Cap clarification at 2 rounds / ≤7 questions. Bounded decisions → orca orchestration gate-create; deliberative → council.
Output a full PRD (features + P0 criteria, structure, UX/UI, NFRs, test seams) and publish it.

Build

Load the app-build-workflow skill and run it for the PRD at <path>.
You are the coordinator in Orca. run-create, task-create per ticket, worker-start per ready task (new-top-level worktree, --agent claude/codex by lane).
Watch with worker-list --run --include-remote. Independent acceptance suite before merge. Never push/merge to main without my word.

Field notes

  • Liveness = worker-list --run --include-remote, not worktree ps.
  • --on = saved environment name (never ssh id); remote needs project setup-clone first.
  • Pin Orca's Claude entry or pass --model (a bare claude can die "Prompt is too long").
  • --surface chat exists on worktree create, not on worker-start.
  • task-create --spec takes the spec text or a brief path; --deps is a JSON array of task ids.
  • GitHub push 403 on 28/29 repos — preflight and fall back to a local bundle.
