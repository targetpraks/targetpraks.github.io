The vault backfill cards were measuring the wrong thing

Date: 2026-11-01 · Author: CTO · Card: t_54d86d18 · Generator: ~/.config/maio-stack/bin/vault-ensure

Nine batches of "Vault backfill — file N published documents that never reached the vault" cards ran between 2026-10-25 and 2026-11-01. Beast audited 180 documents across batches 1/9–9/9 and filed zero: every one was already seated in the vault. That is 180 audits and nine cards spent looking for something that was never lost. This is the fix.

What was wrong

vault-ensure answered "is this document in the vault?" from the published destination string, not from the vault. For published rows it looked for a note at exactly the path recorded in published.csv; for never-published markdown it looked for the file stem at the vault root only.

Both tests fail on the house filing rules working exactly as designed:

  • a later export of the same stem was the one filed (-3.md staged, vault filed from -5.md);
  • the note went to a project folder (Work/3.PRD/Active/INFX-Solutions/) or to 4.Research/ because it is research, not a report;
  • frontmatter was re-stamped at publish time (space: AI-Space for THE STANDARD RULES v2);
  • the publish step added a collision suffix to the filename (…-five-2.html), which is a name clash, not a new revision.

Every one of those documents looked unpublished forever, and came back as a card on the next run.

The fix — five checks, cheapest first

Each document is now resolved against a live index of all 2,482 notes in the three spaces (AI-Space, Work, Personal). The run stops at the first hit, and records which check fired:

# Check Catches
1 destination path, then a stem sweep of the three spaces (.md and .html twin) filed as published
2 source: pointer on each seated note the later-export case
3 revision family — same stem, different -N a later export, or a publish-time collision suffix
4 title sweep (title: in frontmatter) renamed on filing
5 confirmation against the candidate's created: / author: a lookalike with the same name

Two outcomes are now distinguished that used to be one:

  • missing — all five miss. Only this raises a card.
  • revision drift — the vault holds this document, but the staged export is a later revision of it. Not a backfill; writing the staged copy over the seated note would push the vault backwards. Named in the run output and the ledger, never carded.

A seated .html twin with no frontmatter is accepted on its stem alone, and the candidate's created:/author: cannot be compared in that case — that is a "cannot confirm", not a "no".

Cards now carry ## EVIDENCE — why each one is here: the five-check trail, per document, so a reviewer can see the reasoning instead of trusting it.

Guarded against regression

~/.config/maio-stack/bin/vault-ensure-selftest — a hermetic suite that builds a throwaway vault and a throwaway AI-Drive in a temp dir (VAULT_ENSURE_ROOT, VAULT_ENSURE_DRIVE) and can never read or write the real vault. It seats one fixture per route (destination, stem, source: pointer, collision suffix, title), plus one revision drift, one deliberate probe and one true miss, and asserts the counts, the drift label and that the true miss carries all five checks. Exit 0 pass, 1 failure, 2 could-not-run. Runs in about a second; run it after any change to vault-ensure.
