Two deliberate restraints

  • A task that already has a due date is never touched. The rule fills a blank; it does not re-plan dated work.
  • Template lists are exempt. The first sweep stamped 8 TEMPLATE … tasks in TPL MKT — …; those dates were reverted to blank and the guard now skips any list named TPL …, because a date on a template is copied into every task created from it — a false deadline in the future.

Not built: ClickUp's own automation (click pass)

Settings → Features → Automations Manager → location picker → Add Automation opens the native builder (Name this automation rule…, Trigger Task or subtask created, Action Update status, footer Create). It opened for FLF and for MANCO and could not be driven further: Dia re-selects a different tab between tool calls, so the geometry read from the driven tab and the cliclick on the visible window point at different pages, and the wizard's dropdown clicks were dropped. No automation was created, and nothing is claimed to have been.

If it is added by hand, the rule must read When task created → if Due date is not set → Set due date to 4 days from now, and it must be created once per Space — the manager's location picker offers Spaces only, never the workspace. The 15-minute guard already covers the outcome; the native rule would only remove the lag between creating a task and seeing its date.

Changing the rule

RULE_DAYS = 4 at the top of the guard script. Nothing else encodes the number.
