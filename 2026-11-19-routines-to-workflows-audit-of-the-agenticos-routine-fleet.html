Three things the audit found that matter more than the conversion

  1. The fleet is scheduled but unproven. 128 of 132 routines have never produced a run. A schedule with next_fire_at in the future and last_fired_at null looks identical on the console to one that works.
  2. Weekly SOP audit is the one routine that runs as its creator (all 13). It is also the one whose prompt calls a skill, which is the read-only gate no routine can pre-consent — so a failure there parks in awaiting_approval and stays silent, because approval requests send no mail.
  3. Every active routine answers to primary chat. Thirteen nightly reports per unit land in conversations, not in a run log. There is no per-routine run record to check, retry or cost.

2. Which templates should become workflows

A workflow buys a fixed route, a run record per step, retry from the step that failed, error routing, a per-run budget, and a draft you can test before it goes live. It costs you the model's freedom to decide the shape of the job — the shape is drawn, and changing it means republishing.

That trade wins exactly when the job has a shape. Splitting the eleven on that test:

Convert — the job is a sequence with arithmetic in it (5 templates)

Template The step the model should not be doing
ClickUp overdue chase filtering by due date, bucketing at 30 days, counting per owner, the one count line. Today the model does all of that by reading prose, which is where a report silently says "3 overdue" when it is 4
Unassigned work triage pairing unassigned work with the least-loaded owner — a join over two lists plus a ranking
Stale and duplicate watch last_updated < today − 21, and duplicate detection over titles
Friday stand-up pack per-person counts of done / doing / blocked, before any prose is written
Knowledge base upkeep the inventory of what exists against what the unit actually works on

Convert later (2) — Context base drift and Tables base reconciliation: the value is in the diff step, and a diff needs a machine-readable second side that does not exist today.

Do not convert (4) — Weekly SOP audit is a skill-driven judgement call with no fixed route; a workflow around it would add a wrapper and no determinism (and its read_skill approval parks either way). Team Inbox zero, Weekly hours check and WorkDrive STS tidy are paused for a missing data source, and a workflow cannot manufacture a source — converting them would produce 39 beautifully audited failures.

3. The fork: 65 thin ports, or 5 real ones

There is a constraint in the product that decides this. A workflow's "Run an agent" step pins one agent and one published version; it cannot take the agent from a loop variable. So there are only two honest shapes:

A — thin port. One workflow per unit × template (65). Schedule → Run an agent (that unit's bot, pinned) → Output, with that unit's own prompt copied verbatim. Behaviour-identical to today, and it delivers the run record, the retry, the error route, the per-run cap and the Runs page. It does not fix the arithmetic, because the bot still reads a prose feed and still does the counting. And it multiplies the objects: 65 schedules to stagger, 65 budgets, 65 prompts that drift apart.

B — the real conversion. One workflow per template (5), no agent loop needed. The reason a loop over the 13 units is impossible today is that the feed only exists as context text, which only an agent can read. Move the nightly feed to a machine-readable home — a virtual table Routine feed (one row per unit per night, written by the same generator that writes the context doc today) or a JSON file in workflow storage — and the graph becomes:

Schedule → List records (this unit, latest snapshot) → Filter (overdue) → Map (days late) → Aggregate (per owner) → Ask a model (write the nudges from a computed table) → Output

Thirteen units become a table query, not thirteen graphs. The counts are computed by the platform, the model writes only the words, and the whole report is one run record you can open. Five workflows replace sixty-five, the arithmetic becomes trustworthy, and the cost per run drops because the model stops re-reading a 4 000-word snapshot to count.

B needs one change outside the workflow module: the nightly generator (Courage, on this Mac) writes the feed into the table as well as the context document. That is my own lane, and it is a small change.

Recommendation: B. It is the only version that fixes the thing that actually goes wrong in these reports — the numbers. A is a mechanical port that leaves the arithmetic exactly where it is.
