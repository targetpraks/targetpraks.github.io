Camoufox on this fleet

Identity policy (decided 2026-11-13)

  • Default launch claims the host's own OS with canvas_noise=False, so a page reading back canvas or WebGL pixels sees what the fingerprint claims. Verified here: macOS UA, Apple M1 renderer, navigator.webdriver false.
  • Three modes, and the difference matters:
    • default / --os host — claims the host OS, canvas_noise=False. Cleanest, verified macOS UA + Apple M1 renderer.
    • --os random — lets Camoufox draw the OS itself across its whole profile set (verified: drew a Windows/ANGLE identity). Canvas noise on.
    • --os windows|linux|macos — pins that OS. Canvas noise on. Foreign and random identities turn noise on because the host's real GPU would otherwise leak through the pixels. That noise reads as a privacy-hardened Firefox (Tor/Mullvad/LibreWolf) — legitimate but rarer.
  • The macOS identity pool is small. Screen size varies, GPU (Apple M1) and core count do not, so two consecutive host-OS draws collide maybe one time in four. Do not treat "two launches look different" as a pass/fail property; use --os random when you need many genuinely distinct identities, and expect the canvas-noise trait in exchange.
  • Proxies should always be passed: geoip=True then aligns timezone, locale, geolocation and the WebRTC IP to the exit IP. Without a proxy, IPv6 can geolocate elsewhere and Camoufox warns (LeakWarning).

Pitfalls found while installing

  • PYTHONPATH from Hermes breaks the venv. Hermes exports paths from its own install venvs; they shadow yaml/pydantic and imports fail with cannot import name 'CLoader'. Every entry point here runs env -u PYTHONPATH, and server.py scrubs the variable and sys.path before importing.
  • mcp is 2.x now. mcp.server.fastmcp.FastMCP is gone; use from mcp.server.mcpserver import MCPServer (or pin mcp<2).
  • The build is big: ~1.3 GB zip → 2.4 GB extracted, plus a 116 MB GeoIP database. First launch downloads both if camoufox fetch was skipped.
  • Cold start ~10 s per launch (browser fork + identity generation). Keep a browser open across pages when scraping in a loop; camofox get per URL pays it every time.
  • bot.sannysoft.com reports Chrome (New) missing (failed) for any Firefox — expected, not a defect.

Four things the tests taught:

  • core._target() must duck-type on new_context: with persistent_context=True Camoufox yields a BrowserContext, not a Browser, and the first version crashed on BrowserContext.new_context.
  • kill_app is refused under this session's permission rules (status: refused), while click and get_window_state are allowed. Close apps with osascript -e 'tell application "X" to quit' instead, and never retry a refused call.
  • Screenshots fall back locally. The Air reaches /Volumes/Hiksemi 1TB over SMB; infmini and macserver cannot see it at all and got Permission denied. core._artefact_dir() now tries the canonical AI-Drive path first and falls back to ~/AI Hub/camoufox/shots — infmini writes there, verified 10/10.
  • A per-URL camofox get re-launches the browser every call (~8-10 s). Batch work belongs in one core.launch() with multiple pages, or accept the cost.

Linux host: macserver

Ubuntu server ships none of Firefox's GUI libraries and trickyricky has no passwordless sudo, so they were fetched and unpacked without root:

mkdir -p ~/camoufox-libs && cd ~/camoufox-libs
PKGS=$(apt-cache depends --recurse --no-recommends --no-suggests --no-conflicts \
        --no-breaks --no-replaces --no-enhances libgtk-3-0t64 libasound2t64 libx11-xcb1 libgl1 libegl1 libgbm1 \
        | grep '^[a-zA-Z0-9]' | sort -u | tr '\n' ' ')
apt-get download $PKGS
for f in *.deb; do dpkg-deb -x "$f" ./root; done
find root \( -name 'libc.so*' -o -name 'libm.so*' -o -name 'ld-linux*' \) -delete   # never shadow the host C runtime

~/.local/bin/camofox on that host exports LD_LIBRARY_PATH=~/camoufox-libs/root/usr/lib/aarch64-linux-gnu and LIBGL_ALWAYS_SOFTWARE=1, so callers need nothing extra. 192 packages, 676 shared objects, ldd libxul.so → 0 missing.

Known gap on macserver: gl=err — no WebGL context in headless Firefox even with /dev/dri present and mesa extracted. Everything else is clean (navigator.webdriver false, WebDriver rows pass). Use it for text and HTML; for GL-fingerprint-sensitive targets use a Mac. The real fix is sudo apt install libgtk-3-0t64 libasound2t64 libx11-xcb1 libgbm1 libegl-mesa0 xvfb and then running headed under Xvfb.
