The five defects the red team found in shipped code

Each one is a claim from v1 that the code does not keep. Each has a line of evidence and a fix that is a rule, not a resolution.

#DefectEvidence, quotedFix
D-1The QC gate already leaked. A batch closed with the cook test unanswered. var/events.jsonl holds batch_close for B-1 with "cook_test": {"answered": false}, and moisture: "28" with no unit. Replay validates and rejects an unqualified close (I4). The close UI takes a number, not a tick. A closed-without-test record is a lie with a timestamp on it — worse than paper, because a blank draws a question and a green tick draws none.
D-2The connectivity pill lies. It reports the tablet's network, not the kitchen's ledger. app/app.js:42 — if (navigator.onLine) … 'online · sync idle'. Server asleep, wifi up: the screen says online and nothing syncs. Poll the ledger's last seq (I11). Three states, not two: synced to 14:32, queued, N waiting, no server.
D-3The real close path has never run. var/ledger.jsonl is 0 lines. The batch close exists only as a scripted event, not as a proven server run. Stage 2 is not done until the kill-mid-sync drill passes on the ledger, not on a fixture.
D-4Two cards are the formula. Law one defeats one screenshot, not two. The 10 kg and 40 kg cards side by side divide back to every baker's percentage. The engine is exact, so the leak is arithmetic, not carelessness. Be honest: gram cards delay a leak. The controls are the NDA, no export, one size rendered at a time (I12), and a batch id plus operator watermark on every view. Budget the defence legally, not visually.
D-5The draft banner permits production. app/app.js:28 — "The bench may use them for the pilot; the record says so." Delete the sentence. All four versions stay draft until published; from Stage 2 the bench refuses to build a card from an unpublished version at all (I10).

The uncomfortable headline

Stage 1 is real and impressive: a cook can build a correct Bokgat card with the network cut. Stage 2 is nearly real, and the one thing it exists to prevent — a batch closing without its cook test — has already happened in the test data. That is what a red team is for. It is cheaper to find this today than on 14 November.

Part two

The two laws, amended — and twelve invariants

The laws survived. Two of them needed a correction clause, and the list grew from ten rules to twelve because the defects above were not covered by the original ten.

Law one — amended

Percentages stay in the costed model. The bench shows weighed amounts for one batch size, one size at a time, no percentage column, no export, no share, every view stamped with batch id and operator.

The amendment: this is a legal and procedural control, not an information-theoretic one. Any two batch sizes, divided, give the blend. We keep the cards because they make the leak slow, attributable and a breach of a signed NDA — not because they make it impossible.

Law two — amended

Offline is the normal state. Every bench action works with the network cut and replays idempotently.

The amendment: the app must know the difference between the tablet has wifi and my work reached the ledger. Every writing screen shows the last confirmed sync, in words, and never claims a state it has not verified.

Part three

The nine surfaces

Six were in v1. The council added three: handover, publish, and health — the three places where a kitchen system rots quietly and nobody notices until the numbers are worthless.

1 · Bench — the working batch card

PurposeOne immutable version becomes one weighed card, run with the machine on and the network off.
FlowRecipe → How much? (10 / 20 / 40 kg) → Decide the ranges → Card → Method → Checks. One yellow primary action, one grey Back, nothing else.
StatesEmpty: "No batches started today. Tap a recipe to begin." · Loading: "Loading the kitchen…" · Offline: "offline · working local" · Error: "The recipe did not load. Tell the shift lead. Nothing was recorded."
RulesI1, I2, I3, I10, I11, I12, both laws
EdgesDouble-tap Build. Range skipped. Sum fails (Farmhouse). Version published mid-shift — the pinned version holds. Extrude past 40 min — the timer reddens, the screen stays open; time is evidence, not a lock.
TestAirplane mode, hard reload, a first-time cook builds Bokgat 30 kg and reconciles to 30.00 kg with ≤ 2 min of help.

2 · Prep board — today's plan

PurposeWhich batches are planned, in the mixer, drying, done — and what needs making next.
StatesEmpty: "Nothing planned yet. Tap Add a batch." · Offline: "N changes waiting to send" · Error: "The plan did not load. The bench still works — batches record locally."
RulesI5 (status derived from events, never typed), I6 (done rows stay), I7
EdgesTwo leads add the same batch → merge by batch id. Abandoned batch shows elapsed clock. Midnight → carry-overs pinned to the top. A status is always a word plus a colour, never colour alone.
TestAdd offline → one row, one sync, no duplicate. Tap a Done row → read-only, "This batch is closed."

3 · Batch log — the record

PurposeImmutable history: every batch, its choices, its reasons, its checks, the version it ran.
StatesEmpty: "No batches recorded yet." · Offline: full local history, labelled "Records on this tablet only" · Error: "This record would not open. It is not lost — tell the manager."
RulesI1, I6, I7, I11
Edges500+ batches → virtualised, filters before scroll. Unnamed operator renders as "—", never blank. Both device and server timestamps shown. Unsynced rows say "waiting to send".
TestOpen yesterday's batch: reason and QC visible, nothing editable. Search a batch id → one row.

4 · Checks — the QC gate

PurposeNo batch closes without measured answers. This is the surface D-1 disgraced, so it is specified hardest.
StatesOffline: identical, closes locally, queues · Save error: "The checks did not save. Tap Try again." · Success: "Batch closed. Recorded."
RulesI4 (numbers, not ticks), I8, I11
EdgesFailing cook test → allowed and recorded in red, never blocked, never hidden. Temp typed 550 → "That reads 550. Check the number." Answers answered by two cooks → both stored. App killed mid-checks → answers survive. Allergen row skipped → close blocked with the reason named.
TestReplay an event with cook_test.answered=false → rejected, logged, batch shows needs review. That is the regression test for D-1.

5 · Alerts — the quiet banner system

PurposeTell the truth without shouting. Three levels only: info, heads-up, stop-now.
VoiceRed opens with the instruction, never the feeling: "The barrel is over 55 °C. Stop the mixer." Red never auto-dismisses. Sounds only for the method timer and red.
RulesI9 (one nudge per unresolved item per shift), I10
EdgesRed while the slot is occupied → red wins. Dismissals are logged with a name. Nobody at the tablet → red persists on wake and pushes to the manager's phone. Four alerts → top severity plus "3 more".
TestAn unanswered check left all shift appears exactly twice — due, then escalated. Not three times.

6 · Manager — the phone view

PurposeFive answers in ten seconds, on a phone: today's batches, exceptions, stock that is short, drafts awaiting publish, and the week's yield variance.
StatesEmpty: "Nothing needs you right now." · Offline: "No connection. Last seen at 14:32." · Publish: "Published v3. The bench shows it at the next sync."
RulesI1, I5, I9, I10, I11
EdgesStale stock age printed beside the number. Publishing mid-batch leaves the bench on its pinned version. Two publishers at once → "v3 was just published — review before publishing v4." No batch editing, ever.
TestCounts on the phone equal the log. A closed batch opens read-only. A data age over six hours is labelled, never hidden.

7 · Handover — new surface

PurposeMove the floor without a phone call: open batches, unclaimed flags, unfinished checks, escalations.
Who and whenOutgoing and incoming shift leads, at changeover. Both sign, on the tablet, in person.
RulesI4 (a mid-QC batch cannot hand over as done), I5 (a flag carries its owner and time), I6, I9
EdgesLead leaves unsigned → stays flagged for the manager, never auto-clears. A surface-drying batch spans three shifts and appears in all three until closed. A flag claimed by someone who went home → re-claim or re-open. Disputed cleanliness → reopens, dispute recorded. Handover takes more than two minutes → it will be skipped.
TestAfter handover, every flag has exactly one living claimant. An open-QC batch reads "not closable". Fully signable with the network cut.

8 · Publish — where a draft becomes food

PurposeMake I10 a mechanism. A version is drafted, proposed, published by two named humans, retired — and the bench can only make food from LIVE.
ScreensVersion badge and a plain-word diff. "Publish as vN" sits behind typing the recipe name. Provenance survives publication: agent-drafted, human-edited, human-authored.
RulesI10 (no agent path to LIVE), I1 (typo post-publish = vN+1), I8 (allergens and nutrition required), I6
EdgesA publisher on leave → the named deputy. One name, or the same name twice → rejected. Urgent allergen fix → same path, no fast lane. "Live just for today" → refused; drafts print stamped DRAFT, and drafts make no food.
TestAn agent event can never set LIVE. Publish is disabled without allergens and nutrition. Post-publish edit yields vN+1 while vN stays byte-identical.

9 · Health — the surface nobody asks for and every store needs

PurposeOne place that answers: is the ledger healthy, is the backup real, is the store syncing, is a device revoked.
Who and whenRicardo weekly; a remote engineer when something is red. The manager sees one dot.
RulesI6, I11
EdgesHash-chain break at boot → writes refused, banner, restore only. Silent store > 36 h → red and an alert. Backup failed twice → the only true loss case, disclosed. Disk full → writes refuse cleanly, tablet spools.
TestRestore drill on a spare: chain verifies, stock matches the pre-kill numbers. Kill a store's server, keep wifi up → the pill reads "no server" within a minute.

Two roles are deliberately absent: an agent never holds a row, and there is no "owner" superuser that skips the QC gate. Shared devices are named tablets; a personal login is used when more than two people close batches in a shift. Names on records come from the device session, and every record shows which device made it.

Publish authority — D4, the decision that unblocks opening

The bench cannot make food from an unpublished recipe. All four versions are currently DRAFT. That is one decision away from being an opening-day standstill.

Recommended shape: two named humans. Ricardo holds final publish; a named operations person holds the second key so a Friday-night fix does not need a phone call to him. One name cannot publish twice. Publishing is irreversible in the sense that matters — vN is frozen, changes become vN+1.

Why not one key: the manager becomes the only path to a fix and every typo waits for him. Why not three: a committee has no owner. Why not the agent: I10 exists because a machine cannot carry the liability for food.

Zoho Learn keeps the SOP. The Bench does not replace it.

Zoho LearnThe Bench
The written SOP and the training record. Who was trained, when, by whom, on which version.The action on the floor. Which card was run, by whom, with which choices and results.
One link out of each bench screen: "How this recipe is taught."Never hosts a certificate, never records a training completion.

Three adoption risks, stated plainly

  • Flags get punished. If a shortage is debriefed by reading the flag's name aloud, staff stop flagging within a month and the dashboard reads perfect. The manager closes every flag in person at shift end for the first fortnight, and flag-to-close latency is published weekly.
  • Green ticks without tests. A tick is cheaper than a measurement. The close now demands numbers — and the manager spot-checks one batch a week against the physical pasta.
  • The tablet becomes "the thing we tried". One bad morning without a paper fallback ends it. Hence the printed pad in Part eight.

Computed from the manual's own ranges, not from supplier quotes. The point: the defect is small per plate and permanent per week — and either reading is defensible, which is exactly why it is a decision, not a bug fix.

What the manager screen earns its place by showing

Keep

Yield variance. Planned portions against recorded output, per recipe, per week. This is the only number that changes what a cook does tomorrow, and it costs one subtraction.

Cost drift, weekly, one line. The biggest mover of the week and its rand impact per portion. Silent when nothing material moved.

Defer

The live-margin dashboard. The menu is printed before opening and nobody re-prices a plate because baobab moved 8%. The red team's test: "if a portion went from R8.00 to R10.80, what would you do?" If the answer is "nothing until the next print", the dashboard is decoration and the build time belongs to sync hardening.

Part six

Architecture — where the truth lives and how it survives

ConcernDesignTest that proves it
Local truthThe tablet holds the working copy in a durable local store, not memory. Every write is appended locally first, then queued.Kill the app mid-write; the event survives.
SyncServer holds a total order, each store its own sequence. Clients pull by watermark, push with client ids. Server dedupes on (device, client_id).Same batch pushed three times → one row.
Ledger integrityAppend-only JSONL, fsync per event, hash chain. A break refuses further writes. Flip one byte; the chain flags at boot and writes stop.
Connectivity truthHeartbeat against the ledger's last seq, not the network interface (I11).Server down, wifi up → "no server" inside a minute.
Multi-storePer-store sequences, one global ledger, store_id on every event. Clock skew is recorded, not corrected.Two stores, same day, no interleaving errors; both counts add up.
Formula at restZones A (percentages, server only), B (costed model, manager scope), C (weights on device for the pinned version).Deleting zone C leaves cards unbuildable, not wrong.
BackupNightly ledger copy to a second disk, verified by restore drill monthly.Restore on a spare machine reproduces stock to the batch.
HardwareKiosk mode, wall power, no personal accounts, one named tablet per station.Reimage a tablet in under 30 minutes.
SecurityLocal network only, no inbound from the internet, device revocation on the server. Revoke a tablet; its tokens stop working on next sync.

Three things this deliberately does not do: no cloud dependency, no per-seat licensing, no AI in the write path. Stage 10+ can add an assistant that reads; it never writes a version or closes a batch.

Part seven

Design and words — the part that decides whether it gets used

Ergonomics

  • Flour hands, gloves, wet surfaces. Targets at least 64 px, gaps at least 12 px.
  • Weights at 32 px bold, tabular figures, right-aligned. A cook reads grams from arm's length.
  • Landscape, 1280×800, no scrolling on the bench card. If it scrolls, the batch size is wrong.
  • One primary action per screen, yellow. Everything else is grey.
  • Contrast 4.5:1 minimum; the kitchen is bright and the tablet is dim.

The words

  • No error codes, no stack traces, no tool names on a kitchen screen.
  • Every offline message says what still works: "offline · working local".
  • Every red says what to do first: "Stop the mixer." then the reason.
  • Every failure says what was and was not recorded. "Nothing was recorded" is a complete sentence.
  • Status is a word plus a colour, never colour alone.

Language

The staff surface must be in the language the shift actually speaks, and that is a decision only Papa Pasta can make (question 6). Whatever is chosen, strings are externalised now so a second language is a file, not a rebuild.
