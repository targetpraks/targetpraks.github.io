What was wrong

Two consecutive stack-health filings were carded to AI-Space/1.Setup-Config/… while Beast correctly filed them to AI-Space/2.Automations-Skills/Reports/ and logged the deviation both times. The vault was never wrong; the link was. Its file= and doc= parameters carried the carded folder, and no note exists there, so the vault leg of the jump link 404'd on Ricardo's phone. The h= HTML leg stayed fine (19,920 chars rendered, verified 2026-11-15).

Where the wrong path came from: the 06:30 job prompt (~/.config/maio-stack/jobs/com.maio.courage-health.txt) said nothing about publishing, so the run hand-picked a layer — --layer 1.Setup-Config. That bypasses the tool's own content-type table:

The fix

The backups prompt was included because it is the same defect class: an auto-generated courage report published with no destination rule. Today's backup-check link happened to land correctly; with the prompt silent, that was luck, not a guarantee.
