CI cost fix — what to change in signet, and the runner question

From: Adrianna A · For: Tuan · Decision by: Ricardo, 28 Oct 2026 — zero spend Repos: InfinityBrandsOrg/signet, InfinityBrandsOrg/constellation

Why this is happening

The org is on GitHub Free and every repo is private. That gives 2,000 Actions minutes a month and — this is the part that bites — the spending-limit column in GitHub's own billing table reads "Not applicable". A Free org cannot buy extra minutes. When the 2,000 are gone, every job refuses to start.

Measured from the API, not estimated:

What Billed job-minutes
signet — October (180 runs) 3,845
constellation — October (9 runs) 35
Total against a 2,000 allowance 3,880
signet — 28 Oct alone (48 runs) 1,460
of which the single full job 1,138 (78%)

The block began 22:15 SAST on 28 Oct. Until it clears, CI is not failing on bugs — it is not running at all. Two open PRs (#12, #55) are code-ready but unverified for exactly this reason.

The quota returns on 1 November. At 1,460 minutes a day it would be gone again inside two days. So the fix is to spend fewer minutes, not to wait.

Change 1 — signet: cancel superseded runs

File: .github/workflows/ci.yml

This file has no concurrency block today. Codex pushes 48 times a day; every push starts three jobs that run to completion even after a newer commit supersedes them. constellation/.github/workflows/verify.yml already does this correctly — copy its pattern.

Add directly under the on: block:

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

This is the cheapest change and it breaks nothing.

Change 2 — signet: stop running full on every PR

full is the expensive job: brew install poppler ffmpeg webp imagemagick qpdf, a Chrome .deb download, then go test -p=1 ./... -timeout 60m, where internal/app alone measures about 1,265 s. About 27 minutes, every PR push.

It should stay a merge gate — do not weaken it, do not split the package, do not lower the timeout. Just run it less often.

(a) Replace the trigger block:

on:
  push:
    branches: [main]
  pull_request:
    types: [opened, synchronize, reopened, labeled]

(b) Add one line to the full job, directly under full::

  full:
    if: >-
      github.event_name == 'push' ||
      contains(github.event.pull_request.labels.*.name, 'full-ci')
    runs-on: ubuntu-latest

Net effect:

  • Every PR: build + gates ≈ 7 minutes. gates is the PRD §14 DoD-3 set — role matrix, the §5 decision engine, and the §8 anchor verification — which is the actual definition of done. That gate stays on every commit.
  • Every merge to main: the full suite, once.
  • Any PR where someone wants the whole suite before merging: add the full-ci label.

Leave build and gates untouched. They are cheap and they are the real gates.

Change 3 — constellation: nothing to change

verify.yml already has concurrency with cancel-in-progress, and it cost 35 minutes all month. Leave it alone.

Expected result

48 PR runs × ~7 min ≈ 340 minutes, plus main pushes at ~36 minutes each. Inside 2,000 with room, at the same push rate that burned it this month.

How to verify it worked

  1. Push a throwaway PR to signet. Run gh run list -R InfinityBrandsOrg/signet -L 5. Only build and gates should appear.
  2. Add the full-ci label to that PR. full should appear.
  3. Merge anything to main. All three jobs run.
  4. Check next month's burn stays under 2,000.

Later, only if it recurs — self-hosted runner on the Mac mini

If the agent loop keeps exceeding 2,000 even after the trim, the permanent zero-cost fix is a self-hosted runner on the mini. Minutes on self-hosted runners are not metered at all.

Setup (on the mini):

  1. GitHub → InfinityBrandsOrg → Settings → Actions → Runners → New self-hosted runner → macOS / ARM64. It prints a download and a config.sh command with a one-time token.
  2. Run it inside a container via colima (already installed on the mini) with --ephemeral, so repository code never touches the host filesystem — that machine holds the vault and the API keys.
  3. Install it as a launchd service so it survives reboot.
  4. Switch the workflows to runs-on: [self-hosted, macOS, ARM64].

Access — what Ricardo actually needs to do:

  • The runner dials out to GitHub over HTTPS and long-polls for work. There is no inbound port, no router change and nothing exposed to the internet.
  • Day to day: GitHub → Org → Settings → Actions → Runners. Start, stop, remove, and watch it go idle or busy — all from the web UI. No Mac access needed.
  • Install, restart, or read logs: needs SSH or a terminal on the mini. So yes, he needs the machine for setup and when something breaks — not for normal running.

Hard constraint: never let fork pull requests run on it. Restrict it to push and workflow_dispatch, keep it ephemeral, keep it containerised.

What we are deliberately not doing

  • Not making the repos public to get free minutes. That publishes Infinity Brands source.
  • Not upgrading to Team. It would cost $4 × 4 members = $16/month plus $0.006 per extra minute. Ricardo's decision is zero spend, and the trim makes it unnecessary.
