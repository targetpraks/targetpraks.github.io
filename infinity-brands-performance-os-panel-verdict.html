1. The verdict in one paragraph

The structure survives. The spine — Brand × BU, one writer per number, four systems with one job each, Action never the sole score, monthly as the management unit — was protected by every seat without argument. What does not survive is the feasibility claim: the plan told the CEO its gate would pass 71% of the plan, and the gate actually passes nothing at all, because the sheet has columns for two of the gate's seven conditions and the owner column names units rather than people. The panel's unanimous second finding is that the close, not the structure, is where this dies: verification has never happened in this company (0 signatures in 4,200 rows), and the plan assigned it to a role with no person in it.

3. Where they split, and how it was ruled

Split one — is the plan merely under-specified, or is it aimed at the wrong object? Two seats argued the 375 "key results" are mostly activities and should be re-authored from scratch; three argued nothing should be rewritten before the gate is actually applied once. The chair backed the gate: "Run the activation-gate test against the live OKR sheet, publish the exact count, and share that result with the leadership team." Ruling: the gate is applied first, and its output — not a rewrite project — decides what happens to the 375.

Split two — when does the individual layer get built? One seat wanted all ~55 roles before the pilot; one wanted the pilot to run with no individual layer at all. Ruling: the pilot BU's roles only, before the pilot. The pilot cannot demonstrate a band path on an empty layer, and 55 roles is not a pilot's workload.

Split three — is the ClickUp field rebuild safe? One seat insisted the intake lists share the Business Unit field and would break. Measured after the fact: both intake lists carry zero custom fields and no task anywhere holds a value in that field. The rebuild is safe today and will not be once the lists fill — which is an argument for doing it now, not later.

4. Where the panel was wrong, and I am not repeating it

A verdict the owner cannot verify is a rumour with a chair. Four claims failed the evidence pack.

Panel claim Measured truth
"372 of 375 have no digit in the metric value, so ~3 pass the gate" — four seats, and the chair repeated it Wrong, and my fault. My annex read column I (Metric Source) where column J (Metric Value) was meant. 110 rows contain no digit; 265 contain one. The plan's target count was right.
"The gate can never pass because a metric value is a sentence, not a number" Wrong. 265 rows carry a number. The gate fails for a different reason: the owner column names units, and four required columns do not exist.
"You cannot have two Business Unit fields / rebuilding options breaks the intake lists" Wrong. The option set is 13 everywhere, the intake lists carry 0 fields, and 0 tasks hold a value.
"The S&M pilot collapses to 3 closable KPIs because only Outcomes pass the gate" Wrong. The gate does not require Outcome. All 25 S&M KPIs have targets; the pilot is narrow because it is one BU and one month.

And the correction that outranks all of them, which no seat made: the gate fails 375 times out of 375, not because of targets, but because 0 of 375 rows name a human being as owner, and there is no column at all for cadence, weight, baseline or verifier. While checking the panel's arithmetic I found the real one.

6. The ranked actions the panel signs

  1. Publish the gate truth to leadership — 0 of 375, and why. Everything after this is a consequence of that number.
  2. Name a verifier and a deputy per BU, and make an unsigned month stay open. The one control that has never existed.
  3. Put a person's name against every key result that will be Active, and a number against the 110 that have none. This is management work, not build work, and it cannot be delegated to a script.
  4. Freeze the IDs as literal values before anything moves, and rebuild Business Unit while it is still empty.
  5. Write the monthly sequence for the pilot BU's quarterly targets — the pilot is meaningless without it.
