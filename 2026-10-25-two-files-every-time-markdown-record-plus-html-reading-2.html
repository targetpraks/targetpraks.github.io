Two files, every time

Ricardo reads reports as HTML pages, not as raw markdown. The vault needs markdown. So from today every document an agent publishes produces both, from one command.

What you get

  • A markdown record — the note in the vault, with its frontmatter, findable by search, linkable, part of the graph, readable in Obsidian on the phone.
  • An HTML reading edition — the styled page on the public site. One tap on the link, any device, any country.

Why not one or the other

HTML alone was the pattern until now, and it cost something: a .html in the vault is an attachment to Obsidian, not a note. Vault search does not look inside it, backlinks do not point at it, the graph never sees it, and the iPhone does not render it as a page. The vault held 149 of them and 36 had no markdown beside them at all — invisible to everything except the file browser.

Markdown alone would lose the thing that actually works: the page you read. Markdown's own renderer in Obsidian is fine for short notes and poor for tables, side-by-side figures and long reports.

How it works

  • Written in markdown: the tool renders the HTML edition with the house template and publishes it.
  • Written as a hand-built HTML brief: the tool converts the page back to markdown for the vault record, and files that — not the raw page.
  • The markdown record links to the reading edition, so either direction gets you to the other in one tap.
  • A missing converter, a failed push or a git refusal is a warning. The document itself is never lost.

What stays the same

  • One link per document, in the fleet's jump.html shape. It carries both: Read the HTML and Open in Obsidian.
  • The vault is still written only by Beast, through the rule-4 handoff. Agents never write it.
  • Styling lives in one template, so it can be improved in one place and every future edition picks it up.
