How a turn runs

  1. session/new → a T3 session; the platform conversation is opened on the first prompt.
  2. session/prompt → POST /api/v1/agents/{agent_id}/run with Prefer: respond-async → 202 and a run request.
  3. The adapter polls GET /api/v1/run-requests/{id} every 2.5 s, streams the assistant text into the thread as session/update chunks, and stops on completed / failed.
  4. Cancel → POST /api/v1/runs/{run_id}/cancel. A parked approval or question comes back into the chat with a line telling Ricardo to answer it on the platform.
  5. Later prompts pass conversation_id back, so the T3 thread keeps the platform conversation's memory.

Standing rules for this lane

  • Full tools, by Ricardo's word — the lane inherits Iron Man's platform toolset (ClickUp, Zoho, GitHub). Restricting it is an agent-version/permission change on the platform, not in this adapter.
  • Governance stays on the platform — budget, approvals, parked tool calls and questions run there; the adapter only carries text in and out.
  • No credential on this Mac — the owner login happens inside the ssh pipe on macserver.
  • It is its own lane. Never relabel it onto acpRegistry_bruce: that is what put "Iron Man" on Bruce Wayne's row on 25 November.

If it stops working

tail -20 ~/.local/state/agenticos-acp/adapter.log     # what the lane did last
ssh macserver 'python3 -c "print(1)"'                 # is the relay's transport up
~/.local/bin/agenticos-acp < /dev/null                # starts, waits for ACP on stdin

A dropped ssh is respawned on the next request. A provider row that reads enabled: false in ~/.t3/userdata/settings.json is the usual cause of "Iron Man is missing from the picker".
