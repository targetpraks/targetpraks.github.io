Published pages are now a promise

delete a listed page → refused, naming the link commit as Ricardo → refused; author is maio-agents deliberate deletion → one line: ALLOW-PAGE-DELETE: <reason>

What happened

Your Read the HTML button for the Perlite Works plan pointed at …/2026-11-02-perlite-works-south-africa-business-plan-2026-2.html and opened a 404. The publish had worked — the page was live at 07:49. Two minutes forty-eight seconds later, a hand commit called "Remove duplicate perlite plan page" deleted it, and that commit was signed Targetpraks rickymaio@gmail.com.

So there were two separate faults, neither of them a publishing bug:

  1. an ad-hoc commit in the pages checkout landed under your git identity, and
  2. deleting a page that carries an issued link was a silent side effect of a tidy-up.

Both are closed now. The page itself was restored byte-for-byte earlier (5f1fb28c) and both editions serve today: the -2 edition and the newer edition.

What changed

Nothing in that checkout commits as you any more. The checkout now carries its own identity, maio-agents <agents@maio.local>, and a guard refuses any commit there whose author is you — whatever the config says. The tool already named the publishing agent on its own commits; a hand fix now cannot quietly carry your name.

A published page cannot be deleted by accident. Every page the site publishes is recorded in .publish-ledger.tsv inside the checkout — name, URL, title, when it went live, who published it, and a content hash. publish-document writes that line in the same commit as the page, so the record of a link can never lag behind the link. A commit that deletes a page is refused, and the refusal tells you which link it would have broken:

pages-guard: refusing to delete a published page.

  2026-11-02-perlite-works-south-africa-business-plan-2026-2.html
    published 2026-11-02T08:02:22+02:00 by batman
    "Perlite Works South Africa — Business Plan 2026"
    https://targetpraks.github.io/2026-11-02-perlite-works-south-africa-business-plan-2026-2.html

A published page is a promise: the URL is quoted in a vault note and in Ricardo's chat, so a page
that goes takes a link with it and returns 404 to whoever opens it.

Deleting on purpose still works — it just has to say why, in the commit message, where it stays in history:

Withdraw the superseded edition

ALLOW-PAGE-DELETE: the vault note and the jump link both name the -2 edition

One document, one URL. The duplicate that started all this existed because the site name comes from the document's filename: one document saved under two names became two pages. A publish that would create a second name for an already-published title now says so, by name, at the moment it happens — it does not refuse the publish, because losing a link to a warning would be worse.

It holds in a fresh clone too. Hooks are not cloned with a repository, so the rule also runs from the machine-wide ship-small hooks, scoped to this site's origin. Commits made with --no-verify are still stopped at push.

What it means for you

Nothing to do, and nothing to remember. If a page's link is quoted somewhere, the page stays. If a page genuinely has to go, the agent withdraws it in one line that says why — and it is in the history if anyone asks why that URL 404s a year from now.
