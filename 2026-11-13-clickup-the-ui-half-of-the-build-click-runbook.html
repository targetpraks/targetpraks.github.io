2. Views — every list

Why it has to be clicked: POST /list/{id}/view creates the view, but the filters object comes back empty on read — the API drops filters silently. 98 views exist today and 0 carry a filter.

Standard four views on each of the six format lists, in this order:

  1. Board — group by status, no filter.
  2. Table — columns: name, assignee, priority, due date, Business Unit, Work Format.
  3. Waiting On — filter: status is Waiting OR Blocked.
  4. This Week — filter: due date is within this week, closed tasks hidden. SLA lists (SLA - EXP, SLA - TLF, SLA - TIE, SLA - Breach Log) get a fifth: SLA Board — group by SLA State, sorted by First Response Due.

3. Formula fields F12, F13, F16 — the SLA clock

Why it has to be clicked: POST /list/{id}/field with type formula and a field reference returns 400 Invalid formula. Only literal formulas are accepted (CONCATENATE("a","b") works), so the date arithmetic cannot be created by API.

Where: list → … → Custom Fields → + New Field → Formula. Set them on the four SLA lists:

F12  First Response Due   =  DATE_ADD(created, 4, "hours")        # Gold
                             DATE_ADD(created, 8, "hours")        # Silver
                             DATE_ADD(created, 16, "hours")       # Black
F13  Resolution Due       =  DATE_ADD(created, 3, "days")         # Gold
                             DATE_ADD(created, 5, "days")         # Silver
                             DATE_ADD(created, 10, "days")        # Black
F16  SLA State            =  IF(Is Empty([Resolved At]), IF(TODAY() > [First Response Due], "Breached", "On Track"), "Met")

If the ClickUp formula editor rejects DATE_ADD, use the same arithmetic on Start Date with the space's due-date ClickApp, or use a Date field filled by an automation. Either way the three fields are the only acceptable outcomes.

Three items remain: view filters (98 views still carry none), formula fields F12/F13/F16 on the four SLA lists, and chat sidebar sections. All three are React panels that ignore synthetic DOM clicks — they need a real mouse.

That is a permission, not a wall: CuaDriver.app has never been granted Screen Recording (System Settings → Privacy & Security → Screen Recording), so CUA returns screenshot_error: px_capture_unavailable, direct_capture_consent_required and refuses coordinate clicks with screenshot_context_missing. Grant it once and those three items are mechanical: the coordinates are already known, the pages are open, and each is a handful of clicks per list.
