Bottom line

What it is: Dahl is a broker, not a model vendor. It routes OpenAI-shaped requests to the Gonka network — a decentralised GPU network whose chain keeps proof-of-compute records — and handles accounts, tokens and billing. The operator is FROMZERO OÜ (Estonia, registry 17062264); the Gonka network was incubated by Product Science (the Liberman siblings; ~$80M raised, incl. a $50M Bitfury investment, mainnet since Aug 2025).

Why it is worth a look: the same three open models behind one small base-URL swap, at roughly 1–2% of frontier API pricing, with a large free grant to evaluate on. It is the cheapest practical experiment lane when you want MiniMax / DeepSeek / GLM class models without a cloud-giant account.

The catches: account recovery is a lost-fingerprint dead end (store it in a password manager at sign-up); paid top-ups are crypto only; there is no zero-retention promise — keep sensitive data out; and model IDs / uptime move with network capacity.

Endpoints

  • GET /v1/models — public, no key. The live catalog.
  • POST /v1/chat/completions — OpenAI-compatible; streaming (SSE) and function/tool calling work.
  • POST /v1/responses — thin adapter over the same models, for Codex CLI / OpenAI Agents SDK.
  • GET /v1/status?window=1h|24h|7d|30d — public uptime probe per model.

What I verified live (raw probes)

  • GET /v1/models → HTTP 200 in 0.25 s, three models, owned_by "gonka".
  • POST /v1/chat/completions without a key → HTTP 401 invalid_api_key in 0.24 s — the auth wall is real.
  • GET /v1/status?window=24h (9 Oct 2026): GLM 5.3-Flash 100%, DeepSeek V4-Flash 99.3%, MiniMax M2.7 91.7% (it read 96.5% the day before — there is real day-to-day variance); 7d/30d windows: 95.9–98.7% per model.
  • TLS via Google Trust Services; fronted by Cloudflare; browser chat UI at /chat returns 200.

§2 Pricing & the free tier

Free to evaluate

  • 100M tokens deposited in the account pool at sign-up — no card, no email (username + save-once fingerprint)
  • Tokens must be allocated from the pool to an API key before requests; a key at 0 returns 402
  • Failed requests are not charged; creating extra keys does not grant more free tokens

Paid, if it earns a slot

  • ~$0.03 per 1M tokens, prepaid packages ($5–$100); balances do not expire
  • Top-up is crypto only (USDT, BTC, others via NOWPayments)
  • No subscriptions or recurring charges; refund scope is narrow (business purchases generally non-refundable)

§3 Wire the whole set into Hermes Agent

Hermes holds every account side by side — each one a named custom provider — so you route per task and keep a fallback chain for when one throttles. Six accounts, one config file, about four lines each. All six speak the OpenAI API, so the pattern repeats identically.

Step 3 — paste the full provider set into config.yaml

# ~/.hermes/config.yaml
model:
  default: "MiniMaxAI/MiniMax-M2.7"
  provider: custom
  base_url: "https://inference.dahl.global/v1"
  key_env: DAHL_API_KEY

# Every account, side by side. key_env keeps the secrets in .env only.
custom_providers:
  - name: dahl
    base_url: https://inference.dahl.global/v1
    key_env: DAHL_API_KEY
  - name: gonkagate
    base_url: https://api.gonkagate.com/v1
    key_env: GONKAGATE_API_KEY
  - name: joingonka
    base_url: https://gate.joingonka.ai/v1
    key_env: JOINGONKA_API_KEY
  - name: mingles
    base_url: https://router.mingles.ai/v1
    key_env: MINGLES_API_KEY
  - name: chutes
    base_url: https://llm.chutes.ai/v1
    key_env: CHUTES_API_KEY

# Short names for /model — route by role, not by brand
model_aliases:
  dahl:
    model: "MiniMaxAI/MiniMax-M2.7"
    provider: custom
    base_url: "https://inference.dahl.global/v1"
    key_env: DAHL_API_KEY
  cheap:
    model: "MiniMaxAI/MiniMax-M2.7"

This block was loaded into a scratch Hermes install (nothing touched a live setup): the providers, aliases and the three-deep fallback chain all parse and list cleanly. Prefer clicking? hermes model → “Custom endpoint” walks the same four fields for the first provider.

Step 4 — switch by role; verify in two commands

# in session — by alias, or by named provider (triple syntax)
/model dahl                                     # alias → Dahl
/model cheap                                    # alias → GonkaGate
/model private                                  # alias → Chutes (TEE)
/model custom:gonkagate:MiniMaxAI/MiniMax-M2.7  # named-provider form
$ hermes config check      # parses config.yaml and flags anything wrong
$ hermes fallback list     # prints the chain in fallback order

Smoke-test any row of the table

$ BASE=https://api.gonkagate.com/v1 KEY=$GONKAGATE_API_KEY   # swap in any row
$ curl -s $BASE/chat/completions \
    -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
    -d '{"model":"MiniMaxAI/MiniMax-M2.7","messages":[{"role":"user","content":"Hello!"}]}'
# 200 = key works · 401 = bad key · 402 = no tokens allocated on the key

How it behaves once wired

  • Stack the free lanes first. Dahl 100M + JoinGonka 3M + Mingles 3.9M/week + OpenRouter's 19 free models — an evaluation budget at $0 before any top-up.
  • One primary, an ordered chain behind it. Fallbacks fire on rate-limit, 5xx and connection errors; a 429 naming its reset time benches that provider until exactly then.
  • Switching persists. A mid-session /model switch survives a restart; stepping back to a built-in provider clears the custom base URL automatically.
  • Keys stay scoped. Each named provider resolves its credential from its own key_env — never from the account that happened to be active before.

§5 The catches

Fingerprint-only accountLose the 32-character fingerprint and the account cannot be recovered — no email reset exists. Store it in a password manager the moment you sign up.
No zero-retention promiseThe operator's own policy declines to guarantee zero retention or anonymity. Do not route sensitive data through it.
Prepaid crypto; narrow refundsTop-ups are crypto-only (effectively no chargebacks), and business purchases are generally non-refundable for convenience.
Uptime wobble~92–100% per model day-to-day, with occasional 503 "no available backend" spikes. Fine for evaluation; not for hard-availability workloads without a fallback.
Model churnIDs appear and rotate (Kimi K2.6 has already retired). Always resolve model IDs from GET /v1/models at runtime.
Young network economicsMainnet since Aug 2025; the GNK token trades far below its high, which is part of why pricing is this low. Brokers can reprice.
