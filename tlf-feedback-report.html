2 General

The TLF application is designed for franchises, covering both growing and processing functions. The overall program appearance was well received during the demo meeting.

This report consolidates all feedback items raised during the demo for the INFX Solutions team to action. Items are grouped by functional module.

3 Tenant Functionality

New tenant functionality has been added and was well received during the demo. The following configuration and setup items are required:

  • Set up the existing store as "The Local Farmer Betterview" within the tenant functionality.
  • Must include microgreen and mushroom price lists for this tenant.
4 Back Office / Administration

The back office requires several enhancements to give the franchisor full operational control across all tenants:

  • Add function for franchisor to fully update price lists of all tenants from a central interface.
  • Replicate the existing "Today" viewing dashboard.
  • Add a month view option alongside the "Today" view.
  • Create a filter that references "today" or "within this month" for dashboard data.
5 Client / Customer Management

Client management requires faster lookup and search capabilities to reduce time spent scrolling through client lists:

  • Create short codes for clients in the format: 3 letters + 3 numbers (e.g., ABC123).
    • Purpose: faster searching instead of scrolling through the full client list.
  • Add a search function for clients within the sales module.
6 Sales Module

The sales module requires several enhancements to support packaging differentiation, subscription orders, and grow calendar integration.

6.1 Packaging & Retail/Wholesale Indicators
  • No current option to indicate packaging type selected during sales order capture.
  • Missing indicator for Retail vs Wholesale product type.
  • Wholesale requires different packaging and costing compared to retail.
  • Add a highlighter/indicator to distinguish retail vs wholesale during sales order capture.
6.2 Subscription Orders

The ability to load subscription (repetitive) orders is a critical new feature. Requirements:

  • Ability to load a subscription order for repetitive delivery over 3, 6, or 12 months.
  • Subscription order should auto pre-populate the growing calendar.
  • Subscription could be based on a weekly delivery schedule or multiple days per week.
  • Subscription orders must tie into the billing module.

7 Grow Module

The grow module needs visualization and calculation tools to help growers compare planned demand against actual production:

  • Add a heat map / trend map visualization for grow space (popular AI agent trend).
  • Add visualization comparing planned/scheduled sales vs. currently being grown.
  • Add calculation comparing expected/required sales yields (grams on order) vs. expected grow plan.
  • Add a variation calculator to show if producing surplus or shortage.
  • Add visualization of this variation within the growing module.
8 Grow Room Allocations

The system must enforce three allocation categories per tenant/franchise. These categories must be incorporated into both the application and the actual company operations:

1

Stock Order Allocation

For retail orders, new clients, specials, and website/sales opportunities.

2

Scheduled Growth

For regular/subscription clients — ensures consistency and trust.

3

Ad Hoc Growth

Small emergency tray for one-off orders and overruns.

⚠️ These allocation categories are mandatory and must be reflected in both the software and operational workflows.

9 Purchasing Module

The current purchasing workflow allows the grower/grow expert to push direct purchase orders automatically. This must change to include an approval gate:

  • Current state: Grower/grow expert can push direct purchase orders automatically.
  • Required change: Implement an approval process.
    • Grower creates a draft purchase order only.
    • Draft requires administrator approval before it can be pushed to the purchasing module.
10 Cleaning Module

The cleaning module needs global distribution and multi-schedule support:

  • Add ability to push cleaning module functions/steps globally to all tenant solutions.
    • Purpose: enable global updates for health and safety changes across all franchises.
  • Add support for multiple cleaning schedules to be uploaded.
11 Grow Production Module

Production stages must be configurable from the back office and distributed uniformly:

  • Add ability to set production stages in the back office.
  • Production stages must push uniformly across all tenanted franchises.
12 Grow Batches Module

The production process currently shows three stages, with a fourth stage required. The batch module must support configurable, variable-duration stages for both microgreens and mushrooms:

12.1 Production Stages
1
Tray Preparation
Specific to microgreens. Includes multiple sub-steps to program.
2
Growing
Different microgreens have different growth timelines. Duration must be configurable per type (e.g., 10, 14, or more days).
3
Harvesting
Final data capture of harvest.
4
Packaging
Retail, wholesale, or mixed packaging.
12.2 Stage Configuration Requirements
  • Mushroom growing process also needs back office stage configuration.
  • Add ability to create multiple production stages for both mushrooms and microgreens.
  • Add ability to apply specific production stage durations per microgreen type (e.g., 10, 14, or more days).
  • Mushroom stages vary in duration as well — the production section must accommodate this variability.
