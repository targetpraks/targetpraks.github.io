1. What Zoho calls a "template"

Two separate things, and only one of them is API-readable:

Kind Count API Carries
Task-list templates — GET /api/v3/portal/{pid}/templates/tasklists 47 readable, including every task with its hierarchy, description and relative timing tasks + subtasks, relative start offsets, durations
Project templates — GET /api/v3/portal/{pid}/templates 3 (STORE OPENING, General FIN, HRM General) name/id only — no documented endpoint returns their body; child routes (/templates/{id}/tasklists, /tasks, /phases) all answer URL_RULE_NOT_CONFIGURED task lists, tasks, milestones, default assignees (UI only)

2. The 47 task-list templates

  • 32 are empty shells: 30 created in one batch on 2024-11-29 09:48–09:50 named <BU> <AUDIENCE> (FIN HEAD OFFICE, OPS FRANCHISOR, ZOR TLF MKT, …), plus Onboarding and Luke.
  • 2 are junk: Test (two tasks: Franchise Flow › Design) and Luke (empty, named after a person).

The 30 <BU> <AUDIENCE> shells are the department × audience template set. They were created as placeholders during the Zoho One rollout and never filled — the department work lives in the populated templates instead. They are still carried into ClickUp, empty, so the department inventory does not shrink in the move; each one is labelled Empty in Zoho in the register.

Relative timing is real and worth keeping: start_after + start_after_frequency (days) and duration + duration_type. ClickUp has no relative-date model, so every task that carried timing now opens with a ⏱ Zoho timing: line — e.g. starts day 0 · 14 days, starts 1 day(s) before project start — and no absolute dates are invented.

5. Why lists and not ClickUp Template Center entries

ClickUp's API can list and apply templates (GET /v2/team/{id}/list_template, POST /v2/space/{id}/list_template/{id}) but has no create endpoint — a template is built in the UI. The workspace currently holds 0 list templates and 0 task templates (3 stock folder templates only). So the build is the ClickUp-native source shape: one real list per template, fully populated, that a department duplicates to start a project and that can be saved as a List Template from the UI in one click.

6. How a department uses a template

  1. Open the Space → Templates folder → pick the TPL <DEPT> — … list.
  2. Duplicate the list into 02 Projects (or the project's folder) and rename it for the job.
  3. Set the real start date, then read each task's ⏱ Zoho timing line and place the dates from it — ClickUp has no relative-date model, so the offsets travel in the task body.
  4. To make it a proper ClickUp List Template (one-click from anywhere in the workspace): list menu → Save as Template. That step is UI-only; the API cannot create templates.
