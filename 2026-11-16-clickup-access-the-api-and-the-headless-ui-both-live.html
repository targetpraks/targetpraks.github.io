Lane 1 — the API: clickup

One command on the PATH, token read from the profile secret (never printed, never in a report).

clickup me                         # who + workspace + plan
clickup tree --lists               # every space, folder and list with ids
clickup lists "BU 1 FIN"           # lists in one space, ids included
clickup tasks <list_id> --all      # tasks, paging through 100 at a time
clickup fields <list_id>           # custom fields + dropdown option ids
clickup create-task <list_id> --name "…" --status "Open" --desc "…"
clickup update-task <task_id> --status "in review"
clickup set-field <task_id> <field_id> <option_id>
clickup comment <task_id> "text"
clickup raw GET space/901211093186   # anything not wrapped yet

Reference for the calls above: create a task · get a task · set a custom field value · comment on a task · get a space (statuses live here) · get space views · create a list · create a folder.

Where the API bites

Every one of these was hit while proving this lane today, not copied from a blog.

  • Statuses are per Space, not per list — read GET /space/<id> → statuses[] before sending a status, or ClickUp answers Status does not exist.
  • A dropdown field takes the option id on write and returns the option's order index on read. Resolve labels off type_config.options[].
  • Field writes are POST /task/<id>/field/<field_id>. PUT answers 405.
  • 429 is normal on bulk runs: pace ~0.4 s and back off 6 + 3i seconds, ~8 attempts.
  • Space creation via API lands shared unless you PUT {"private": true} and re-read it.

Lane 2 — the UI, headless: cu-ui

The statuses, fields, dashboards and sharing that the API refuses are all reachable: a Chrome runs against a copy of Ricardo's own ClickUp session — cookies and local storage copied out of his Chrome profile — so no password is typed and his real browser is untouched.

cu-ui ensure            # start headless Chrome with the signed-in profile
cu-ui open <url>        # open a tab and wait for it to load
cu-ui eval "document.body.innerText"   # read the page
cu-ui click "<selector>"
cu-ui shot /tmp/x.png    # screenshot for the record
cu-ui stop

Session profile: ~/.config/maio-stack/clickup-chrome · debug port 9333 · driver: node + CDP, no dependencies.

What this buys

  • Any task, field or comment change in the workspace is now a command — no clicking.
  • Bulk work (a whole list, a whole space) is a script, with a read-back proving the result.
  • The handful of things ClickUp keeps in the UI — statuses, field definitions, dashboards, sharing — are still doable, by the agent, in the signed-in headless browser.
