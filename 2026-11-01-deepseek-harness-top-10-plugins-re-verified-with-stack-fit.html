Why each would be great for us (Ricardo's stack context)

"Us" = Ricardo's local Hermes stack on this Mac: Discord + Telegram + terminal channels, local Ollama gateway (:11434/v1, pinned free models), Courage scheduled jobs/checks, Beast as vault steward (read-only to me), §8 gates via d3-flash-mlx, Maio OS cockpit, English-only to Ricardo, work routed to Bruce Wayne / Splinter — never handled by me.

1 · dsh-our-free-model — why great: frontier models with zero key management

Ricardo keeps OpenRouter at zero balance by design (free models only) and routes models through the local Ollama gateway. This plugin surfaces DeepSeek V4.1 Flash / Kimi K3 without any API key or signup, with local usage metering and signed, rollbackable upgrades. It would sit beside — not replace — the Ollama gateway, giving fallback frontier models with no credential surface. Caveat: the Kilo free-pool channel warns prompts may be logged for service improvement — never send sensitive content there; the EAC desktop channel requires a GitHub star handshake.

4 · MemOS / MemTensor — why great: local memory that talks to Hermes

Strongest fit on the list. MemOS publishes an official Hermes Agent local memory plugin — hybrid FTS5 + vector retrieval, smart dedup, tiered skill evolution, 100% local, zero cloud. Ricardo already runs Beast as vault steward and Hermes memory across sessions; MemOS would add structured, inspectable, graph-backed long-term memory that survives session pruning. All data stays on this machine (SQLite), which matches the credential/local-first posture. Worth evaluating against what Beast/Hermes memory already cover before adding anything.

5 · dsh-web — why great: scheduled task board + cost control

Host-authority task board with cron scheduling, multi-agent cascade, and an adversarial quality gate echoes Courage's scheduled jobs/checks — a possible comparison point, not a replacement. The token bank / daily cost monitoring fits Ricardo's cost discipline (OpenRouter at zero balance). GitHub Issue-to-PR auto-loop could be relevant if Ricardo ever wants hands-free issue triage — but that's his call, and any write to GitHub is a money/legal gate.

7 · dsh-routing-suite — why great: measured model routing

Task-aware reasoning-mode routing with real P1-P23 measurements (open-task completion 0% → 100%) is directly analogous to how Ricardo routes models through the local gateway and the §8 d3 gate. The dev router tools (dev_router_status, etc.) could inform how we observe routing decisions. MIT licensed, genuine DSH bundle. Worth a read-only diff, not an install.

8 · DS-Bot — why great: bots inside DSH, like ours on Discord/Telegram

Ricardo already runs bots (AdriannaA84, brucewayne84, Shadow84, Splinter84) on Discord and Telegram. DS-Bot is the DSH-native equivalent: long-lived bots, main bot + group chats, shared capabilities, local data under ~/.dsh. Conceptually adjacent — useful as a reference design if the bots ever need to operate inside DSH sessions rather than chat platforms. Apache-2.0, genuine plugin.

2 · anywhere-labs/dsh-desktop — why great: native Mac DSH desktop

A packaged macOS DSH desktop (DMG, no Node.js step) could complement Maio OS as a local GUI face for DSH. Ricardo's stack is terminal/Hermes-first, so this is optional — but if he ever wants a standalone DSH window on the Mac mini, this is the most-starred genuine desktop option (34.3k, MIT, community-run).

3 · dataelement/dsh-desktop — why great: Safe Mode + presets + PPT

Safe Mode (isolated profile, third-party plugins blocked) is exactly the kind of guard Ricardo would want before evaluating any community plugin — recover without wiping the normal profile. Portable .dshpreset agent presets and built-in PPT output could feed the "publish every document with a link" workflow. macOS builds are Apple-signed and notarized. MIT, genuine desktop.

6 · iPolloWork — why great: one workspace across agent engines

Unifies Codex, DSH, and OpenCode in a single project workspace — Ricardo already touches multiple agent runtimes on this Mac. Local-first and bring-your-own-model fits the local Ollama posture. License caveat: Source Available 1.0 is not OSI open source; free only for individual use and under 3 users, with written authorization needed beyond that. Would need Ricardo's legal sign-off before anything.

9 · Whale widget — why great: balance & cost visibility

If Ricardo ever uses DeepSeek API directly, this widget gives balance, per-turn cost, daily budget, and 34 vendor templates including OpenRouter and local Ollama/LM Studio ("local model, no interface"). Fits the cost-watching posture. Note: code MIT, but images/sounds are not re-licensable — run-as-is only.

10 · dsh-purge — why NOT for us

It's a red-team prompt-swap tool that patches the local harness packages, targets DSH 0.2.1-rc.2 only (rc.3+ unsupported), and the author posts legal/resale warnings. Modifying the host layer of a locally installed agent conflicts with the "prepare, don't change live systems without Ricardo" rule and the credential/stack discipline. Excluded from consideration.

Bottom line

  • Most relevant to our stack: MemOS (Hermes memory plugin, 100% local), dsh-routing-suite (routing measurements), DS-Bot (bot pattern reference), dsh-web (task board + cost monitoring).
  • Most optional / nice-to-have: dsh-our-free-model (fallback frontier models, watch the Kilo-pool data warning), the two DSH desktops, iPolloWork (license-restricted).
  • Do not install: dsh-purge.
