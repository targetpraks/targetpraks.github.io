The upstream production ceilings (app 2560 + db 2048 + valkey 512 + worker 2560 = 7680 MB) exceed this VM's 7400 MB total, so a reduction is required for the gate to pass. The reduction is recorded in docker-compose.instance.yml; it is a configuration change, not a hidden default. Worker and database ceilings were rebalanced once against measured appetite (worker 961 MB idle of a 1024 MB ceiling → 1536 MB; database 78 MB of 768 MB → 512 MB).

CPU compared separately: app 2.0, db 1.5, valkey 0.3, frontend 1.0 against 6 vCPU; worker keeps the default share because a cpus key conflicts with the upstream deploy.resources block.

Not done — by design

  1. Model profile. The bootstrap CLI offers Anthropic, Google, OpenAI and OpenRouter only, and no provider key was placed on the host. Ollama Cloud is added in the product (Settings → AI providers), which is where the key belongs — in the encrypted vault, not a file.
  2. Embedding integration row. The ollama-embed endpoint answers both callers, but registering it as the ollama provider at http://ollama-embed:11434/v1 is a product step.
  3. SMTP, so invitations cannot be proven.
  4. Staff access route (PRD D4) — company network only versus an authenticated HTTPS address. Until that decision, the console is tunnel-only.
  5. Live Zoho, MCP connections, departmental bots (Stage D/E) — each needs D1–D5 answered and Zoho admin work.

Reproduce

The three compose files plus agenticos.sh are the artefact; .env secrets are per-install and are not copied anywhere. Rebuilding elsewhere is pull → up → bootstrap as the README sets out.
