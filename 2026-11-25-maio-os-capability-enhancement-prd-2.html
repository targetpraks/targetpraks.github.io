01 - PURPOSE

This document defines the enhancements to every capability of the website at https://ricardos-mac-mini.taile9f837.ts.net:9443/#wheel and assigns responsibility for the delivery of each to Google Neon.

The request named no specific enhancement for any capability. Every enhancement detail that the requester did not state is marked [unspecified]. The proposed requirement under each capability is derived from the live build and its documented contracts, so the scope is grounded in what the site actually does today, not in assumption.

02 - PRODUCT IN ONE PARAGRAPH

Maio OS is a single-user workspace over Ricardo's household: one static shell, one generated data snapshot, and one loopback companion that adds live machine readings, the fleet board, document reading, vault search, and the folded-in Life applications. Content opens in the main area with persistent navigation and bookmarkable routes. There are no floating windows and no pop-up search. The vault is read-only to the site and Beast is its only writer. Money and legal actions are never taken from the site.

03 - CURRENT CAPABILITY INVENTORY (EVIDENCE FROM THE LIVE BUILD)

Shell and navigation

  • One HTML shell at the repository root: index.html, 218,201 bytes, with assets/theme.css, assets/workspace.css and an icons.svg sprite.
  • 19 section definitions registered in the shell: overview, projects, agents, reports (Library), kanban, machine, vault, prds, stack, almanac, recordings, path, wheel, astro, top8, accounts, search, file (hidden), about.
  • Persistent sidebar, breadcrumbs, top bar with a generated-at stamp, and a Search button that binds Command-K.
  • Route grammar: #section, #project:name, #agent:name, #file:relative-path, #report:agent, #docs:title, #almanac:YYYY-MM-DD, #desk.

Data

  • data.js is a 328 KB generated snapshot, owned by the refresh job and never hand-edited.
  • local.js is the live payload, refreshed on a 30 second cycle and on window focus. Its keys are: machine, ram, slow, ollama, omlx, sessions, spend, kanban, launchd, docker, serves, library, services, recordings, almanac, path, firefly, companion.
  • Snapshot and live readings are rendered as distinct states with honest badges.

Companion API (declared in /openapi.json)

  • GET /health, GET /local.js, GET /openapi.json.
  • GET /api/fix/log, POST /api/fix, GET /api/vault/search, GET /api/vault/note, GET /files/{rel}.
  • GET /api/top8/status, GET /api/top8/research.
  • Reverse proxies for /wheel (Next application on 127.0.0.1:3210) and /astro; static serve for /top8.
  • Every route enforces a Host allowlist; fix endpoints require a token for non-loopback hosts; vault reads require an allowlisted origin when an origin is present.

Gated actions

  • Trim RAM, model unload, model warm, allowlisted service restart across 6 labels, and data refresh.
  • Each action is two-click confirmed, cool-down limited, and written to the action log.

Work

  • Projects, Kanban and Agents sections, reading the generated snapshot plus the live fleet board.

Knowledge

  • Library over three shelves (Machine, Public, Docs), PRDs found in the vault, and Vault search plus read-only note rendering through the companion.

Life

  • Almanac: daily reading, weekly Green Light timing map, Oracle of the Week, event calendar, and the moon computed in-process.
  • The Path: the Manual and the Grimoire of Light, with today's principle and the grimoire's cleansing window read against the computed moon.
  • Wheel of Life: a mounted Next 16.3.2 application with React 19 and Prisma 7.9.1 over SQLite, with pages for the wheel, goals, ikigai, thinking, board and settings, and API routes for stock, backup and upload.
  • Astro Cartography, Top 8 magazine, and Accounts (Firefly III, linked out and never framed, read-only).

System

  • Machine, Stack and About, including launchd, docker, serves, local model runtimes and the service allowlist.
