Hermes Memory Providers — the free-only bake-off

Three engines, one identical corpus, measured retrieval, freshness and cost. Then the community and benchmark evidence behind the numbers. No paid tiers considered: if it needs a card, it is out.

24 notes · 26 ingested units 22 scored queries + 2 abstention controls Mac mini · macOS 27.2 · arm64 cost: £0.00

Best free answer: Mnemosyne — with Hindsight demoted to "quality ceiling".

Mnemosyne gets 17/22 top-1 and 20/22 top-5 for zero tokens, zero cloud, 0.44 s ingest and 2.1 MB on disk. Hindsight scores higher (20/22 and 22/22) but pays for it with 144,000 tokens and 177 LLM calls per 26 notes, a 3.58 GB container plus a 4.0 GB volume, and — on this Mac, today — an extraction model living at ollama.com, i.e. your memories leave the machine. For a fleet that runs 24/7, in many profiles, on free models, that trade is the wrong way round.

01How the test was built

A 24-note corpus in the fleet's own domain — ports, launchd behaviour, vault rules, model routing, standing preferences — with 22 answerable questions and 2 deliberately unanswerable ones. Every question was written the way a person actually asks: paraphrased, sometimes referring back ("that older port I used to call"), never by keyword.

  • Scoring: each returned memory is mapped back to the corpus note it most resembles (token Jaccard), then hit@1 / hit@3 / hit@5 and MRR are computed. Marker strings are not used, because every engine rewrites the note during extraction — scoring on markers would have measured the rewriter, not the retriever.
  • Fairness: each engine ran through its own native pipeline — Hindsight through its HTTP API, Mnemosyne through its own SDK — not through a hand-built index.
  • Floor row: a plain SQLite FTS5 index of the same notes, to establish what "free keyword search" alone is worth.
  • Test data only: Hindsight ran in a throwaway bank that has since been deleted; Mnemosyne ran in throwaway banks that are also gone. Nothing touched production memory.

Read the numbers honestly: three queries separate Hindsight from Mnemosyne, on a 22-question synthetic set. That is a real edge on multi-hop and rephrased questions, not a landslide — and it is bought at roughly 400× the ingestion cost.

03The freshness test — nobody wins

I added two plain supersession notes: "Snappier moved off 8800 to 8850" and "RAM guard raised from 85% to 90%" — synthetic fixtures, not changes to any real service. Then asked for the current value.

EngineResultDetail
Hindsight0 of 2Both stale values held rank 1. The update was present at rank 3 / rank 2. A /consolidate pass was accepted and did not change the ordering.
Mnemosyne1 of 2Snappier update won rank 1; the RAM-guard update sat behind the old value. Enabling the LLM knobs did not change it (0 consolidated).
FTS5 floorn/aReturns both notes; the newer one is not preferred.

Conclusion: no free engine resolves contradictions for you. The reliable fix is procedural, not a vendor — write the supersession into the note text itself ("port 8800 is retired, 8850 is current") and keep a nightly consolidation job. This is exactly what hermes-dreaming is for, and it is the one add-on I would actually add.

Where extraction runs

ollama.com

Hindsight's container is configured with HINDSIGHT_API_LLM_MODEL=gpt-oss:20b at https://ollama.com/v1. Its embeddings and reranker are local; the note text is not.

The container setup itself is worth stating plainly: Hindsight is not a native Mac service here — it runs as ghcr.io/vectorize-io/hindsight inside colima, with port 8888 forwarded into the VM. That is one more moving part between a memory write and a disk on this machine.

On the benchmark side, treat published memory scores as a contested field rather than settled science:

  • The LOCOMO dispute is unresolved. Zep publicly attacked mem0's SOTA claim and reported 84% on LOCOMO; an independent re-evaluation put Zep's own number at 58.44%; mem0's 2026 pages report 91.6–92.5 on LOCOMO and 93.4–94.4 on LongMemEval. Every one of those numbers is vendor-published or vendor-rebutted.
  • Hindsight and Zep both sit at the top of LongMemEval — 91.4% vs 90.2% as each reports it — which is the strongest independent-ish signal for graph memory being genuinely better at synthesis, and consistent with my multi-hop row.
  • Judge models differ between vendors, so a 65% from one and a 73% from another are not the same ruler. Anyone quoting a single memory percentage as proof is overselling it.

07What I changed, and what I would do next

  • Done: Hindsight updated 1.2.1 → 1.2.3 (hermes plugins update hindsight, now pinned at d952b6e6). The daemon is healthy and all production banks are intact.
  • Proposed: switch memory.provider to mnemosyne for this profile, keep Memory Wiki as the audit pane, and add hermes-dreaming for nightly consolidation. Expected effect: memory writes stop costing tokens and stop leaving the machine, retrieval drops from 91% to 77% top-1 on this corpus, and the multi-hop edge narrows to one or two questions.
  • If you would rather keep maximum recall: leave Hindsight in place but move its extraction model off ollama.com onto the local Ollama gateway and pin consolidation to the decision model — that removes the cloud exposure without losing the graph.
  • Next test worth running: Mnemosyne with its consolidation actually engaged (the SDK path left consolidated: 0 — the LLM features need the plugin runtime, not raw remember()), measured against Hindsight on the same 22 questions. If consolidation closes even half the gap, the free answer stops being a compromise.
  • Standing rule from this exercise: never let a synthetic fixture read like an operational statement. Fixtures now carry an inline SYNTHETIC label.
