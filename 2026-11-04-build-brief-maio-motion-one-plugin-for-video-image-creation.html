Build Brief — maio-motion: one plugin for video + image creation across all four harnesses

Give this file to the builder. Everything in "Verified today" was measured on this Mac on 2026-11-04 — the builder must not re-derive it, re-install it, or "improve" it. The job is to wrap what exists into one installable plugin that Hermes, Claude Code, omp and dsh all pick up.

The one-paragraph ask

Build a single installable plugin — working name maio-motion — that gives every harness on this Mac one consistent way to (a) create video from code, (b) create and process images, (c) post-process footage, and (d) machine-check the result before it is shown to anyone. It must install from one repo into four harnesses whose plugin systems differ, sharing one skill set and one set of command wrappers so the same brief produces the same output regardless of which agent runs it. Zero recurring cost, no hosted service required, no paid API, no secrets in the repo.

Non-negotiables

  1. Free and local. No paid API, no stock library, no render farm, no hosted video model. If a feature needs one, it ships as an optional adapter and Ricardo decides whether to enable it — the builder does not.
  2. No new MCP servers. The plugin's capability must come from local binaries and skills. Blender-MCP, ComfyUI-MCP and friends stay out unless Ricardo explicitly approves one.
  3. No credentials in the repo, ever — no keys, tokens or passwords in code, manifests, examples or tests.
  4. Do not touch the vault. Vault writes go through Beast via the existing handoff; the plugin is read-only toward ~/Library/Mobile Documents/iCloud~md~obsidian/Documents/Maio Hub.
  5. Do not shadow ffmpeg. The stock ffmpeg stays first-class for ordinary work; the full build is a separate name.

The image lane — read this before promising image generation

Today the machine can process images but cannot generate them. No ComfyUI, no diffusers, no image model in Ollama, no imagegen binary — verified 2026-11-04.

Ships in v1 (all local, all free):

  • background removal / matting (rembg, bria-rmbg-2.0)
  • upscale ×2/×3/×4 (Real-ESRGAN x4plus, plus spandrel 0.4.2 for ESRGAN-family checkpoints on torch 2.15 MPS)
  • composition, colour and contact sheets (Pillow + opencv)
  • stills from any video at frame accuracy (ffmpeg)
  • HTML/Canvas/SVG → PNG (headless Chrome via puppeteer, already verified)

Ships as a disabled adapter, Ricardo's call: image generation. Two honest options — (a) ComfyUI locally, stills only (Apple-MPS video is not production-viable), or (b) an API the user already holds. The adapter must be inert until a human enables it, and must never ship a key.

Per-harness install mechanics (formats read off this Mac, not guessed)

Claude Code — .claude-plugin/plugin.json inside the plugin dir:

{ "name": "maio-motion", "version": "1.0.0", "description": "…",
  "author": { "name": "Adrianna A" }, "keywords": ["video","image","render","ffmpeg","hyperframes"] }

Install target ~/.claude/skills/ for the skills, and a marketplace entry so claude plugin install works.

omp — reads the shared cross-harness store ~/.agents/skills/ and consumes Claude plugin marketplaces listed in ~/.omp/marketplaces.json. It does not read ~/.claude/skills. Install = copy/symlink skills into ~/.agents/skills/, and verify with:

omp skill list . --json     # each record's filePath names the root it resolved from

Hermes — plugin.yaml with manifest_version: 2, provides_tools, provides_hooks, python_dependencies, config_schema, plus a skills/ directory and optional .hermes-catalog.json. Install target ~/.hermes/plugins/maio-motion/. Note Hermes skills are per profile — the plugin should install into every profile that needs it, or expose one tool that any profile can call.

dsh — has no skill system at all. Its adapter is an npm package with "dsh": { "profile": { "bundles": [...] } } in package.json plus loader entries in cordis.patch.yml (- id: <name>, name: "@deepseek-ai/dsh-…", config: {...}). If dsh cannot load skills, the honest minimum is a motion tool plus a one-paragraph cheatsheet injected into the profile patch — do not pretend dsh has skill parity it does not have.

The PATH rule — the bug this audit actually found

~/.local/bin is not on the PATH a GUI-launched harness receives. launchd hands apps only /usr/local/bin … /opt/homebrew/bin. Proof: env -i /bin/bash -lc 'command -v scenedetect' → MISSING.

So every wrapper must be reachable from both:

  • ~/.local/bin/ (terminal shells)
  • /opt/homebrew/bin/ (GUI-launched Hermes desktop, omp, dsh, T3 Code) — user-writable, no sudo

And each wrapper must pin its own PATH, because a GUI-launched process cannot be trusted to supply one:

export PATH="/opt/homebrew/bin:/opt/homebrew/sbin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin:${PATH:-}"

render-qc already does this correctly — copy its pattern. Verify any new wrapper under env -i HOME="$HOME" PATH="/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin:/opt/homebrew/bin".

Command surface the plugin must expose

One verb per job, stable names, --json on everything so agents parse instead of scraping:

Verb Does
motion new <dir> scaffold a project (HyperFrames or Remotion, chosen by flag)
motion render <project> render to MP4, then run the QC gate automatically
motion qc <file> the gate: frozen frames, loudness, black/torn frames, contact sheet
motion caption <media> local transcription → SRT/VTT + burn-in option
motion edit <media> the post lane: --cut --stabilise --grade --slowmo --upscale --stems
motion image <verb> matte, upscale, sheet, still, compose, svg2png
motion audio <verb> stems, beat, loudness, mix
motion doctor prints what is installed, what version, what is knowingly absent

motion doctor is the acceptance instrument: it must report the table above truthfully, including the deliberate absences, so no agent ever claims a capability the machine does not have.

Acceptance tests (the builder must show real output, not claims)

tests/acceptance.sh runs these and fails loudly. Each is a command, an expected shape of output, and a non-zero exit on mismatch:

  1. motion doctor --json lists every row of the verified table with a real version string.
  2. Scaffold → render → motion qc returns PASS on a 3-second piece with audio. (A video-only render must FAIL the gate — that is the gate working, and the test asserts the failure.)
  3. motion caption on a spoken sample returns at least one segment with words in it.
  4. motion edit --slowmo doubles the frame count and near-duplicate pairs stay under 5 % (proves interpolation, not frame doubling).
  5. motion edit --stabilise reduces measured inter-frame motion by at least 50 %.
  6. motion image upscale -s 4 returns exactly 4× the input dimensions.
  7. Every wrapper resolves and executes under the GUI environment (the env -i line above).
  8. omp skill list . --json shows all the plugin's skills; ls ~/.claude/skills shows them; a Hermes profile can load them.
  9. No secret-shaped string anywhere in the repo (gitleaks or equivalent).

Rollout and rollback

  • Install is additive only: new symlinks, new skill dirs, new manifests. Nothing is overwritten; existing ~/.local/bin and /opt/homebrew/bin entries are left alone.
  • Keep an uninstall path: one make uninstall that removes exactly the symlinks and skill dirs it created, recorded in an install manifest.
  • If a harness rejects the plugin, that harness must degrade to "tools available by name, no skill" — never to "tools missing".

Definition of done

Ricardo can open any of the four harnesses, say "make me a 30-second vertical clip about X with captions", and get back an MP4 that passes motion qc — with the same answer from all four, and no new spend.
