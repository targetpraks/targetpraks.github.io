Herdr CLI → herdr-app: what actually migrated

Source of truth: ~/.config/herdr/config.toml (herdr 0.9.5, 333 bytes, 3 TOML tables). Target: ~/.config/herdr-app/settings.json + keys.json (herdr-app 0.1.13).

The headline

The source config has no [keys] table. Its tables are exactly [ui.toast], [ui], [theme]. So there were zero custom keybinds to migrate — every Herdr CLI key was running on defaults. What did exist were four settings, and only one of them has a real equivalent in the app.

Setting-by-setting

~/.config/herdr/config.toml herdr-app Result
theme.name = "terminal" + theme.auto_switch = false "theme": "graphite" Migrated. CLI "terminal" = colour from the terminal itself, with no automatic light/dark flipping. The app's nearest equivalent is one fixed theme: a lone name in settings.json does not follow the system appearance, which is what auto_switch = false meant. graphite is the app's neutral dark chrome — the closest thing to "the terminal owns the colours". One-word swap if you prefer a real palette: atom-one-dark (shipped themes/atom-one-dark.json), or ink / moss.
[ui.toast] delivery = "herdr" (toasts drawn by Herdr, not the OS) built in, no setting Already the behaviour. The app posts its own toast on done / blocked when you aren't looking at that terminal, and never hands it to Notification Centre. There is no delivery key to carry over, and sounds.enabled was already true.
[ui] status_indicators = "symbols" built in, no setting Already the behaviour. Agent rows show symbol states (blocked > done > working > idle) with no textual mode switch exposed.
onboarding = false not applicable Dropped. The app tracks its own first run; the welcome overlay is currently open (overlays: ["frame-welcome"]).

Unrelated to the TOML, settings.json already carried zoom: 1.2, font_ligatures: false, minimum_contrast: 1.0 — left untouched.

Keybinds — why nothing moved

  • herdr config reset-keys exists precisely to strip custom bindings; nothing in the file suggests it ran, and the file simply has no [keys].
  • The app has no prefix/chord mode. keys.json binds single keystrokes per section (global, terminal, layout:<name>, mod:<name>), so a ctrl-b-style prefix map cannot be expressed even in principle. The CLI's navigation actions all exist as cmd-based bindings in the shipped app keymap, which is untouched:
Action herdr-app key Action herdr-app key
new tab cmd-t split right cmd-d
close tab cmd-w split down cmd-shift-d
next / prev tab ctrl-tab / ctrl-shift-tab close pane cmd-shift-w
new space cmd-n zoom pane cmd-shift-enter
next / prev space cmd-alt-] / cmd-alt-[ move pane focus cmd-alt-arrows
next / prev agent cmd-] / cmd-[ swap panes cmd-alt-shift-arrows
switch layout cmd-shift-l tab select 1–9 cmd-1 … cmd-9
command palette cmd-shift-p space select 1–9 ctrl-1 … ctrl-9
terminal search cmd-f settings cmd-,

If a CLI binding you actually use is missing, name it and it gets bound — with the caveat from the guide that plain ctrl+letters belong to the terminal program (ctrl+c, ctrl+d, ctrl+l, ctrl+r, ctrl+w, ctrl+a, ctrl+e, ctrl+u, ctrl+k, ctrl+z, ctrl+[) and shouldn't be taken without a decision.
