02 The retitle: ZOR → COR

Codes used throughout: ZOR/FND = franchisor / franchise-network development · COR = corporate, end-user marketing · TLF = The Local Farmer · KPD = King Protea Designs (the template this document was copied from).

The title says franchisor. The content is end-user marketing for a microgreens brand. The lane that matches the content is the corporate one, and it already exists.

Why COR is the right tier

  • The Company Snapshot describes an urban microgreens farm selling to restaurants, wholesalers and consumers: “precision hydroponic growing”, head office Bedfordview, primary target market “restaurants”. That is end-user marketing, which is what COR means in this space.
  • ZOR/FND is franchise-network development — the franchisor selling and supporting franchisees. The document’s core product line mentions a farming franchise, but there is no franchisee recruitment, territory or fee content anywhere in its 56 pages. The one franchisor-flavoured artefact, “Franchise Overview Sheet”, is a single row of a generic 40-row collateral template.
  • The space already holds MKT ZOR/FND - TLF (1501000000001192) and MKT COR - TLF (1501000000001208). Both lanes are fully built — 19 lists each, same seven pillars — so a misfiled document would load without a single error. The tier has to be decided on content, not on whether a list happens to exist.
  • The space conventions record the rule directly: “a doc titled ZOR: for end-user marketing should read COR:”, with two documents already retitled for this reason. The Papa Pasta sibling document was retitled on the same grounds.

Upstream decision. The fleet mapping PRD Brand docs mapped to ClickUp lanes: the ZOR/FND rename and COR (AI-Space/3.PRD/2026-11-21-brand-docs-mapped-to-clickup-lanes-zor-fnd-rename-and-cor.md) records the same line — ZOR: INF MKT: The Local Farmer → COR: INF MKT: The Local Farmer, lane MKT COR - TLF — and marks the doc “loads”. This is the section-level PRD that executes it.

Do not merge two documents. A second, different TLF document exists: FND-INF-MKT-The-Local-Farmer (superhuman://docs/dbzClTIy8Yb). That one is a shell and stays in MKT ZOR/FND - TLF. Same brand, different tier, different document.

What changes: the document title only. The doc URI superhuman://docs/sAAUHZZB7r and the web URL stay the same, so links, embeds and the Quick Links table keep working. Nothing in ClickUp changes as a result of the retitle — the target lane is already COR.

What “creates nothing” means, precisely

  • 0 folders, 0 lists, 0 custom fields. The lane’s 19 lists and the space’s custom fields already cover every section above; the field values the load needs (Brand, Engagement Tier, Function, Objective, Work Format) exist.
  • No moves. Nothing in the lane is re-pointed; where a doc block already has a home the payload links to it.
  • No deletions in ClickUp. The 25 KPD keyword rows are retired inside the document, not deleted from a list, because they were never in one.
  • One writer at a time. ClickUp cannot move a task between lists (PUT /task/{id} with a new list id returns 200 and moves nothing), so a mis-filed item can only be re-created. That is why every phase names its list id before it starts.
  • No due dates on create. A space automation rewrites due_date to the following Monday within seconds; dates are written in a second pass, and undated items are left undated.
