Two faults the scripts are built around, both of which look like "sshd is down" from outside:

  1. /run/sshd missing after a reboot. /run is a tmpfs; if the unit does not recreate the directory, sshd refuses to start with Missing privilege separation directory and the host sits there healthy with no SSH at all. --apply recreates it.
  2. Enabled ≠ running, and running ≠ enabled. The Ubuntu VM above had active: active with enabled: disabled — perfect today, gone at the next reboot. --apply fixes the enable, which is what stops this card coming back in a month.

  if ! $SUDO /usr/sbin/sshd -t; then echo "STOP: sshd config is broken, nothing started"; exit 1; fi
  if [ "$(ps -p 1 -o comm=)" = systemd ]; then
    $SUDO systemctl enable --now ssh 2>/dev/null || $SUDO systemctl enable --now sshd
    $SUDO systemctl restart ssh 2>/dev/null || $SUDO systemctl restart sshd

fi
