Known gaps

  • Authentication is OFF by owner decision; any change remains pending the owner decision. With auth disabled, the no-auth host list does not supply protection. When auth is enabled and an owner is registered, loopback may still bypass it unless security.allow_no_auth_hosts=[] is deliberately configured. Test unauthenticated rejection and authenticated success. The app persists password hash, salt and JWT material in its secret store; “Keychain only” was an incorrect v1 promise.
  • Autostart is live: the loaded job runs as PID 97340. Its conditional KeepAlive does not prove recovery on clean exit; crash/clean-exit recovery and confirmation after the next login remain outstanding.
  • Memory is PASS: ingestion into MEMORY.md, exact fresh-chat recall and exact recall of BLUE-HERON-42 after the transition from PID 81527 to new launchd-owned PID 97340 all passed.
  • Backup is PASS, with a caveat: agents must be an explicit list. The initial "green but empty" archive (agent_count: 0, 565 KB / 209 files, no workspace) was corrected with "agents":["default"] (agent_count: 1, 1,207,007 bytes / 466 files, workspace and config included). Secrets were excluded by design (include_secrets: false); isolated application restore remains NOT DONE.
  • Console UI hides reasoning when show_thinking=false, verified by a screenshot of the open conversation showing only "ALIVE"; reasoning still appears as text deltas in the raw SSE stream. This is expected, not a defect, and matters only to API consumers.
  • No external channel is enabled or tested. This is unfinished scope until Ricardo explicitly defers it or a real round trip passes.
  • GUI proof covers English rendering, version, model label and Smart Mode, plus the supplied screenshot showing only ALIVE with reasoning hidden. Other settings rows, the thinking toggle itself, disabled QA selector behavior and the workspace-file reply have no fresh GUI proof.
  • The daily cron has manual-success evidence only. Its old recorded next_run_at was 2026-11-10T09:00:00+02:00; it is not asserted to still be in the future.
  • Stage 1 init reported a CRITICAL scanner finding for make-skill, safe=false, while blocking was disabled. It was not resolved. Inventory is not a security review of all enabled skills.

Risks

An unauthenticated local API capable of tools is an unresolved access risk; loopback limits network exposure but does not authenticate local callers. Smart Mode and enabled guard settings have not been tested as enforcement boundaries.

The free router can change downstream models, throttle or fail. The bounded successful samples do not establish reliability. The live conditional KeepAlive can recover qualifying process exits; it cannot detect hung turns. Broader recovery checks and alerting remain unfinished.

Memory continuity across a process restart is proven; isolated application restore remains unproven. Ingestion, fresh-session retrieval, restart recall and the current application backup have passed; secrets were excluded by design. Unbounded launchd streams and unverified memory/index retention can grow the disk footprint. Sleep, missed schedules, locked-session tools and credentials remain operational unknowns.

Chinese vendor files remain on disk in the disabled QA workspace. API available_in_chat=true leaves its selector presentation ambiguous. Do not equate disabled runtime status with hidden or deleted content.
