Three chat surfaces, one machine, one honest answer

T3 Code Nightly, Discord and Buzz were measured on the same Mac: installed builds, real voice-to-text timings, live agent wiring and actual message volume. No product marketing, no remembered opinions.

Verdict

No single app wins all four criteria. T3 Code wins depth and presentation; Discord wins mobile reach and is the only one whose voice notes already reach your agent today; Buzz has the richest voice stack but is a one-day-old preview with zero audio ever sent. The utility answer is a two-lane system: T3 Code as the cockpit, Discord as the voice front door — both point at the same Hermes fleet, so nothing is duplicated.

1 · Mobile app availability and performance

All three ship a phone app. Only two are shipping, not previewing.

T3 Code's phone app is a near-complete remote for the desktop; Discord's is a decade-mature client; Buzz's is a TestFlight beta with no Android build.

T3 Code
Best parity iOS T3 Code - Remote, Claude & more v2.2.0, 4.9★ / 178 ratings, 130.6 MB, iOS 18+; Android com.t3tools.t3code, 10K+ installs, updated 28 Oct 2026. Store copy: "pretty much the full power of the desktop app" — runs, diffs, PRs, terminal. Pairs by code over LAN, T3 Connect tunnel, or Tailscale. Not paired on this Mac yet — ~/.t3/pair holds only a 22 Oct bookmark.
Discord
Most reliable Native iOS + Android, no beta gate, no pairing step, no tunnel to maintain. The agent is simply already there: gateway log shows [Discord] Connected as Adrianna AI#2851 plus batman and splinter profiles. Nothing to install on the phone beyond the app he already has.
Buzz
Preview only App Store v0.21, 4.2★ / 60 ratings, 67.4 MB, iPhone only; the shipping mobile path is public TestFlight testflight.apple.com/join/ubPnpGUz. No Android build exists. Pairing needs Tailscale on the phone and a desktop QR + six-digit confirmation, and the relay's own setup note calls this "Preview-grade … mobile in preview".

2 · Voice notes

This is where the three genuinely separate — and where T3 Code is empty.

Measured local speech-to-text on this Mac; all three clients inspected for a recording path, not just an audio player.

T3 Code
None A full scan of the 465 MB bundle returns no voice-recording or transcription strings — every "voice" hit is a MIME table or a CSS property. 2.2.0 added "play audio inline", which is playback. Voice input means the OS keyboard mic (iOS/macOS dictation) typing into the composer: usable, but no audio file, no transcript echo, nothing for the agent to re-read.
Discord
Works today Recording is native and mobile-only by design (Discord's own docs: voice messages "can only be sent through the mobile app"), up to 20 minutes, playable anywhere. Hermes catches it automatically: _event_media_is_stt_input routes MessageType.VOICE or any audio/* attachment into STT, transcribes, and echoes the transcript — with stt.enabled: true, local provider superwhisper. Replies can go back as native voice bubbles (_VOICE_EXTS = .ogg/.opus).
Buzz
Deepest, unproven Real native stack: src/commands/media_voice_note.rs, on-device STT via sherpa-onnx (Cohere Transcribe, Whisper, FireRedASR, Moonshine), formats wav/m4a/mp3/ogg/oga, input-size cap, agent text-to-speech with Pocket voices, and voice huddles with transcription. But the relay has 0 audio attachments of 89 messages — the path has never been exercised here.

3 · Information representation and looks

T3 Code
Purpose-built Diffs, PR summaries with live checks, file viewer, terminal, per-thread model and usage. A result is a rendered object, not a paragraph — and the phone app mirrors it (release notes: "on iPad, open threads and devices in a resizable inspector"). 335 threads and 6,047 messages live in statev2.sqlite (1.8 GB): this is the surface actually carrying the work.
Discord
Chat-shaped ceiling MAX_MESSAGE_LENGTH = 2000 with a 1900-char split threshold in the adapter — long answers arrive as a burst of chunks, with flood limits acknowledged in the code. No diff view, no file tree, no terminal. Pretty for conversation, wrong for output; the answer is to link out to an artifact.
Buzz
Best-looking room Channels, threads, rich media with pinned frame comments, canvases, per-agent identity and audit trail. It reads like a designed workspace rather than a chat app — but its agents here run the buzz-agent harness on mimo-v2.6-flash:cloud, a thinner brain than the Hermes agent behind the other two.

4 · Recommendation

Run two lanes, not three apps.

T3 Code for depth and the pretty surface, desktop and phone. Discord for the voice memo you record walking to the car. Buzz stays installed as a lab, not a driver.

Already true — no work needed
1
T3 Code is the work surface: 335 threads, full tool set, phone app rated 4.9 with near-desktop parity.
2
Discord is connected to the same fleet (Adrianna, Bruce Wayne, Splinter) with local STT at ~20× realtime and transcript echo.
3
Nothing sensitive goes in Buzz: no end-to-end encryption on that relay, per its own setup note.
Three steps to finish the setup
1
Pair the phone to T3 Code: Settings → network access → Pair devices, then scan with the iOS app (or paste the pairing code). Tailscale already covers the away-from-home case.
2
Use one Discord channel as the voice inbox: record there, let STT answer, and ask for the artifact link rather than the essay — that sidesteps the 2000-char ceiling.
3
Re-test Buzz voice in a fortnight: if the relay logs its first audio attachment and the mobile beta lands, it becomes the single-app candidate — it is the only one whose voice stack is native end-to-end.
What I did not test, so I am not claiming it. No voice note was sent through Discord or Buzz during this review — the Discord result comes from the adapter code path plus the measured STT pipeline, not from a live memo. The T3 phone app was verified from its store listing and pairing machinery, not from a paired device. Buzz voice notes were verified from the shipped binary, since the relay holds zero audio events.
