The engine question.

Hermes wins as the core — not as the best coder. There is no single runtime that takes all four jobs you give an engine, so the honest answer is a routing rule rather than a champion. Below: the nine dimensions, four sets of weights, and what happens when the weights change.

The one-line claim Memory, schedule, delivery and a chat surface, in one process, under an MIT licence — only one of the seven does all four. That is the job the word "engine" is doing.
7 engines compared every one installed here, and version-checked tonight
9 dimensions from model freedom to what it costs to keep alive
4 real jobs the fleet · a repo · a colleague · the night shift
3 / 4 for the same engine and it loses the fourth to a smaller tool

The claim, restated so it can be tested. Hermes is the right core because it is the only engine that closes the loop from memory to schedule to delivery to a chat surface. It is not the best patcher — Codex is calmer about it and omp is faster across parallel worktrees — and it is not the sharpest judge of a nasty diff; Claude Code is. If you only ever did one job, you would not pick Hermes. You do four.

Where each one loses

A comparison that only lists strengths is a brochure. These are the failure modes that would hurt you specifically.

Hermes Weight and drift. 246 skills and 35 profiles are power and a governance problem at once; an upgrade leaves a dashboard serving stale code, and it is the one engine that needs an operator who enjoys configuration.
OpenClaw Breadth before depth. It is a gateway first: a young agent runtime under a very wide channel list, host-level tools unless you configure sandboxing, and an install base fifty times yours means fifty times the attack surface and the issue volume.
Codex CLI No clock, no memory, no voice. Brilliant inside a repository and mute everywhere else — and it sees OpenAI models first, everyone else as a config exercise.
Claude Code One vendor, one bill, no memory. Superb judgement on a hard diff, closed source, and nothing survives the session except a CLAUDE.md you maintain yourself.
OpenCode Breadth without a spine. Any provider and a decent LSP story, but permissions are config you write, and nothing schedules, remembers or calls you.
omp Young and fast. Best-in-class fan-out and a real toolchain, but a 19.x line that moves weekly and no clock — it is a hand, not a heartbeat.
Antigravity Quota-shaped. Frontier reasoning without a per-token meter, until the quota resets; closed, opinionated, and not something you leave running for a company.
DSH A harness, not a platform. Cheap and DeepSeek-native, its plugin-stack model rewards tinkering and punishes anyone expecting a dashboard, memory or a phone.

What would change my mind

  • A head-to-head on the same three tasks: if omp's curated memory recalls the same facts as Hermes' graph across sessions, Hermes loses its main structural advantage and the core becomes a two-horse race.
  • If Codex ships a scheduler and a delivery surface, the split collapses: one vendor, one binary, sandbox included. That is the single most likely change in the next two quarters.
  • If a week of OpenClaw on this Mac shows a memory and an agent runtime as good as its channel list, the core moves and this page is wrong twice — once for claiming uniqueness, once for keeping Hermes on governance alone.
  • If AgenticOS sets per-user provider keys and a spend cap, "engine for staff" stops being a gap and becomes a solved row — and none of these seven is the answer for it.
  • If Hermes keeps breaking on upgrade — the dashboard is still serving pre-update code as this is written — then operability turns from a 3 into a 1 and the core candidate becomes something you can leave alone.

Method, and what this is not

The scores are mine; the facts underneath them are not. Every version was read from the binary that sits on this Mac tonight, every star count from the GitHub API, every install number from the registry that distributes it. Where a product is closed source — Claude Code, Antigravity — there is no repository to count, so the row says so rather than inventing a figure. OpenClaw was scored from its documentation, not from running it: its channels, cron and delivery are documented in detail, its memory depth is not, and that uncertainty sits inside the 4 it was given.

This is not a model benchmark. Two of these engines can run the same model, and the differences measured here are about what surrounds the model: whether it remembers, whether it wakes on its own, whether it can reach you, whether it will stop when a file looks dangerous. A coding bake-off on identical tasks is the next experiment, not this page.

Nothing was installed, upgraded or reconfigured for this comparison; no money was spent and no live system was touched. The companion page — Hermes vs OpenBot vs AgenticOS — covers the two layers that are not engines, and why they are not in this race.
