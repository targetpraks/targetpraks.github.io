One real finding: a plugin version skew

On boot dsh disables the profile plugin row orca-agent-hooks:

@deepseek-ai/dsh-hooks-claude-code@0.2.1-rc.5 is incompatible with dsh 0.2.2-rc.1 — it requires the whole 0.2.1-rc.5 family (dsh-agent, dsh-llm, dsh-session, dsh-tools, …, all pinned to 0.2.1-rc.5). Running it may cause crashes or data loss.

So dsh runs, but without the Claude-Code hook layer. It needs the plugin family moved to 0.2.2-rc.1 (or that one row pinned back to a matching runtime). The exact-version exemption is not active — deliberately, and correctly.

Proposal (Ricardo decides): upgrade the dsh-hooks-claude-code plugin to a release built for 0.2.2-rc.1, then re-run dsh headless "Reply with exactly: OK" and confirm the plugin row is no longer disabled. Do not use dsh plugin allow-version to silence it — that is the crash-risk path the message is warning about.
