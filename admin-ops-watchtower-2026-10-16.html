How the norm is measured, not invented

There is no honest global hour limit — an eight-hour film cut and an eight-hour data capture are not comparable work. So the norm is measured per peer group: same Function, same role, completed work only, trailing 90 days. A task is flagged when it sits above four times the median of its own peer group, and only where the group has at least twelve peers. Where a group is too thin to judge, the report says insufficient sample rather than inventing a threshold.

On today's snapshot 222 tasks sit above their Function's own median. Many peer groups are still below twelve members, so the phantom-hours list above — which needs no threshold at all — is the finding to act on this week, and the peer norm tightens as the sample grows.

TeamInbox: all attended, nobody parked

Designed in full, and waiting on one credential from the Zoho account. The moment it exists, these are the numbers the admin team will be judged on — every week, per person and per department.

What is measuredHow it is counted, in plain words
AttendedA customer thread that got a human reply, or was closed with a reason. A reply always wins.
Replied rateThreads a human answered, out of all threads a customer opened that day.
Self-assigned, never answeredSomeone assigned the thread to themselves and no human reply followed within three working days. This is the "just assigning themselves" detector.
First response timeFrom the customer's first unanswered message to the first human reply. Working hours only, so nobody is marked slow for mail that arrived at 22:40.
ReopenedClosed and reopened within seven days. It never resets the thread's age — reopening is a mark on the closer, not a way to look fresh.
Aged openOpen with no human action for more than three working days.
The one line that makes the score unhackable: assigning a thread to yourself earns zero credit, ever. Only a human reply or a reasoned close counts. There is no path by which parking a thread on your own name improves any number on the page — which is exactly the behaviour you asked to catch.

What is needed to switch it on

  • Admin-granted API access to TeamInbox on the Zoho account, with read scope on threads, messages and assignments.
  • The department list and who each department's inbox belongs to — the agent allowlist, so a robot is never counted as a reply.
  • The mailbox-to-department map signed off by you, because names attached to a wrong department are the one error that makes people stop trusting the report.

Until then, every TeamInbox line in every report and message reads not measured — no TeamInbox lane provisioned. It will never show a zero, because a zero would read as "nothing to see here" and that would be a lie.

Guardrails already built into the sender

  • Nothing sends twice. Every message carries a fingerprint built from the item, the person and the period; a re-run produces zero new messages.
  • Dry run is the default. The scheduled job writes previews to a folder. Live sending needs an explicit switch.
  • Assignment earns nothing. Parking a thread on yourself cannot improve a single score.
  • Fair clocks. Working hours only, Monday to Friday, eight to five, South African public holidays excluded — so nobody is marked late for a weekend.
  • No secrets, ever, in a message. No codes, no links with credentials, no ID numbers.
