2 · Where a harness lied to itself

HarnessModelit saidtruthmy verifier found
ompglm-5.3PASSFAILFAIL [('Über', 'ber', 'uber'), ('Ärger über Öl', 'rger-uber-l', 'arger-uber-ol')]

omp's own test suite passed — it wrote weaker tests than the spec asked for. On Über it returned ber and on Ärger über Öl it returned rger-uber-l: it strips non-ASCII before lowercasing instead of transliterating the uppercase forms. The same model, driven by Hermes, handled both correctly. That is a harness-plus-model interaction a model leaderboard cannot show you.

Latency is a harness property

Hold the model fixed and the harness still moves wall time by 3.7–4.4×: deepseek ran in 10 s under OpenCode and 38 s under omp; glm in 13 s under Hermes and 56 s under omp. Model choice within Hermes barely moved the clock (12.8–14.1 s across three models).

If a delegated task feels slow, the harness is the first suspect, not the model.

Correctness on this task was near-flat

All four harnesses produced working code on deepseek, and three of four did on glm. This task is small enough that model capability barely binds — which is exactly why the one failure is informative: it came from a harness/model pair mishandling uppercase transliteration, not from the model being weak in general.

Combine with §2 of the model matrix: reasoning quality separates models, execution mechanics separate harnesses.

4 · What each harness cost me in setup

HarnessBehaviour that would break an automation
OpenCode 2.3.2Resolves its working directory from $PWD, not the process cwd. Driven via subprocess(cwd=…) it wrote files into my home directory for three runs. Setting env["PWD"] fixed it. Also caches a project root per path — reuse a directory name and it keeps the old root.
omp 19.1.1Model ids are provider-prefixed and drop the :cloud suffix (ollama-cloud/glm-5.3, not ollama-cloud/glm-5.3:cloud); a wrong id fails in 0.3 s. Slowest of the four by a wide margin.
DeepSeek harness 0.2.2No --model flag anywhere: the model is pinned in the profile patch, so a model sweep needs one copied profile per model (I built mini-glm and had to add glm-5.3 to its declared model list or the profile silently had no such id).
Hermes 0.23.3Nothing. It was the only harness that needed no correction to run identically from a shell and from a subprocess.
Method: each run got a fresh directory and git init; the prompt was byte-identical; verification is a ten-case script written before the runs, importing slug.py from the run directory. Three harnesses ran three models, dsh two (profile-pinned). Wall time is the harness process end to end, including its own test execution. Where an invocation needed correcting, the correction is listed in section 4 rather than hidden — the first opencode and omp attempts failed on my invocation, not on their capability.
