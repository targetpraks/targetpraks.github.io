Five things only a person in the browser can finish

These are not build gaps — they are the only remaining items, and each is a click, not a project.

  • Turn on the Custom Fields ClickApp — workspace settings, ClickApps, Custom Fields. Without it the field set, and therefore SLA and reporting, cannot exist.
  • Re-case the statuses if the lower-case names bother you; behaviour is unaffected.
  • Build the first automation — one per Space is enough to prove the pattern: on status change to blocked, notify the Space's channel.
  • Delete the four leftovers I could not remove by API: two probe statuses on BND2 › BND2 Briefed-In, one empty doc, and the six pre-build channels (announcements, leadership, marketing-creative, finance, people, technology) which the API cannot rename.
  • Invite the team — the workspace has one member, so no permissions, no guest access and no cross-space sharing can be exercised yet.

When the plan is upgraded, nothing is rebuilt

The structure was built to hold the full model: every department already owns its folder and lists, the SLA lists already exist under Finance with their own status sets, and the reporting Space already carries weekly, monthly, quarterly, meeting-notes and knowledge folders. An upgrade fills them in — custom fields on the existing lists, automations on the existing statuses, dashboards over the existing views. No object built this week has to be thrown away.

Order I would do it in: custom fields first (everything else depends on them), then the SLA clock on the four Finance SLA lists, then one automation per Space, then the reporting dashboards. Each stage is independent of the next.
