The one-sentence version The hub is installed, supervised, backed up and on the LAN; it cannot see a single device because one macOS privacy toggle is still off, and it cannot reach Apple or Google until that same gap is closed and a public endpoint decision is made.

Decision

Finish the two links that make the system worth having, and stop adding plumbing until they work.

Concretely: clear the macOS Local Network gate so Home Assistant can reach the house, pair Apple Home to the HomeKit bridge that already exists and is advertising-ready, pick one route for Google Home — a Nabu Casa subscription or a public hostname of our own — and only then widen device coverage (the Sonos S1 speaker, the Midea aircons, the RTSP camera). The hub is installed, supervised, backed up and reachable on the LAN; what is missing is permission, pairing and purpose.

Summary

Home Assistant runs natively on the Mac mini under launchd, holds 68 entities across 16 integrations, takes a verified daily backup and answers on the local network. Yet 45 of those 68 entities are unavailable, the HomeKit bridge exposes nothing, and no Google Home link exists at all.

Every one of those three symptoms traces to one of two causes: a macOS privacy grant that was never given, or a missing public HTTPS endpoint. Neither is a code problem. Both need Ricardo. This PRD sets out seven workstreams in the order that produces a working system fastest, with acceptance written as commands so “done” is provable.

Problem

The house has real devices and no automation engine in the loop:

  • Nothing can be controlled from Home Assistant right now. All five Sonos renderers, both Cast players, all four Android TVs and the Brother printer report unavailable with supported_features=0.
  • Apple Home cannot see the hub. The HomeKit bridge entry exists on port 21063 with a filter, but with zero valid accessories it never advertises _hap._tcp.
  • Google Home has no path to Home Assistant. The Google Assistant integration is not configured, and the manual route needs an externally reachable HTTPS URL this Mac does not have.
  • There is no automation. automations.yaml is [], scripts and scenes are empty, and the only dashboard is the default Overview. The house is instrumented, not automated.

Proposal — seven workstreams

WS1 · Clear the LAN gate blocks everything

Grant local-network access, then prove it from Home Assistant's own process rather than from a shell.

Acceptance: every Sonos, Cast and Android-TV entity reports a real state with supported_features > 0; the Brother ink sensors report levels.

WS2 · Apple Home pairing

The bridge already carries a tight filter — media_player, climate, light, cover, lock, camera — and excludes the off-network Kitchen Play:1. Once WS1 lands, reload HomeKit, read the live pairing code from the persistent notification, and pair.

Acceptance: dns-sd -B _hap._tcp local shows Maio Home <setup-id>; the iPhone shows the rooms; changing volume from the Home app changes media_player state in HA.

Watch-out: the PIN regenerates whenever the bridge restarts — read it at pairing time, never from an earlier message.

WS3 · Google Home — one decision, then a fixed runbook

Google's cloud must reach HA over HTTPS. The free shortcuts are gone: Tailscale Funnel allows only 443 / 8443 / 10000 and all three are occupied (8443 proxies an office tunnel to macserver), there is no Cloudflare zone, and cloudflared is not installed.

Acceptance: the Google Home app lists the house's HA entities; a voice command changes a media_player state that HA logs.

WS5 · Make it an automation engine, not a dashboard

The point of HA is behaviour: things that react. Today there are zero automations. First three once WS1 is green: (1) all speakers off at 23:00, (2) TV volume down when the bedroom speaker plays, (3) a printer-ink alert to the phone.

Acceptance criteria

# WS1 — permission granted
curl -s -H "Authorization: Bearer $HA_TOKEN" http://127.0.0.1:8123/api/states \
  | python3 -c 'import sys,json; s=json.load(sys.stdin); print(sum(1 for e in s if e["state"]=="unavailable"), "unavailable")'

# WS2 — bridge advertising
timeout 8 dns-sd -B _hap._tcp local | grep -c "Maio Home"

# WS3 — public endpoint answers (after the link)
curl -s -o /dev/null -w '%{http_code}\n' https://<public-host>/api/

# WS6 — backup integrity
/bin/zsh ~/.config/maio-stack/home-assistant/backup.sh --ship | tail -1

Risks

  • Router, NAS and Ajax firmware are out of scope for me. Flashing those can drop the network or brick hardware; each needs Ricardo's explicit go, one device at a time.
  • One toggle unlocks 45 entities at once. If the grant lands while an automation is half-written, expect surprise behaviour — write automations after WS1 is verified.
  • Nabu Casa creates a recurring charge. Nothing is started until Ricardo says so.
