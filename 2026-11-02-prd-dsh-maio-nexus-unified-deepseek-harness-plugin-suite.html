PRD: dsh-maio-nexus — Unified DeepSeek Harness Plugin Suite + Ecosystem Adoption + Code-Video Lane

Targets: Web profile (dsh web) and official DSH Desktop app · Base integration: Hermes memory + Beast / OpenKnowledge vault (AI-Space) · Model path: local Ollama gateway :11434/v1 · Rendered-video lane: 12 verified code-video repos · Staged by Adrianna A, reviewed and manually installed by Ricardo.

Executive summary. Three deliberate workstreams, one plan. (A) Build a custom suite — dsh-maio-nexus — that gives DSH shared memory with Hermes and read-only recall over the Maio Hub vault. (B) Adopt a curated, verified subset of the community plugin ecosystem alongside it — each with an explicit adopt / evaluate / reject decision, a security review gate, and a manual install step owned by Ricardo. (C) Render video from code — HTML, React, 3D and FFmpeg — so a DSH session can turn a brief into an MP4 with no stock footage and no studio invoice. The three workstreams share one staging area, one security policy, and one install gate.

What changed in v3: adds Workstream C — the code-rendered video lane. Twelve repos were checked live on GitHub on 2026-11-02 (existence, stars, licence, last push) and the local Mac stack was checked for what is already installed versus what still has to be installed. Nothing was installed or executed for this version.

1. Vision & Problem

Problem. DeepSeek Harness sessions are isolated from the rest of Ricardo's Mac stack. A DSH session cannot see Hermes memory (user preferences, standing rules, cross-session facts), cannot query the Obsidian vault (Maio Hub) for PRDs, research or guidelines, and has no curated, risk-assessed path to the community plugin ecosystem — the dsh-plugin topic alone carries 25,115 tagged repos, many of them tag-squatters. It also cannot make a video: today video means a stock subscription or a studio quote, and the Mac already has the parts of a code-rendering pipeline that cost nothing.

Solution. dsh-maio-nexus registers Cordis plugin handlers that inject Hermes memory into DSH session context and expose a read-only vault_recall tool over AI-Space via Beast/OK. In parallel, the adoption workstream gives each community plugin an explicit decision and a reviewable install path — no blind installs, no third-party code run by me. The video workstream pins a short, verified, free stack that a DSH session can drive from a brief to a finished MP4.

Acceptance criteria. F5: a DSH session takes a one-line brief and produces a 1080×1920 MP4 of ≤ 30 s with no stock asset, no paid credit and no studio; a second run of the same brief renders the same output. F6: all text arrives through PNG cards, HTML/Remotion overlays or GSAP type — never through an FFmpeg drawtext filter. F7: every asset and every render stays on this Mac; the lane makes no outbound call to a stock, render-farm or model-hosted service unless Ricardo has approved that service separately.

Constraints. ComfyUI video on Apple MPS is not production-viable (images only) — the lane uses ComfyUI for stills, not motion. Renders are local and CPU/GPU-bound, so clips stay short. Licensing is checked per repo before any monetised use: Remotion carries its own company licence (NOASSERTION), GSAP its standard licence, remotion-dev/skills ships no licence file and is therefore reference material only, Blender is GPL and fine as a tool, ComfyUI is GPL-3.0. None of this is a spend decision; it is a licence reading, and legal stays with Ricardo.

5. Plugin governance policy (applies to A, B and C)

  • No blind installs. Every plugin — mine or third-party — is staged, its dsh.bundle / cordis.patch.yml read, its network calls and filesystem writes reviewed, and its license checked.
  • Ricardo installs. Adrianna A stages; Ricardo runs the install command or uses the Desktop settings after reviewing the manifest. I never install third-party code or change a live profile on my own.
  • Read-only vault. No plugin gets write access to Maio Hub. Beast remains the sole writer via OpenKnowledge.
  • No credentials. No key, token or password enters any plugin config, log or artifact — the credential hard stop applies unchanged.
  • Fail-closed. A plugin failure degrades to standard DSH behaviour and is logged; it never blocks the harness.
  • Revert path. Every install has a documented uninstall step and, where offered, a Safe Mode / isolated profile for first run.
  • Video lane too. A video repo is installable code, not a document: it enters through the same review gate, and a render never ships to a client channel without Ricardo's look first.

6. UX & UI design

The suite adds a settings panel under DSH Settings → Maio Nexus: connection status for Hermes memory and Beast/OK, vault scope selector (AI-Space default, read-only badge), recall latency and token telemetry, a list of adopted community plugins with version + install state, and a Video tab that reports which elements of the render lane are present (HyperFrames, Remotion, Blender, ComfyUI, FFmpeg, faster-whisper) with the last render path and duration. Third-party plugins keep their own settings pages — the panel only reports their status.

7. Non-functional requirements

  • Security: 100% local execution; no vault contents or credentials leave the machine; read-only vault access; no telemetry.
  • Performance: local FTS5 vault recall < 50 ms warm; memory injection adds no visible latency to session start; a ≤ 30 s code render completes unattended in one pass.
  • Reliability: fail-closed as above; nightly reindex idempotent; repeated renders of the same brief are reproducible.
  • Compatibility: DSH ≥ 0.2.x for both Web and Desktop; plugin API differences handled by capability detection, not version pinning alone; Node ≥ 20 for the render lane (this Mac runs v26.13.0).

8. Delivery plan

  • Phase 1 — Staging (Adrianna A). Build the dsh-maio-nexus bundle skeleton (manifest, TS glue, vault_recall tool, memory bridge) under ~/AI Hub/dsh-maio-nexus/; stage the adoption review notes for the Evaluate tier; stage the video lane as a skill folder with the twelve repos, one worked HyperFrames example and one worked Remotion example. No installs.
  • Phase 2 — Review (Ricardo). Manifest and code review; approve which Evaluate plugins graduate to Adopt; approve the first video install batch (HyperFrames + Remotion first — both Node-only, no root, no licence fee).
  • Phase 3 — Install (Ricardo). Manual install into the Web profile and the Desktop app; first run in Safe Mode where available. Video lane order: HyperFrames CLI → Remotion + remotion-dev/skills → faster-whisper (own venv) → Hallmark/Impeccable skills → Blender + Blender MCP only if 3D is actually needed.
  • Phase 4 — Verify (Adrianna A). Run the acceptance criteria F1–F7 against real output; report pass/fail with evidence; log to AI-Drive/Agent-Output/adrianna.
  • Phase 5 — Operate. Courage nightly reindex; monthly plugin review (new versions, CVEs, license changes); monthly re-verification of the video repo list (stars, licences, renamed repos — the Blender MCP entry already moved once).

Out of scope. Installing any plugin without Ricardo's sign-off; writing to the vault; sending any credential, ID or health data to any plugin, gate or sandbox; auto-merging upstream plugin code; replacing Hermes memory or Beast with a community store; paying for stock footage, render farms or hosted video models as part of this lane.
