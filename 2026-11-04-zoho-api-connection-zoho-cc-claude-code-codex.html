Zoho API connection — zoho-cc (Claude Code + Codex)

One separate Zoho connection, shared by both coding CLIs. It has its own OAuth grant and its own refresh token, so revoking it kills Claude and Codex access and leaves every Hermes agent, the 25 MCP shards and the fleet's zoho-all lane untouched.

Built 2026-11-04. Verified against live Zoho data, not assumed.

1. What "separate" means here

Layer This connection (zoho-cc) Fleet lane (untouched)
OAuth grant own grant, granted 2026-11-04 granted earlier
Refresh token ZOHO_CC_REFRESH_TOKEN ZOHO_ALL_REFRESH_TOKEN
Scopes own scope pack, 98 scopes 98 scopes
Revocation revoke this token alone revoke kills agents
Client ID / Secret shared shared
Entry point zoho-api MCP gateway zoho-p01…p25 MCP shards

Why the client ID is shared: Zoho permits exactly one Self Client per account, and the alternative — a new Server-based Application — means accepting fresh developer terms in the console. That acceptance is Ricardo's, not an agent's. A new client app can be added later on his word; the token, scopes and revocation would still be separate today.

2. Credentials

Stored in the one canonical 0600 store — /Users/ricardomaio/.config/maio-stack/secrets.env. No secret value appears in this document, in a ticket, or in a chat.

Key Role
ZOHO_CC_REFRESH_TOKEN the separate grant — read only by this connection
ZOHO_CLIENT_ID Self Client id (shared, suffix CANX)
ZOHO_CLIENT_SECRET Self Client secret (shared)
ZOHO_ACCOUNTS_HOST accounts.zoho.com

The access token is minted on demand and cached at ~/.cache/zoho-cc/token.json (0600, ~50 min TTL). It is never returned to the client — tools return data, never credentials.

3. The gateway

/Users/ricardomaio/.local/bin/zoho_api_mcp.py — stdio MCP server, stdlib only, no dependencies.

Four tools, instead of the thousands of per-product shard schemas:

Tool Purpose
zoho_call any Zoho REST endpoint — service + path (or absolute url), params, json_body, form_body, headers, save_to
zoho_services service → base URL map, scope count
zoho_connection which connection this is, token mints or not, TTL. Never returns secrets
zoho_scopes the 98 granted scopes, to separate "missing permission" from "wrong endpoint"

Service bases: crm, projects, projects_rest, workdrive, sheet, books, invoice, inventory, expense, mail, calendar, desk, people, analytics, tables, creator, cliq, writer, sign.

CLI checks:

python3 ~/.local/bin/zoho_api_mcp.py --check    # connection health, JSON
python3 ~/.local/bin/zoho_api_mcp.py --scopes   # granted scopes

4. Configuration — Claude Code

~/.claude.json, scope user (all projects):

{
  "mcpServers": {
    "zoho-api": {
      "type": "stdio",
      "command": "/usr/bin/python3",
      "args": ["/Users/ricardomaio/.local/bin/zoho_api_mcp.py"]
    }
  }
}

Added with the CLI, which is the only safe way — the Claude app rewrites ~/.claude.json and silently drops hand-edited entries:

claude mcp add zoho-api --scope user -- /usr/bin/python3 /Users/ricardomaio/.local/bin/zoho_api_mcp.py

Live status: claude mcp get zoho-api → Status: ✔ Connected.

7. Revoking just this connection

Console → api-console.zoho.com → Self Client → the token issued 2026-11-04 for "Claude Codex separate Zoho API connection" → revoke. Then, on this machine:

rm -f ~/.cache/zoho-cc/token.json
claude mcp remove zoho-api -s user
codex mcp remove zoho-api

Agents keep working — they never use this token.

8. Standing rules for the two tools using it

  • Writes to live business data (tickets, invoices, CRM records, mail) still need Ricardo's go. Read freely.
  • Never paste a Zoho secret, client secret or refresh token into a prompt, a ticket or a report.
  • ZohoCreator answers status 200 with code=3000 on a bare probe — that is a normal "no apps in context" reply, not an auth failure.
