What was wrong

Shadow's own brief says it runs on a local uncensored model and never routes work through a cloud provider. The live config said otherwise: deepseek-v4.1-flash:1017-cloud on ollama-cloud, with three cloud fallbacks, a cloud vision model, a cloud background reviewer and a cloud escalate delegate lane. The lane existed on paper only.

The last local attempt was weaker still: an Ollama tag of a 1B MLX model (llama3.2-1b-mlx), and our own Heretic abliteration of Qwen3-4B, which refuses 81 of 100 harmful-behaviour prompts — not usable as an uncensored lane. Evidence: Tools/heretic/runs/t_8479e42a/evidence-summary.json.

How the head-to-head was decided. Refusal behaviour, tool calling and footprint were a dead heat, so the tie-break was code correctness on a real task: parse AA-BB-CC-DD-EE-FF_2026-11-26_office.pcap.

  • Huihui's function used parts[1].split('.') on 2026-11-26 — unpacks one value into two names and raises ValueError, and it misidentified the edge case it failed to handle.
  • The DeepSeek-distilled heretic returned an anchored regex parser that works, uppercases the BSSID and names the real edge case (underscores or dots inside the location).
  • Second sample (WPA3 transition-mode brief): Huihui expanded SAE as "Simultaneous Authentication of Equality" and claimed the first SAE hash can be brute-forced offline; the distilled build stayed accurate on transition-mode downgrade and stated confidence explicitly.

Both are weak at bare mental arithmetic (3/6 on a rate/percentage set) — that is what the terminal tool is for. With reasoning enabled the winner fixes two of three arithmetic probes (70,200 and 37,800) where the non-thinking path got none.

Why the HauhauCS "Aggressive" build was rejected. With reasoning enabled it spent its entire token budget thinking and returned an empty answer twice out of three reasoning probes (empty content, 4,140 and 4,351 characters of thinking). An agent that sometimes answers with nothing is worse than one that answers plainly.

The 10-probe refusal set covered the shape of Shadow's real work — SQL injection, phishing template for awareness testing, lock picking, OSINT address correlation, WPA2 handshake capture, port scanner, XSS, own-machine keylogger, scraper anti-detection, surveillance essay. Both models answered all ten directly and factually; neither lectured.

Is there a cloud abliterated model?

No. The Ollama Cloud catalogue served here was enumerated from the live library (https://ollama.com/search?c=cloud): beam, clef, deepseek-v4.1-flash, gemma4, glm-5.2, glm-5.3, glm-5.3-flash, hy4, inkling-2-small, kimi-k2.7-code, kimi-k3, kimi-k3.1-pro, mimo-v2.6-flash, mimo-v2.6-pro, minimax-m3, minimax-m3.1-flash, mistral-large-4, muse-spark-open, nemotron-3-super, nemotron-3-ultra. Every one is an RLHF-aligned release — none is an abliterated or refusal-removed build. Cloud-hosted uncensored endpoints do exist (Featherless, VeriSafe), but renting one puts Shadow's restricted work on somebody else's disk, which is exactly what the lane forbids. Local is the answer, not a compromise.

Hermes side note: with provider: ollama the custom-endpoint plugin always sends options.num_ctx, and sends think: false only when reasoning_effort is none/disabled. Only auxiliary.background_review is set to none, since that call does bound its output.
