01How the access works

The office VLAN is not reachable from this Mac, and the bastion only forwards to the staging VM — not to the Mac mini. The working route is therefore end-to-end SSH through both hops, so the key stays on this machine and is never copied to the bastion:

ssh infmini          # ~/.ssh/config: ProxyJump bastion,macserver · User infmac · key id_ed25519

That alias now resolves to infmac@192.168.88.173; before today it pointed at a ricardomaio account that does not exist on the box. Five public keys are now authorised on ~/.ssh/authorized_keys (permissions 700 on the directory, 600 on the file, as asked).

One thing to note before it becomes a habit

Adrianna asked for read access; what was granted is an administrator account — a member of admin, with the SSH access group and screen-sharing access attached. Passwordless sudo is not enabled (a password is still required), so this is narrower than root, but it is wider than “read”. If we only need to inventory, a standard account would do the job with less blast radius.

Two of those deserve a sentence each. 9390 serves an index of whatever the browser agent has been doing — frames, step-by-step logs, shift reports — to anyone on the office network, with no login: amazon-split.html, steps.jsonl, shift-report.md, frames/. 9377 is the control endpoint for that same agent, also unauthenticated; it currently reports running:false, but an idle control port is still a control port.

On top of that, the application firewall is off, stealth mode is off, and the box accepts SSH passwords. The whole office VLAN can knock on all of the above.

04What I would do about it

  1. Bind the agent ports to localhost. 9377 and 9390 need to be reachable from the Mac mini, not from the VLAN. One listening-address change, no loss of function, closes the worst of it.
  2. Decide whether SMB, Screen Sharing and ARD belong on the general VLAN. If they are only for IT, restrict them to a management subnet or switch on the application firewall with an explicit allow-list.
  3. Turn the firewall on. It is currently disabled with stealth mode off, which is why every port above is visible to a scan.
  4. Turn off SSH password authentication and keep public keys only. It costs one line in sshd_config.d and removes the thing we were careful to avoid in chat.
  5. Check the Kerberos KDC on port 88. A single-user Mac mini serving Kerberos to the office is unusual; either it is a deliberate directory-service role, or something is enabled that nobody meant to enable.
  6. Treat the self-hosted Actions runner as code execution. It is registered to the InfinityBrandsOrg and runs as infmac — an admin account that can also reach the staging VM. Any workflow that lands on it runs with those rights.
