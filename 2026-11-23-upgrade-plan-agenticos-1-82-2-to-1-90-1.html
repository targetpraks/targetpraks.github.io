3. Pre-flight (blockers, in order)

  1. Backup + restore proof. The 02:15 dump exists; a restore has never been rehearsed and the migration is one-way. Rehearse the restore into a scratch database before touching production, or accept that rollback means losing everything since the dump.
  2. Disk. 15 GB free of 76 GB. Pulling a new image set needs roughly 2–3 GB on top of the current layers, plus migration growth. Clear old images first (docker image prune after a verified backup) — this is a host mutation for the lane, not a bot.
  3. Read the full changelog for 1.83–1.85, which this table only summarises from the published release bodies.

4. Staging run (Monday window, 04:30)

  1. Snapshot the staging database (backup-db.sh on the staging stack) and record the dump path.
  2. Record current image digests and archive docker-compose.yml as .bak-preupgrade-1.90.1.
  3. docker compose stop app worker.
  4. Pull the 1.90.1 images; docker compose up -d app worker together.
  5. Watch the migration logs for 0345 and 0349; confirm alembic_version matches 1.90.1.
  6. Run the eight named smoke checks: gateway health 200; login through Cloudflare Access; one agent turn calling one MCP tool; one document upload → embed → retrieval hit; one routine dispatch; one sandbox run; one artifact render; DB schema version consistent.
  7. Soak 24 h; compare error rate, latency and agent-run success to the 7-day baseline.

5. Production (Thursday window, 03:00)

Only after staging is 8/8 and the soak is clean. Same sequence, in the maintenance window, with Ricardo and Tuan present or explicitly approving in writing. Superman re-runs the same eight checks and writes one ledger row per check with its evidence id.

6. Rollback

Case Action
Image fails to start Re-pin the 1.82.2 digests, docker compose up -d, verify health. No database change.
Migration applied but smoke fails Re-pin images and restore the pre-upgrade dump; accept the data-loss window since the dump; record it in the ledger.
Partial migration Restore the dump; do not attempt a down-migration that the release notes do not provide.
