03 Two faults — found and fixed

F1 · The vault watchdog was bouncing Beast's write server every 10 minutes fixed

The cron job judged health from launchctl print … active count. The launchd job runs through a JXA wrapper that exits once the server detaches, so that counter reads 0 while the server is serving perfectly. Every tick it decided "inactive", ran kickstart -k, and killed the vault's CRDT write server — then reported failure anyway.

7e69263… completed  19:50:11  ← after the fix
dc3d241… completed  19:48:34  ← after the fix
5c01356… failed     19:41:12  ok-vault-server still inactive after restart attempt
da425e6… failed     19:38:26  ok-vault-server still inactive after restart attempt

A Nov-1 rewrite had replaced the correct, port-based watchdog with this older launchd-count version at ~/.hermes/scripts/, while the good logic still lived in ~/.config/maio-stack/bin/. Fix: the cron copy is now a two-line exec wrapper onto the canonical script (socket probe → kickstart → bounded wait → detached fallback), so a second copy cannot drift again. Verified: manual run exit 0, silent, and pid 6320 unchanged with uptime intact; the 19:50 scheduled run completed.

F2 · 61 MB of supervisor stderr that nothing rotated fixed

Hermes rotates its own logs, but the files written by a launchd redirect are opened once and never reopened — gateway.error.log (the gateway plist's 2>> sink) had been growing since 2 October at roughly 8 MB a day. hermes doctor never mentions it.

before:  61M  ~/.hermes/logs/gateway.error.log
run:     archived gateway.error.log (61MB) -> archive/gateway.error.20261106-195045.log.gz   exit=0
after:   0B   ~/.hermes/logs/gateway.error.log   (archive 4.8 MB gz)
+20s:    186B — new WARNING written at offset 0, writer unaffected

Nothing was deleted: the content is compressed into logs/archive/. New daily job hermes-log-rotate (04:10, no-agent, local, silent unless it acts) archives anything over 20 MB and truncates with : > — safe because the writer holds an O_APPEND fd, proven live by the 186 bytes that landed afterwards.
