publish-document 1.6.0: kanban workers can file their own documents

Summary

Since October, every document published from inside a kanban worker stopped at NOT FILED (exit 8). The vault filing card for Beast was never opened, so somebody had to open it by hand every time. It happened five times on 2026-10-09 and again today (t_24f52a21).

The cause is a safety fence, and the fence is correct. The tool opened the card by running hermes kanban create in a shell. Inside a worker, every shell carries the HERMES_DELEGATED_CHILD_CONTEXT marker, and the board refuses card writes from any process that carries it. The fence is what stops a delegate_task helper from changing the board. It stays exactly as it is.

The fix uses the other way in that already exists. The worker's own kanban_create tool may create cards; only shells and helpers may not. So the tool now prints the exact card it would have opened, and the worker posts it with one kanban_create call.

[!NOTE] The one new step for workers Inside a kanban worker, run publish-document … --card-lane spec. It prints a JSON card between <<<publish-document card-spec and card-spec>>> and exits 8. Then call kanban_create(title=…, assignee="beast", body=…, idempotency_key=…) with those four fields as printed. That call is the filing step.

graph LR
  W[Kanban worker] -->|shell| P[publish-document]
  P -->|tries hermes kanban create| F{Board fence}
  F -->|refused: shell carries the marker| S[Card spec printed, exit 8]
  F -->|admitted: human, cron, plain shell| C[Card opened by the tool, exit 0]
  S -->|worker's own tool| K[kanban_create]
  K --> B[Beast card on the board]
  C --> B
  B --> V[Vault note filed by Beast]

What changed

Piece Change
publish_document.py 1.5.3 → 1.6.0 New card lane. --card-lane auto (the default) tries the CLI and switches to the spec only when the refusal is the board fence. --card-lane spec / --emit-card-spec / PUBLISH_CARD_SPEC=1 skip the CLI. PUBLISH_CARD_SPEC=0 turns the lane off.
The spec Exactly the four kanban_create fields: title, assignee (beast), body, idempotency_key (publish-<sha16>). They come from the same builders the CLI lane uses, so both lanes produce the same card, and a re-post returns the same card.
--json Stdout is still one JSON receipt. The spec rides inside it as handoff.card_spec; the pointer line goes to stderr.
Filed: line Never a bare "pending". It reads pending (rule-4 handoff — card NOT on the board yet: post the card spec with kanban_create).
Exit code 8 until the card exists. A broken CLI (missing binary and so on) is still a hard NOT FILED; only the fence leads to a spec.
Side fix The renderer's "hand-built page" guard read only the first 8 KB of a page. The v2 templates grew past that, so the tool refused to replace its own earlier HTML edition. It now reads the whole page.
Spec + instruction block Convention §1.5, new §1.7 (the two lanes), §5, §6.2, §6.3 and §6.4. The per-prompt block now names the one worker step, and all 32 profile SOUL.md files are updated through the installer.
