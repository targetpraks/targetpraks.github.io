Multica — self-hosted agent workspace on the Mac mini

What this is

Multica is the open-source "project management for human + agent teams" product from the X thread (@Mariandipietra, 2026-11-22). Agents are first-class assignees on a board whose columns are owned steps; moving a card hands it to that step's agent. It supports Hermes, Codex, Claude Code, OpenCode, omp, QwenPaw, Grok and DSH natively — all already installed on this Mac.

Rather than clone the UI, the real product is running here, wired to our fleet.

Known pitfalls

  1. hermes session/new failed … "Gateway draining: update_paused". Multica builds a per-task HERMES_HOME overlay; the first tasks each triggered a Hermes source-update / dependency tail that takes the shared checkout lock and fences the gateway for every other run (upstream multica#9390). Fix applied: HERMES_DISABLE_LAZY_INSTALLS=1 in each Hermes agent's custom_env (multica agent env set --custom-env '{"HERMES_DISABLE_LAZY_INSTALLS":"1"}').
  2. Codex/agent role pushback: an agent handed work outside its stated role comments and stops rather than acting. That is the identity guard working; assign work that matches the card's owner.
  3. Ports 3000/8080 were free; if a dev server takes 3000 later, set BACKEND_PORT / FRONTEND_PORT in .env and restart.
  4. If mail delivery ever fails, codes are still stored in verification_code (Postgres) and the backend log; check the log for an SMTP error line first.
