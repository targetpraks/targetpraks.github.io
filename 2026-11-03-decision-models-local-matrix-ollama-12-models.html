The answer, in one line

clef-flash (Cloudflare, 9B, Apache 2.0) is the best general-purpose local decision model for this Mac: strongest tool-call gating in the field (BFCL 98.8), lowest measured latency of any model in its class (38.8 ms median), 64K–256K context, image input, and it fits in 11–12 GB. kev:9b-nvfp4 is the best accuracy-per-byte pick (6.7 GB, 68/111 hard JevBench tasks). d3 — which this Mac already runs as the §8 gate — remains the safest strategic bet because it is the only family with a 2B→27B ladder you can climb as hardware grows.

Where the three actually diverge

  • Sarcasm / sentiment — "Great, another outage. Third one this week." Gold is Negative. Local d3 read it as Neutral with 0.22 confidence (miss). clef-flash got it, 0.595 confidence. clef 27B also missed it — but at 0.005 confidence, i.e. it knew it had no idea. That is the single most useful difference on this set.
  • A buried SLA band — a long triage note with a distractor queue. Gold P3. d3 and clef-flash both answered P2; only the 27B picked P3. This is the one place the big model earned its size.
  • Everything else agreed — 16 of 17 answers identical between local and either cloud lane, including all nine yes/no items.

The subscription runs a smaller window than the local weights

ollama show on this machine: clef-flash:cloud serves 24,576 tokens and clef:27b-cloud serves 65,536, while the local packages advertise 256K. So the cloud lane is cheaper to run but the first thing you give up is context, not accuracy. Sending a 100K-token document to clef:27b-cloud is rejected, not truncated.

Clef vs Clef-flash, same suite, published

Only Cloudflare scores both on one yardstick, so this is the one legitimate family head-to-head:

  • clef-flash wins — BFCL 98.8 vs 98.5, API-Bank 93.1 vs 91.9, home-appliance simulator 97.7 vs 83.0, median latency 38.8 ms vs 209.3 ms.
  • clef 27B wins — CLINC150+OOS 97.4 vs 66.8 (a 30-point gap on intent classification), ANLI 69.8 vs 59.1, When2Call 72.4 vs 65.6, BANKING77 94.2 vs 90.9, PhishNChips 79.6 vs 75.0.
  • Read: for tool-call gating and bounded state machines, flash is the better and far faster model. For routing on open-ended intent and for long-context judgement, the 27B is worth its 5× latency.

What the numbers actually mean — read this before quoting any of them

Four different "indexes" are in play

These models are scored on at least four unrelated yardsticks, and the pages quote them side by side as if comparable:

  • Jev Decision Index 0.2.1 — d1 48.57, nimble-v3 56.88
  • Jev Decision Index 0.3.2 — d3 38.9–66.3 (text), 54.7–71.3 (vision)
  • JevBench 231-case public set — kev 183/231, nimble-v3 201/231, strands 183/231
  • Cloudflare's Decision Index — the suite behind clef's BFCL/API-Bank table

A 56.88 and a 55.8 are not a 1-point gap. Index versions and task sets differ. The only honest cross-model comparison is on the same 231 JevBench cases, and that only covers kev, nimble, strands and the older nimble.

nimble-v3 is non-commercial

Bespoke Labs relicensed nimble-v3 to CC BY-NC 4.0 — a change from the earlier nimble, which is Apache 2.0. It is the best-scoring 9B on Decision Index 0.2.1 and it is unusable for any paid work in the group. Use nimble (v1) instead, or clef-flash.

Context lengths are advertised, not usable

  • d3 — table says 256K; the page's own limits section says the shipped packages run at 4,096 tokens.
  • clef / clef-flash — highlight says 64K, spec table says 256K.
  • tev1 — 256K in the table, "about 2,000 tokens" in the notes; longest training example ~1,500.
  • nimble — 256K in the table, 8,192-token prompt cap in the notes.
  • strands-decider — genuinely 4,096, stated plainly. Plan for short inputs.

The gate model is already good news

This Mac's §8 gate runs d3-flash-mlx. Its real identity, from ollama show: qwen3_5 · 8.4B · int8 · ctx 262,144 · 10.31 GB resident. A live System One request returned urgent 0.997, team = technical 0.9998 in 10.1 s cold and 0.36–0.39 s warm. That is the baseline any replacement has to beat on this box.

Every page says the same thing about trust

Without exception, the publishers warn that probabilities are model outputs, not real-world frequencies, and that confidence measures how concentrated the distribution is — not the chance the answer is right. Laya's page is bluntest: a 0.9 confidence does not mean 90% correct on your data. Any threshold this stack relies on has to be refit on our own labelled examples, per model.

Practical recommendation for the fleet

  • Keep d3 as the gate — installed, working, vision, and the only 2B→27B ladder (swap in d3:27b the day a 64 GB machine joins).
  • Trial clef-flash beside it for speed-sensitive gating: ~10× the measured warm latency headroom, image input, Apache 2.0. Cost: ~1.5 GB more RAM.
  • Add laya only if routing volume justifies a second always-loaded model — 844 MB and 14 ms/question batched make it nearly free, but it is text-only and weak off-distribution.
  • Rule out pplx-decider, clef 27B, d3:27b and kev:27b on this hardware; rule out nimble-v3 on licence.
