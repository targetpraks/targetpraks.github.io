2. Why

Batman was a seat that only answered when spoken to. "Proactive" on this platform means a routine: a prompt plus a cadence the platform fires on its own, with a run record, a budget and a failure limit. The two routines cover the two jobs a platform seat should do without being asked — a nightly check of what is broken, and a Monday brief of what it cost and what needs a decision.

3. What was refused, and the fix

The first two attempts were saved paused and refused to activate:

ROUTINE_SOURCES_REVIEW_REQUIRED — "The AgenticOS platform MCP server requires Act as creator. Enable it or remove the platform binding."

Set runs_as_creator: true on both, re-read the sources review, consented, enabled.

The first real fire then parked on search_tools — dynamic tool discovery is a read-only framework gate with no capability id, so it never appears in the action-consent options (can_waive: false) and a routine can never pre-consent it. Batman called it only because his tool_search capability defers MCP tools by default (defer_mcp_servers: true).

The fix was at the source rather than around it: the ten tools the routine needs are now always visible to Batman, so he never searches:

agenticos_list_runs, agenticos_get_run, agenticos_read_run_transcript,
agenticos_read_run_tool_call, agenticos_get_spend, agenticos_list_agents,
agenticos_get_agent, agenticos_list_routines,
agenticos_list_workflow_definitions, agenticos_list_watches

The second fire then reached execute (a shell call to inspect a spilled tool result) and parked there. The prompts now name the ten tools, forbid search_tools/execute/files/memory/skills, and require limit=20 or fewer so results do not spill.
