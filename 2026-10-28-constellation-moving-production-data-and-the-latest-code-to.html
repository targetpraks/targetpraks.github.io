3. What has to travel with the data

Names only — no values leave this machine through chat, cards or documents:

Variable Rule
CONSTELLATION_ENC_KEY Must be byte-identical. It decrypts every stored reading and revision. A new key makes the history permanently unreadable.
CONSTELLATION_PREVIOUS_ENC_KEYS Same — carries the older key(s) still needed.
AUTH_SECRET May be new; the only cost is signing everyone out.
DATABASE_URL / MIGRATION_DATABASE_URL Staging's own database roles.

All three secrets are present on this Mac in ~/.config/constellation/runtime.env (mode 600). They can be carried across without ever being displayed.

6. The runbook, once access lands

# 1. target: staging VM (through the bastion)
ssh macserver 'cd /srv/staging/apps/constellation && git fetch --all && git switch main && git pull --ff-only && git log --oneline -1'

# 2. data: dump production, stream to staging, restore — never through git or chat
ssh <prod-host> 'pg_dump -Fc -d constellation' | \
  ssh macserver 'pg_restore --no-owner --no-acl --exit-on-error -d constellation'

# 3. secrets: copy the file, never print it
scp ~/.config/constellation/runtime.env macserver:/srv/staging/apps/constellation/.env.production

# 4. code: build and start
ssh macserver 'cd /srv/staging/apps/constellation && docker compose config --quiet && docker compose up -d --build && docker compose ps'

# 5. verify: counts must match production, then a real login and one assessment page
ssh macserver 'psql "$DATABASE_URL" -tAc "select (select count(*) from \"Staff\"), (select count(*) from \"Response\")"'
curl -sS https://constellation-staging.infinityapps.co.za/api/health

Done means: the restored counts equal production's counts, the encryption key is the original one so old readings open, and a real login reaches an assessment with history intact. A healthy /api/health is not that — both instances answer ok today while one of them is empty.
