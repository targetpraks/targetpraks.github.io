Summary

The first version of this record ended on an open finding. The cost fields were gone, but the same money still travelled inside scaling_note — "raw cost ~R4–5.50/serving at 60–70% margin", "retail R69–79/500 g", "the franchise margin floor". Both guards look for key names, and a sentence has no key. A cook with devtools could still read the margin off the file their own tablet had downloaded.

That finding is closed. Commit 197c9e3, pushed on 30 October at 00:10 on fix/payload-hygiene, stops the payload build from carrying scaling_note. Nothing filters it out by pattern: the payload is assembled as a list of keys, one line each, in scripts/lock_versions.py, and the line that put the note in is gone. Bringing it back would take a change you can see in a diff.

The four payloads were regenerated, one line lighter each, and their payload_sha256 pins were refreshed in data/registry.json. I recomputed all four hashes from the bytes on disk: they match. content_sha256 did not move for any recipe, because the recipe did not change — the note is still in data/source/recipes_source.json and in each data/recipes/*.draft.json. That is correct: it is production guidance, not something a tablet shows.

app/sw.js moved BUILD to bench-v2-2026-10-29-20. The four payloads are precached, so a tablet that already holds the old copy would keep serving the margin until its cache name changed. That bump was not in the ask, and I made it anyway — the reasoning is below.

The full-run artefact yesterday's record said was missing now exists: verify-last.log, 1,078 lines, 20 sections, 653 checks, 0 failures. PR #20 stays open with both commits on it, so it is one review, not two. Merge stays Geoff's call and publish authority stays Ricardo's.

What this is

The kitchen bench is the tablet app that scales a recipe, builds the batch card and closes the batch. A tablet is not always online, so it precaches its recipes: the four files under data/bench/ are what a cook's device holds on disk and re-reads offline. Law one says no money and no formula percentage reach the glass. The payload sits behind the glass, so the payload is the edge that matters.

This note keeps the file name it was filed under yesterday. The link already handed out points here, and a corrected edition belongs at the same address, not beside it.

The fix deletes that one line and adds a comment above the dict (lines 66–70) saying why. A regression now needs a person to type the key back into that dict.

Two calls I made, and one I did not

1. The cache version bump was mine. The card asked for the payload change, the regenerated files and the re-pinned hashes. It did not ask for app/sw.js. Without the bump the fix would not reach a tablet that already cached the old payload: the file a cook's device serves comes from the cache, and the cache is keyed by BUILD. Served bytes changed, so the key had to change.

2. Farmhouse's ingredient spec still says "oven-dry ≤ 70 °C for cost". That line is real and it does render — app/app.js line 1358 prints an ingredient's spec on the card, and scripts/pad.mjs line 51 prints it on the sheet. I left it. It carries no number, it is a process instruction the cook needs to read, and cutting it would edit the manual's truth (I2) to fix a word. Flagged here rather than changed.

3. I did not add a value scan. A regex over payload values would catch this class of leak, and it would also fire on the quality gate, which legitimately says things like "protein ≥ 13%" and "moisture 28–32%". The structural guard — a payload whose keys are written one per line — is smaller and cannot rot into false confidence.

Where the work stands

  • Both leaks are closed on the branch. A tablet collects the fix on its next cache refresh, because the cache name changed.
  • PR #20 is open, not draft, head 197c9e3, carrying both commits. The repo has no CI configured, so there are no checks to wait on.
  • Merge is Geoff's. D4, publish authority, is still Ricardo's call and no agent's.
  • The Farmhouse total row is still a manual defect, not a code one: its 10 kg ingredient rows sum to 10.20 kg under a 10.00 kg total. The card and the sheet print the disagreement rather than hiding it; the recipe owner corrects the manual.
  • Percentages still appear in the payload, and that is fine: they are the quality gate's own numbers (protein ≥ 13%, moisture 28–32%, a 5% sensory ceiling). What is gone is the baker's percentage — flour-relative formula — which is what I12 keeps off the card. R638 in a drying step is a food-safety regulation number, not rand.
