Why the obvious candidate loses

CodexBar is the bigger project — 22,763 stars, 63 providers, a release published today — and it does ship an Ollama provider. It still cannot show this account’s number. Installed 0.80.0 here and asked it directly:

codexbar usage --provider ollama --source api --format json
[{"provider":"ollama","source":"api",
  "error":{"message":"Ollama returned an unrecognized credit balance response."}}]

Its API-mode parser expects the credit-wallet shape (allowance_usd / balance_usd); your Max plan answers with session.remaining_percent and weekly.remaining_percent. Its cookie mode would read the page, but that needs a Chrome or Safari login — your browser is Dia — and no fix landed in the 0.80.0 release of this morning. OpenUsage parses both shapes.

Finishing it on rmmacbook — three steps, all yours

  • 1. Sign the Ollama key in. In Terminal: ollama signin (the CLI is now at /opt/homebrew/bin/ollama). Approve in the browser that opens. If it reports no server, run ollama serve once and repeat. This is what links the machine’s ed25519 key to your account — the app never asks for an API key, and I will not copy the mini’s private key across.
  • 2. Open OpenUsage, click “Connect Selected”. When macOS asks about “Claude Safe Storage”, choose Always Allow and type your login password yourself — that dialog is a hard stop for me. Deny also works; Claude then falls back to ~/.claude/.credentials.json.
  • 3. Customize → turn on Ollama, star “Session”. Ollama never enables itself. Two stars per provider are allowed, so Claude Session, Codex Weekly and Ollama Session can all sit in the strip.

Until step 1 is done the Air shows Codex only; the existing Ollama Bar keeps showing the Ollama percentage in the meantime, so nothing goes dark.

For the Hermes workflow

OpenUsage is also a read-only CLI and a loopback HTTP API, so an agent can ask before it burns a limit:

openusage --force              # full openusage.limits.v1 JSON
openusage ollama               # one provider
curl -s 127.0.0.1:6736/v1/limits

A Courage cron can parse providers.*.resources.session.remaining and warn when Claude’s 5-hour window drops under 10% or Ollama’s weekly under 15% — the same shape for every provider, so one script covers the whole stack.

What becomes redundant

  • Quotio Beta — its Claude, Codex and Copilot lanes are all covered by OpenUsage, which does not rewrite its config or fight macOS for the keychain on every refresh. Retire it once step 2 is done.
  • Ollama Bar — the Ollama percentage duplicates OpenUsage. Its unique value is the loaded-model list and one-click unload; keep it in “Local models” badge mode if you still want that, otherwise retire it too.
One reading worth noticing: at 21:30 tonight the Claude lane came back session 100% used, 0% left (weekly 44% used). That is the 5-hour window being spent, not a parse error — and it is exactly the kind of wall the bar exists to show before a long run starts.

Caveats

  • OpenUsage needs macOS 15+ (both Macs are 27.0.1) and pins at most two metrics per provider.
  • Ollama’s /api/balance is undocumented; the app treats a shape change as “invalid response”, never as zero usage.
  • The Ollama lane needs Ollama installed on that Mac — signing is per-machine, which is why the Air needs step 1.
  • No purchase, no terms accepted, no credential typed, copied or printed at any point.
