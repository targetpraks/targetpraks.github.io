The finding that reshapes the plan

Mnemosyne ships with profile_isolation set to false. Left alone, all 29 configs would write into one shared memory database — every profile seeing every other profile's facts. Isolation has to be switched on before the first memory is stored, because un-mixing imported facts afterwards is not a clean operation.

01Summary

Twenty-nine configs point their memory at Hindsight. The free-only bake-off measured what that arrangement delivers: 20 of 22 questions answered at rank one, against 17 of 22 for Mnemosyne, which spent no tokens and sent nothing off the machine.

This PRD moves the fleet across, carries the learned facts with it, and switches Hindsight off only after one profile has run clean for a week and the export has been verified twice.

What this PRD does not claim

Hindsight measured better on multi-hop and rephrased questions and is the only one of the two with entity resolution. The argument is operational: for a fleet writing memory on every turn, 29 times over, an engine that is nearly as good at a thousandth of the cost should be the default.

03Six phases, reversible until the last

  • Phase 0 — Export. Page every fact and every document's original text out of the three banks into JSONL under AI-Drive, with counts and a sha256 per file. Nothing stopped, nothing deleted.
  • Phase 1 — Isolate. Set memory.mnemosyne.profile_isolation: true and a per-profile bank name before the plugin stores anything. Skipping this merges 29 configs into one database.
  • Phase 2 — Canary. Enable the plugin, switch this profile only, restart the gateway, run the probe set against this profile's own bank.
  • Phase 3 — Import. Replay facts in batches of 500, keeping each fact's original timestamp, and compare imported against exported per bank.
  • Phase 4 — Rollout. Same two lines per profile, in waves: scribe and beast first, then the executive seats, then the rest.
  • Phase 5 — Decommission. Stop the container, then colima, only after the fleet is clean. Hold the volume 14 days, then remove it on an explicit go-ahead.
  • Phase 6 — Freshness. Add hermes-dreaming for nightly supersession. Both engines failed that test, so it is a real gap.

04Acceptance criteria

  • A1 — Export complete. wc -l <bank>.jsonl equals the bank's total read at the same minute. Pass: exact match on all three.
  • A2 — Provider switched. hermes memory status | grep -qE "^ Provider: +mnemosyne$". Pass: exit 0. The real line uses two spaces, so a substring match would fail.
  • A3 — Canary retrieves. Ten single-fact questions, 10/10 at rank one. Pass: scorer.py reports hit@1=10/10.
  • A4 — No cloud egress on a write. Resolve dig +short ollama.com | head -1, run nettop -P -l 1 -p <hermes pid>, trigger one retain and one recall. Pass: no connection to that address. lsof is not enough — it prints IPs, never hostnames.
  • A5 — Import complete. Facts in the profile's bank equal facts exported for it within 0.5%. Pass: printed counts inside tolerance.
  • A6 — Prompt growth measured. Record loaded memory-tool count and first-turn prompt tokens for one fixed session template. Pass: both numbers recorded; flag above +2,000 tokens. No plugin-level allowlist exists, so the fallback is a smaller engine, not trimming.
  • A7 — Rollback proved. Flipping the provider back returns a recall with a real memory id from maio-ops. Pass: one successful recall, before any deletion.
  • A8 — Reclaim measured. After removal, the image and volume listings print nothing. Pass: both empty.
  • A9 — Isolation holds. With two profiles enabled, a fact written by one is not recalled by the other. Pass: the second profile's recall returns nothing.
