How it was written, and how it was proved

ClickUp's public API cannot add a person to a chat room: every members route answers 405 or 404, and the one that answers 200 stores nobody. The app itself writes through a different door — a chat room is a view in ClickUp's access-control service, and its member list is that access list. With the session the signed-in desktop app already holds, the list is read, the missing person appended, and written back:

GET https://frontdoor-prod-eu-west-1-2.clickup.com/v3-user/access/4627083/view/<room>/acls
PATCH … {"entries":[ …existing…, {"kind":"user","id":<person>,"permission_level":5} ]}

Every write answered 200, and every room was then re-read through /chat/channels/<room>/members — the column above is that read, not the write's own echo.
