5. The swap, when it is approved

Downtime is the stop → migrate → up window, measured at roughly 30 s of migration plus container start, so about one to two minutes. Sequence:

cd ~/agenticos
stamp=$(date -u +%Y%m%dT%H%M%SZ)
docker compose $F exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -Fc "$POSTGRES_DB"' > backups/pre-$stamp.dump
cp .env backups/pre-$stamp.env
cp docker-compose.yml docker-compose.yml.bak.$stamp
cp docker-compose.instance.yml docker-compose.instance.yml.bak.$stamp
cp ~/agenticos-1901-prod/docker-compose.yml .
cp ~/agenticos-1901-prod/docker-compose.instance.yml .
cp ~/agenticos-1901-prod/.env .            # AGENTICOS_VERSION=1.90.1
docker compose $F config -q
./agenticos.sh pull
docker compose $F stop app worker
./agenticos.sh up              # migrate runs first, then app/worker/frontend together
./agenticos.sh doctor
docker exec agenticos-app-1 agenticos --version

Rollback: re-pin staff-access-7c612abc5695 and agenticos-frontend:1.82.2, restore docker-compose.yml.bak.$stamp and the pre-swap dump. Because 0345/0349 have no down migration, rolling code back across them means restoring the dump — accept and record the data-loss window.
