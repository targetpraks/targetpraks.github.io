2. Applied

Connect framing is live. The 1.92.0 frontend was layered a second time — agenticos-frontend:1.92.0-unit-frame = the private-unit-count image plus patch.js, which sets frame-ancestors https://connect.infinitybrands.co.za in the edge chunks and drops the X-Frame-Options rule. Verified on the running container: one patched chunk, zero x-frame-options, and the header served at http://127.0.0.1:3000/en now reads frame-ancestors https://connect.infinitybrands.co.za. The unit-count page is still compiled in.

Disk guard restored, with a correction. A guard already existed on this host (agenticos-disk-guard.service, JSON line, 90 % threshold) and my first attempt overwrote its unit file. It is restored as ~/agenticos/ops/disk-guard.py with the same JSON contract (checked_at, path, used_percent, used_gb, free_gb, total_gb, threshold_percent, status), the same 90 % threshold and 10-minute timer, plus one addition: above 90 % it prunes Docker's build cache and re-measures, because a 18.75 GB build cache is what took this disk to 100 % on 24 November. Latest run: used 72.9 %, free 16.5 GB, status ok.

The AI HUB card path is built and proven. wd-sync/workdrive_sync.py now writes a second card per unit when the manifest names a folder:

  • agent_output_folder — that unit's own AI HUB subfolder (preferred);
  • agent_output_root — the shared AI HUB root, for units whose subfolder id is not known yet.

The card text names the folder, says it lives inside the AI HUB - Agent Output tree and tells the agent to open it with the employee's own account. It is uploaded, indexed and then proven by the same RAG-search check the existing cards use, and any failure on the second card is caught so it can never break the unit's own card. Proven on production for BU 03 ADM with a temporary value: card indexed with 1 chunk, returned by search with its link, then deleted (204) and the manifest left untouched.

3. Blocked on one input

The card needs a Zoho folder id, and the platform cannot discover one:

  • the Zoho "system user" client has no WorkDrive scope (F7007 Invalid OAuth scope), so no enumeration or write;
  • this Mac's WorkDrive TrueSync mount is cloud-only File Provider placeholders with no ids in the paths or attributes;
  • agents run in containers with no mount at all.

What unblocks it, either way, in one step:

  1. paste the https://workdrive.zoho.com/folder/<id> link of AI HUB - Agent Output — one id covers all 24 units through agent_output_root; or
  2. re-consent the Zoho system client with WorkDrive.files.ALL, and I enumerate the root and every BU subfolder myself, then write agent_output_folder per unit.

Once either lands, activation is one manifest edit plus python3 ~/agenticos/wd-sync/run-all.sh, and the 03:05 nightly job keeps it verified.
