2.1 Hiksemi 1TB drive — night check reports false RED every night PERSISTENT COURAGE

Every Courage night check from 2026-10-26 through 2026-11-01 reports:

hiksemi_drive RED I/O BLOCKED — read_ok=False write_ok=True read_err=False (signature of the 2026-10-06 overnight wedge)

But the dedicated Hiksemi watcher (real byte read + write, every 30 min) reports healthy continuously, and my live read+write test just now passed. The night check's read method appears to use stat/df, which lies during a wedge — only a real byte read is trustworthy. Result: a week of false RED alarms.

Automation candidate: align the night check to the watcher's real read+write test

Replace the night check's Hiksemi read probe with the same real byte read+write used by recover-hiksemi-wedge.sh (runs every 30 min via com.maio.hiksemi-recover). This kills the false alarms and gives one consistent signal. The watcher state file currently reads "healthy".

Root cause of the original wedge (19 Oct): the Hiksemi enclosure falls back from SuperSpeed to a 480 Mbps USB 2.1 link. The watcher logs this as a leading indicator, never as an outage.
