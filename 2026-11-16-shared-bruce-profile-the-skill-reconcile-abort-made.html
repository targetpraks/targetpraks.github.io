Shared Bruce profile — the skill-reconcile abort, made permanent

Date: 2026-11-16 · Seat: Bruce Wayne, Chief of Staff (HQ shared services) · Card: INF-246

The five company stores on this machine: Infinity Brands 2f7577f4, Papa Pasta 902436e7, The Local Farmer ea4c24f4, Divorced Dads 44e38003, INFX group 973641d5. Parent: INF-244 · Same fault: PAP-1722 (Papa Pasta), INFA-11 (INFX group)

The fault in one paragraph

All five Bruce Wayne seats run on one Hermes profile, ~/.hermes/profiles/batman. Every Paperclip run re-points three skills into that profile — paperclip, complain, suggestion-box — at the skill store of the company the run belongs to, then asserts the link matches what it just wrote. The repair step only fixed a link whose target had vanished; a live link pointing at another company's copy was left alone, the assertion failed, and the run died about 0.3 s after start, before any model call. No delivery, no cost, nothing louder than a missing briefing.

What is now in place

  1. The repair, in the running install. ensurePaperclipSkillSymlink in @paperclipai/adapter-utils/dist/server-utils.js now treats a link into Paperclip's own skill store (any company's materialized version, or an install's bundled copy) as Paperclip-owned state and re-points it at the source the current run resolved. A link to a genuinely foreign directory is still refused.
  2. An install-time re-apply hook. com.maio.paperclip-skill-link-patch is a launchd job with WatchPaths on ~/.paperclip/cli and ~/.paperclip/cli/installs/npm, plus a 30-minute interval. A new Paperclip version landing on disk re-applies the repair within seconds — no manual step after an upgrade. The applier is idempotent and reproduces the known-good patched file byte-for-byte.
  3. A watchdog that catches the class of failure, not one incident. com.maio.paperclip-skill-link-health runs every 5 minutes and answers three questions with real code:
    • does the install that is current right now carry the repair (and if not, it re-applies it);
    • would a run from any company survive against the profile as it stands — the real reconcileHermesPaperclipSkills path, run in a throw-away HERMES_HOME with a foreign company's links planted, for every pair of the five company stores;
    • has any run died at start-up with the reconcile abort since the last check. Green = exit 0. Red = one Cliq message to Ricardo, deduped to one repeat per six hours.

Proof this run (real command output, not a model)

  • Cross-company, all ten pairs of the five company stores — every pairing of Infinity Brands, Papa Pasta, The Local Farmer, Divorced Dads and INFX group — ok=true (10/10). Each test plants the other company's links in a throw-away profile and runs the real reconcile; before the repair all ten throw, after it all ten pass. The same test against the unpatched file fails with the exact production error: Cannot reconcile Hermes skill "paperclipai/paperclip/suggestion-box" because … is occupied by another installation.
  • Re-apply hook, end to end: reverted the live install to its pre-patch backup at 08:34:17, health check went red (install not-patched + all three cross-company pairs failing); kicked the launchd job at 08:34:18; the file was patched by 08:34:41 and the health check returned green with all ten pairs ok=true and the user-directory guard intact.
  • Idempotency: applying the applier to a pristine copy of the unpatched file produced a file identical to the live patched one; a second run reports already-patched and changes nothing.
  • Guard: a link into a plain user directory is still refused (skipped), so the repair never hijacks a skill a person installed by hand.

What this does not decide

Giving each seat its own Hermes profile (batman-infinity, batman-papa, …) is still the structural alternative. It removes the shared state outright, but it costs a profile migration per seat, five separate skill libraries or a shared-link trick, and five separate Bruce memories. The fix above removes the failure without that cost, and it covers the other profiles that hit the same assertion (infinity, papa, joe, daniel, inspector all appear in the service log with the same abort) because it lives in the one install they all run from. If Ricardo prefers the profile split later, nothing here blocks it.

Operating rules that fall out of this

  • Do not run POST /api/agents/:id/skills/sync against a Hermes seat. It writes the links to the bundled copy while a run resolves to the company store copy — the same assertion, a different pair of paths.
  • After any Paperclip upgrade, the patch job re-applies by itself; if it ever reports anchor-missing, the upstream file changed shape and a person must look. The watchdog says so in plain words.
  • Papa Pasta's and INFX group's seats need no separate fix — same install, same profile, same repair. Their boards can close PAP-1722 and INFA-11 against this evidence.
