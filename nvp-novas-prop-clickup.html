NVP — Retiring the Novas Prop document

ClickUp becomes the only home for Nova Property's records.

Status: PROPOSED — supersedes the migration PRD of 19 November. Prepared 19 November 2026 by Adrianna A. Nothing has been created, changed or moved. The document is still live and untouched; this is the plan to replace it.

At a glance

  • What is being replaced: 22 pages, 20 tables, 134 columns and 217 rows of property data, 187 of which carry a bill, a certificate or a payment. Plus the eight jobs the document does that are not data at all.
  • Where it goes: two folders, six lists, four saved views and ten documents inside the space. Every page gets a named home — none is left "for later". §7 draws every one of them, with real rows.
  • The gate: 187 rows migrate, 24 missing lines are added, and every one of the 20 tables is counted against a named list. One unmatched row and the document does not get retired.
  • The dates: edit rights come off the document on 27 November, work moves to ClickUp on 2 December, the document is locked and archived on 14 December.
  • Why it has to be a replacement and not a copy: the document is already drifting (last edited 21 September; Frances' lease ended seven weeks ago and its exit inspection is still recorded as "scheduled"). A copy of a drifting document drifts too.
  • What I need: seven decisions in §12. Reply go and I take the recommended option on each.

1. The replacement standard

Copying the data is not replacing the document. A person who needs an answer will keep opening Coda until ClickUp answers the question better. So the document is only retired when four tests pass:

Test What it means How it is proved
Every page all 22 pages have a named destination inside the space the ledger in §3, one row per page
Every row all 187 data-carrying rows arrive, and none arrive twice the reconciliation in §9, per table
Every column all 134 columns are either mapped to a field or consciously dropped, with a reason the field mapping in §4
Every function the eight things the document does are done by ClickUp the function table in §5

The fourth test is the one that decides whether this works. Data without function is a spreadsheet; people will keep the document open beside it.

4. The field mapping — table by table

This is the part that decides whether the register is usable or just different. Each table's columns, and what happens to them.

4.1 Statutory documentation — 6 tables, 68 rows, 4–5 columns

In the document In ClickUp Change
Document (11–13 free-text names) Document type (fixed picklist, 15 values) the free text contains four spellings of the same COC; a picklist makes the missing-document view possible
Date (empty on every row) Issue date the column is never filled, so it is filled at verification, not at migration
Link (a WorkDrive URL, or the word "Link", or "None") File (attachment) + Status three different meanings in one column: a real file, a dead placeholder, and a request. Each becomes its own state
Notes (the reasoning) Notes + Status + Certificate no. the reasoning is kept word for word; the status is lifted out of it
Additional Notes (Samuel only) Notes, prefixed one table has a fifth column; it merges rather than creating a fifth field

Three quirks worth naming, because they are the kind of thing that quietly ruins a migration:

  • The word "Link" with no URL appears in three cells (Frances electrical, Samuel outgoing inspection, Riley electrical). They migrate as received with no file, which is exactly the state that forces someone to go and fetch it.
  • Not Bonded and No Gas Installation are facts, not gaps. They migrate as not applicable, so they stop counting against the portfolio.
  • "Pin 728" is the note on the insurance schedule for four of the six properties. That is a copied row, not four policies with the same access pin. It migrates flagged verify, and someone confirms each schedule names the right property.

5. Function parity — the eight things the document does

Data is half of it. These are the jobs, and what takes each one over.

# What the document does How it does it today What replaces it
1 Portfolio rent roll with time to lease end two formula columns, cached, on one page Leases & Inspections, live formula, plus the same numbers on the space dashboard
2 Per-house statutory status one table per house, read by eye Document Register, filtered by property — the same view as the page, with a status instead of a sentence
3 Maintenance history with evidence date, cost, supplier, before/after photos Maintenance Log, with the photos as files and a running total per property
4 Rolling spend per house a formula under each table (Bushwillow R173 035.91, Samuel R107 299.81) a rollup on the Property Register — one number per property, everywhere it is needed
5 Twelve-month bill ledger with proofs of payment a 12-row grid per property Utility Ledger, grouped by month, filtered by property, with the bill and POP attached
6 The lease narrative a written summary on the Bloom page Tenancy Dossier: Bloom Paediatric — the same prose, in a document built to be read
7 The reasoning notes like "there is no side door, when the power trips you go in through the roof" kept verbatim in Notes, and in the property dossier — this is the most valuable writing in the document and none of it is lost
8 Where the PDF is WorkDrive links the file itself, attached

Number 7 is deliberate. Most of the document's value is not in the tables — it is in the sentences that explain why a thing is the way it is. A migration that keeps only the tables would take the data and leave the knowledge.

Two columns do the work the document's free-text notes were doing badly:

  • Status (the coloured pill) is the work: to do → in progress → waiting (on a supplier or council) → complete. This space already has to do and complete; the two in between are a two-minute UI change, not a rebuild.

The freeze rule. From 27 November nobody edits the document — not to correct a typo, not to add a note. Anything learned between 27 November and 1 December is captured in ClickUp and reconciled back to the source page if it changes a row. This is the only way the reconciliation means anything.
