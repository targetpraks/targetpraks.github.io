Per task

Brainstorm — 10 cockpit features, mechanism + pain, ≥3 cost ideas

All four obeyed the constraint set: exactly 10 numbered ideas, no cloud dependencies, cost ideas present. The judge ranked MiMo 37 > omp 36 > OpenCode 34 > Qwen 33.

  • MiMo — "Flawless compliance; cache-prefix alarm and port leases show deepest operational insight."
  • omp — "Tightest lines; resource governor and conflict radar unique; minor hand-waves."
  • OpenCode — "Solid and clean, but mechanisms more conventional; slight budget/loop-detector overlap."
  • Qwen — "Most tool-specific integrations, but handoff ideas #3/#10 overlap; wordiest lines."

Plan — implementation plan for a CSV export, repo-grounded, risk + rollback

All four stayed read-only (clean git status) and stayed under 400 words (310–345). Judge: Qwen 37 > OpenCode 36 > omp 35 > MiMo 33.

  • Qwen — "Strongest tests including subprocess exit-status check; sharp money-drift risk, granular rollback."
  • OpenCode — "Thorough grounding, named tests, sharp float-rounding drift risk; rollback clean and additive."
  • omp — "Sharpest risk (to_csv argument semantics) with concrete mitigation; assertions concrete but unnamed."
  • MiMo — "Named tests, sharp exit-code risk; csv.writer default \r\n undermines exact-equality plan." — and that is exactly the weakness that showed up in its build.

The stress suite tested things the agents never saw: extra dict keys, integer amounts, negatives, large numbers, unicode categories, comma-in-category, sort order, --format=csv equals-form, uppercase rejection, and trailing-newline behaviour. Only MiMo lost points, and only on the two real defects above.

Method

  • Prompts and runner: /tmp/bench-harness/run_bench.py (copied to AI-Drive with the evidence).
  • Each task ran in its own fresh copy of a small tally repo (/tmp/bench/<agent>/<task>), TERM=dumb, no colour, PATH pinned to ~/.local/bin:/opt/homebrew/bin:….
  • Commands: opencode run --model ollama-cloud/deepseek-v4.1-flash:1017 --auto; qwen -p … -m deepseek-v4.1-flash:1017 --approval-mode yolo; mimo run --dangerously-skip-permissions; omp -p --model ollama-cloud/deepseek-v4.1-flash:1017 --auto-approve --no-session.
  • Tests were run by me afterwards with ~/AI Hub/venvs/agent-bench/bin/python -m pytest, so an agent's claim of green was never taken at face value.
  • Judging was blind: labels A-D shuffled per task, one pass by kimi-k3 at temperature 0 on a fixed 4-criterion rubric per task.

Caveats

  • One run per cell. These are single samples; expect a few seconds of variance. The speed gaps (4.5×) are far larger than that noise, the text-score gaps (33-37) are not.
  • The harness is part of the measurement. System prompts and tool sets differ: omp injects ~15k prompt tokens before the first turn, which is why it is slower and more expensive per task. That is a real property of the harness, not a measurement error.
  • Token/cost was not compared apples-to-apples — omp ran with --no-session, so no session record existed to read usage from. Speed and quality are the comparable axes here.
  • OpenCode's configured maio-core MCP server answers 401 and retries on startup; it adds noise to that harness's runs but did not change the outcome.
