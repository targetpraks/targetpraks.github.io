0. What this document is

Today INFX FND answers "where is everyone?". It does not answer "how do we build this network, in what order, for how much, and who owns which ground?" That second question is the whole of franchise network development, and it is the question the three brands are now asking — each with a different answer.

This PRD adds one branch to the product: Network. It holds a brand's territories, its candidate stores, and its build plan, and it does the arithmetic between them. It does not replace Explore (the map) or Research (the evidence workspaces). It sits beside them and reads the same data.

Three things drove the spec, and each is a document, not an opinion:

  1. Papa Pasta has three competing zone schemes — 135 polygons, 96 zones, and a 38-cluster plan — and the app can hold only one of them.
  2. The Local Farmer sells a radius, not a polygon: seven kilometres from the premises, per Annexure "E" of its franchise agreement. The database cannot store that today.
  3. ACDC Express builds a network country by country, with five Namibian cities sequenced in four phases and a six-million-rand store. Those are candidates and phases, not pins on a competitor map.

Two structural facts decide the design.

  • zone_set is scoped to a tenant, not a brand. The 0.4.0 migration even inserts two honest empty sets — the-local-farmer territories and acdc-express territories, source "Awaiting reviewed company boundaries" — because the 135 Papa Pasta polygons must not be copied onto other brands.
  • zone.geom is NOT NULL and typed MultiPolygon. A seven-kilometre circle can be drawn as a polygon, but nothing in the schema records that the polygon is a derived circle — so when the radius changes, nothing knows to redraw it.

The arithmetic check that matters. In the source, zone_roy is not an annual figure, whatever the column name suggests. For cluster GT01: 3% × R7,833,913 target monthly sales = R235,017 — the stored value, to the rand. Across all 38 clusters the 3% column sums to R5,377,861 and the 2% column to R3,585,234, against R179,261,734 of target monthly sales. A build that labels that column "annual" overstates the zone's income twelvefold. The unit is a required field, not an inference.

Three schemes cannot be reconciled by choosing one. The 96-zone paper and the 38-cluster plan disagree about the size of a territory (2.8 stores vs 8.2), and the 135-zone set disagrees with both. The product's job is to hold all three as versions, let Ricardo compare them, and mark exactly one live per brand.

2.2 The Local Farmer — a radius, and a two-class zone

From TLF-2024-Prospectus (pages 6–10) and Annexure "E" of the draft franchise agreement:

  • Territory = 7 km radius from the premises. Marketing is permitted only inside it (clause 14.3).
  • Two zone classes. Franchise fee: class A/AA R25,000, class B/BA R20,000. The fee "secures the area of purchase".
  • 25 zones are offered — Gauteng 11, Western Cape 9, KwaZulu-Natal 5 — of which 13 are AA and 12 are BA. Fees total R565,000.
  • Royalty 7% + marketing 3% of turnover. Setup R144,420 per unit (Mighty Grow Machine R25,000, tent R15,000 optional, equipment R25,000, software R10,000, registrations R3,420, working capital R57,000).
  • At the brief's R50,000 monthly revenue per grow room, one unit pays R3,500 royalty + R1,500 marketing a month.

Twenty-five units at R144,420 is R3,610,500 of franchisee setup — a number no one can see in the app today, because there is nowhere to put it.

3. The product decision

Network is a new top-level branch with three surfaces, one shared spine.

Surface Question it answers Sits on
Territories Who owns which ground, on what terms? zone_set → zone
Pipeline Which sites are we chasing, and how far along? candidate_site + study documents
Plan How many stores, in what order, for how much? new network_plan

Why a branch and not a tab inside Research: Research is organised by evidence and workspaces (one analyst's saved view, a snapshot, a brief). Network is organised by commitments — a territory sold, a site approved, a phase gated. They have different objects, different permissions (fees are money) and different verbs (approve, supersede, sequence). Burying the second inside the first makes both harder to explain.

Why not a fourth product: every screen reads the same location, brand and zone rows. The map stays the map.

4. Domain model

Additive only. No live table is dropped or re-typed; zone gains nullable columns and one generated default, so the 135 existing rows keep working.

4.1 Territory sets and territories

-- A set is one brand's territory scheme at one version.
ALTER TABLE zone_set
  ADD COLUMN brand_id     uuid REFERENCES brand(id) ON DELETE CASCADE,
  ADD COLUMN kind         text NOT NULL DEFAULT 'polygon'
                          CHECK (kind IN ('polygon','radius','named_area')),
  ADD COLUMN effective_from date,
  ADD COLUMN superseded_at  timestamptz,
  ADD COLUMN source_document_id uuid REFERENCES study_document(id);

-- Backfill: Papa Pasta's 135-zone set belongs to the Papa Pasta brand.
UPDATE zone_set s SET brand_id = b.id FROM brand b, tenant t
 WHERE s.tenant_id = t.id AND b.slug = t.slug AND s.brand_id IS NULL;
ALTER TABLE zone_set ALTER COLUMN brand_id SET NOT NULL;
CREATE UNIQUE INDEX zone_set_brand_version_idx
  ON zone_set(brand_id, slug) WHERE superseded_at IS NULL;
ALTER TABLE zone
  ADD COLUMN territory_kind text NOT NULL DEFAULT 'polygon'
      CHECK (territory_kind IN ('polygon','radius','named_area')),
  ADD COLUMN radius_km      numeric CHECK (radius_km > 0 AND radius_km <= 50),
  ADD COLUMN fee_zar        numeric CHECK (fee_zar >= 0),
  ADD COLUMN fee_basis      text CHECK (fee_basis IN ('territory','store','annual')),
  ADD COLUMN exclusivity_months int,
  ADD COLUMN phase_no       int,
  ADD COLUMN target_stores  int CHECK (target_stores >= 0),
  ADD COLUMN economics      jsonb NOT NULL DEFAULT '{}',
  ALTER COLUMN geom DROP NOT NULL;

A radius territory stores its centre in label_point, its radius in radius_km, and a derived polygon in geom. The radius is the source of truth; the polygon is a cache. A trigger (or the repository function, where the tests can see it) redraws geom whenever radius_km or label_point changes:

UPDATE zone SET geom = ST_Buffer(label_point::geography, radius_km * 1000)::geometry
 WHERE territory_kind = 'radius';

4.2 Study documents — the evidence a candidate stands on

CREATE TABLE study_document (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id     uuid NOT NULL REFERENCES tenant(id) ON DELETE CASCADE,
  brand_id      uuid REFERENCES brand(id) ON DELETE SET NULL,
  title         text NOT NULL,
  kind          text NOT NULL CHECK (kind IN ('market_study','site_study','feasibility','terms_of_reference','strategy','financial_model')),
  author        text,                       -- Fernridge Solutions, Galaxy Retail Solutions, ACDC Franchise Development
  published_on  date,
  source_url    text NOT NULL DEFAULT '',   -- web page, when one exists
  workdrive_id  text NOT NULL DEFAULT '',   -- folder or file id, for our own documents
  pages         int,
  confidence    text NOT NULL DEFAULT 'secondary' CHECK (confidence IN ('primary','secondary','unverified')),
  notes         text NOT NULL DEFAULT '',
  created_at    timestamptz NOT NULL DEFAULT now()
);

A study is a record of a document, never a copy of it. The PDF stays in WorkDrive; the row carries the id, the page and the confidence. confidence = 'unverified' is how the Durbanville report enters the system today: it exists in Cliq, not in WorkDrive.

4.4 The plan

CREATE TABLE network_plan (
  id             uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id      uuid NOT NULL REFERENCES tenant(id) ON DELETE CASCADE,
  brand_id       uuid NOT NULL REFERENCES brand(id) ON DELETE CASCADE,
  zone_set_id    uuid NOT NULL REFERENCES zone_set(id) ON DELETE CASCADE,
  name           text NOT NULL,
  version        text NOT NULL,
  status         text NOT NULL DEFAULT 'draft'
                 CHECK (status IN ('draft','active','superseded')),
  assumptions    jsonb NOT NULL,   -- every rate, with its unit
  created_by     uuid REFERENCES app_user(id),
  created_at     timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX network_plan_one_active ON network_plan(brand_id) WHERE status = 'active';

assumptions is not free text. It is a typed object and the API rejects anything else:

{
  "royalty_pct": {"value": 5, "unit": "percent_of_turnover", "period": "month"},
  "zone_share_pct": {"value": 3, "unit": "percent_of_turnover", "period": "month"},
  "marketing_pct": {"value": 3, "unit": "percent_of_turnover", "period": "month"},
  "technology_fee": {"value": 5000, "unit": "zar", "period": "month_per_store"},
  "store_sales": {"value": 600000, "unit": "zar", "period": "month", "vat": "excluded"},
  "setup_cost": {"value": 144420, "unit": "zar", "period": "once"},
  "currency": "ZAR"
}

That shape is the fix for the zone_roy ambiguity in §2.1. A number in this product travels with its unit or it does not travel.

4.5 Invariants — the part a future feature cannot quietly break

# Invariant Enforced in
I1 A territory set belongs to exactly one brand; a territory belongs to exactly one set. NOT NULL + unique index
I2 A plan references one territory set version; superseding a plan never mutates a superseded one. network_plan + superseded_at
I3 Fees, plan revenue, candidate scores and study notes are never serialised without pricing:read. src/lib/visibility.ts
I4 For a radius territory the radius is authoritative; geom is recomputed, never hand-edited. repository function + trigger
I5 A candidate cannot reach approved without a study_document_id or a written evidence_exempt. repository, not the UI
I6 Overlap inside a set is computed and surfaced; it never blocks an import. network-overlap check
I7 Every total on a plan is recomputed from its territories and assumptions on read; a stored total is a cache with a 0.5% tolerance. pure function planTotals()
I8 closed locations never count toward a territory; coming_soon counts only as committed, never as trading. summary SQL
I9 Every candidate stage change writes a research_event with before/after. existing pattern
I10 A share link never shows a fee, a plan total, a study or a note. field allow-list

5. The arithmetic, worked

One pure function, planTotals(plan, territories, assumptions), and three worked cases that become acceptance tests.

5.1 Papa Pasta, the 38-cluster plan

  • Territories: 38. Target stores: 311. Territory fees: R12,900,000.
  • Target monthly network sales: R179,261,734 (sum of per-cluster targets, average R576,404 a store).
  • Royalty at 5%: R8,963,087 a month.
  • Zone share at 3%: R5,377,852. Head office at 2%: R3,585,235.
  • Reference stores already mapped: 115 (i.e. 37% of the target network already exists as a pin).

5.2 Papa Pasta, the 135-zone set read the same way

Same function, different version: 135 territories, 234–357 target stores, R102,700,000 of fees. The plan screen's job is to put those two rows next to each other and say, in one sentence, that the cluster plan sells fewer, larger territories at a third of the fee income but a higher store target.

5.3 The Local Farmer

  • 25 territories, 13 AA at R25,000 and 12 BA at R20,000 = R565,000 of fees.
  • Setup at R144,420 a unit: R3,610,500 across the network.
  • At R50,000 monthly revenue a unit: R3,500 royalty (7%) + R1,500 marketing (3%) = R5,000 a month per unit; R125,000 a month across 25 units at full build.

5.4 ACDC Express

Candidates are not a plan yet, and the product must say so rather than invent one. What it can compute from the pack: 17 candidates, 1 approved (Maputo, R6,000,000 investment, 12-month exclusivity), 3 shortlisted, 3 needing a visit, 9 under research, 1 on hold — and, per approved store, R200,000 of commitment fee received against R3,200,000 of fit-out managed.

6. API surface

Every endpoint follows the house conventions already in the repo: cursor pagination, revision checks on write, and authorisation decided in the repository layer.

7. The screens

7.1 /network — the plan board

One card per brand: active plan name and version, territories, target stores against stores already trading, fee income, and the phase the network is in. A second column lists the other plans with a one-click "compare". Nothing here is an input.

7.2 /network/territories — the ground

The Explore map, scoped to one brand and one set, with three additions:

  • Territory kind is visible. A radius territory renders as a circle with the radius labelled (7.0 km); a polygon renders as it does today.
  • Target vs trading. Each territory shows target 14 · trading 4 · shortlisted 2, so the map answers "where is the network thin" without opening a panel.
  • Overlap is a warning, not a colour. Clicking an overlap pair lists both territories and the overlapping area; it never silently repaints either.

7.3 /network/pipeline — the sites

The existing shortlist pattern, with three columns added: brand, territory and study (title and page). Approving a candidate with no study opens the evidence_exempt field and refuses to save it empty. Stage chips are the existing six; nothing new is invented.

7.4 /network/plans/:id — the plan

Header: brand, version, status, and the one sentence that describes the scheme. Body: a table of territories (code, name, tier, phase, target stores, fee, monthly royalty) and a totals row that is derived, with a footnote naming the assumptions and their units. Right rail: the assumptions, editable only in a draft; activating a draft supersedes the previous active plan after a confirmation that names what will stop being live.

7.5 What is deliberately absent

No scenario sliders in v1. A slider that changes a royalty rate in the browser and shows a number no one can defend is worse than a table with a derivation. Scenario comparison comes after the derivation is trusted.

10. Build order — stages by dependency, no dates

Stage A — foundations. Migration for zone_set.brand_id, zone territory columns, study_document, candidate_site additions, network_plan. Backfill Papa Pasta. Exit: F1 passes and the app still renders 5,073 locations and 135 zones.

Stage B — territories. Radius support (store, recompute, render), overlap endpoint, territory detail with target vs trading. Import TLF. Exit: F2–F5.

Stage C — plan arithmetic. planTotals() as a pure, tested function; network_plan CRUD; activation and supersession; totals endpoint with derivation. Exit: F6, F7, F11, F15.

Stage D — pipeline. Study registration, candidate brand/territory/study fields, approval guard, stage audit. Import ACDC. Exit: F8, F9, F13.

Stage E — surfaces. /network, /network/territories, /network/pipeline, /network/plans/:id; the map additions; mobile pass at 390 px. Exit: F10, F12, F14 and a browser walk of all four surfaces.

Stages A–E are sequential; inside a stage the work is parallel. The incumbent (Zoho Projects briefs, the spreadsheets) keeps running until Stage E ships — the plan is read-only evidence until then.

12. Decisions register

# Question Recommendation Cost of the alternative
D1 Which Papa Pasta scheme becomes the active plan — the 135-zone set, the 96-zone paper, or Luke's 38 clusters? Luke's 38 clusters active; v7.2 kept as a superseded version; the 96-zone paper archived as a working paper. The clusters are the only scheme with fees, targets and reference stores in one document, and they are the most recent. Activating 135 zones keeps a scheme with 2.8 stores a territory live, which the zone-owner paper's own arithmetic says cannot pay a zone manager.
D2 Does the TLF territory stay at 7 km, or move to a named suburb boundary? Keep the 7 km radius. It is what the signed agreement annexure says; changing it is a legal act, not a product one. A polygon looks tidier on a map and contradicts the contract.
D3 Do we import the 17 ACDC candidates before the studies are re-verified? Import now, marked by confidence. A candidate row with a document and a page is more honest than an empty pipeline. Waiting means the five Namibian cities stay in a PDF.
D4 Does the Network branch ship fees to anyone below owner/manager? No — fees follow the existing pricing:read capability. No new role, no new flag. A second permission system to keep in sync.
D5 Is network_plan allowed to hold a plan with zero territories? No. A draft may be empty for the first save, but activation requires at least one territory. An "active" plan that computes to zero reads as a bug to every user who sees it.
