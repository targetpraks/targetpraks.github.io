D4 · Who is the close manager, and who signs second?

Question. Name the close manager per BU and the second signatory, or the close cannot reach Verified.

§7.1 defines the office — "the close manager is independent of every measured owner in the close being discharged", and where the manager is also an owner, "that object escalates to MD / EXCO for an independent disposition" — and names no incumbent. §7.6 now hardens this: named before the pilot, not during it — one verifier incumbent per BU, entered in the rules log, and a deputy for every close step, not only for the close manager.

Options.

  • A — One close manager per BU, drawn from outside that BU, with a named deputy. You are the disposition of last resort for the manager's own object and for MD/EXCO head scores.
  • B — A single group close manager across nine BUs. Maximum independence; one point of failure for 300 rows at WD4.
  • C — HR closes every BU. Independent of operations, but the same desk both dispositions a month and opens the PIP case.

Recommendation: A. It satisfies independence per object, survives an incumbent's leave, and matches the deputy rule already written into §7.6. The pilot needs one name for MKT and one deputy to start.

Residual conflict to settle with PRD-A. A §10.6 says "Only Ricardo can set Accepted" on an exception, while B requires the close manager to record an accepted governance disposition. As the two documents stand, a close manager cannot reach Verified on a month with an exception. One line in one document — but before the first close, not during it.

Blocked until answered. The close rehearsal (B5), and the WD3/WD5 names on the close record.

D5 · Where is the override boundary?

Question. What may an HOD override, by how much, and with whose second name?

§5.5 fixes the floor: an override is evaluated only after every required input passes the evidence gate, needs a comment and an auditable author, and "cannot repair a missing actual, missing evidence, rejected evidence, failed mandatory control or unscored inherited component." Undecided is the ceiling and the countersignature.

Options.

  • A — Bounded override. Up to ±10 points on a fully evidenced score, with a comment and a named author; anything larger needs an MD/EXCO countersignature on the same row.
  • B — Unbounded with a comment. Simplest to run; the comment is the only control.
  • C — No overrides. Cleanest arithmetic; removes the HOD's ability to record context where a target was re-baselined mid-month.

Recommendation: A. The evidence gate stays absolute while a bounded, countersigned human judgement applies to the only scores allowed to move.

Blocked until answered. B4's override refusal test cannot prove a boundary that is not a number. Tests N10, N17 and N18 already run it.

D7 · Do we adopt strict null propagation, with no partial discount?

Question. Is a month with one missing required input unscored, or scored on what arrived?

Options.

  • A — Strict. Any required null makes the composite null; inherited null makes the HOD null; partial evidence is not a discount; no renormalisation; mandatory zero-weight controls still block; no override converts null to a number; the WD4 close does not cure a null.
  • B — Null scores as zero, flagged. The band moves, the HR sequence moves, and a data gap becomes a performance finding.
  • C — Keep a partial discount, drop renormalisation. The engine keeps producing a number from incomplete evidence, at half weight — which is what V3 does today.

Recommendation: A. It is the only option under which a missing number cannot be mistaken for a bad one, and it is already written as a runnable suite: 30 cases, of which the twelve §5.6 null tests, six close-authority cases and three period-lock cases all bind here.

6. The one defect that would corrupt a month's scores

Evidence multiplier - Partial = 0.5, 11 Config.txt line 7.

It is live in the engine today, and the engine's own demo row shows what it does: an IT support specialist scores 88 against a 70–90 band → 90; the verifier marks the proof partial; the engine records 45, weights it at 0.45, lands 20.25, and bands the person PIP. Nobody typed a wrong number. The engine converted an evidence gap into a performance finding, and the row's band column now reads PIP.

Retiring that line is not a tuning exercise. It is the difference between "we do not know" and "they failed", and only one of those may reach HR. Test N06 fails any engine that still discounts: the legacy engine returns exactly 20.25, the contract returns null.

The same disease sits in §2.1 as 5,632 typed zeros and 762 target-derived formulas in input columns — numbers where a null belongs. A typed zero that migrates as a result is the multiplier's argument at capture time. Test N21 now fails any engine that accepts one.

The eight colliding IDs are the runner-up: one person's evidence attaches to another's scorecard, silently, for 16 rows across three tabs. Sized in PRD-B-reconciliation-plan.md; it cannot be fixed by the engine's logic.
